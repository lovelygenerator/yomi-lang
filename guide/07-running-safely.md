# 07 安全に動かす

AI エージェントやユーザーが書いた台本を動かすときは、「台本が、予想外のことをしても、ホストが困らない」ことが大切です。yomi は、次の 3 つで、これを支えます。

## 1. できることは、登録したコマンドだけ

台本は、ファイルもネットワークも、直接には触れません。台本ができることは、ホストが `Registry` に登録したコマンドだけです。承認フローのホストが登録したのは、本文を表示する `ui.say` と、標準パッケージだけでした。通知を送るコマンドを足すなら、ホストが、送り先や回数を制限して登録します。

台本は、コンパイルの時点で、型と名前が検査されます。登録されていないコマンドを呼ぶ台本は、動く前にエラーになります。

## 2. 実行には上限がある

```rust
let config = VmConfig::default().max_steps_per_run(Some(100_000));
```

`VmConfig` に、上限を決めます。超えると、台本は、実行時エラーで止まり、ホストには `Err` が返ります。

| 設定 | 意味 | 既定 |
| --- | --- | --- |
| `max_steps_per_run` | 1 回の `run` で実行できる命令の数 | 5000 万 |
| `max_call_depth` | `call` と `fn` の呼び出しの深さ（再帰を含む） | 256 |
| `max_value_bytes` | 1 つの値の大きさ | 16 MiB |
| `max_total_bytes` | 変数に持つ値の大きさの合計 | 64 MiB |

無限ループの台本も、`max_steps_per_run` で止まります。また、乱数の状態は、セーブに含まれ、コアは時計を読みません。同じ台本と同じ入力からは、いつも同じ結果になるので、問題の再現もできます。

## 3. 別のスレッドから中断できる

長く走る台本を、外から止めたいときは、中断のトークンを使います。`Vm` から取り出したトークン（`Send + Sync`）を、監視のスレッドへ渡し、時間を測って `interrupt()` を呼びます。

```rust,ignore
let handle = vm.interrupt_handle();
// 監視のスレッドで: 期限が来たら
handle.interrupt();
```

台本は、次の確認点（命令の区切り・コマンドから戻ったあと）で、実行時エラー `interrupted` で止まります。要求は、ホストが `handle.reset()` するまで残ります。ホストが登録した関数（時間のかかる入出力など）も、`Ctx::interrupted()` で、中断の要求を確かめられます。壁時計の期限は、コアではなく、ホストの監視のスレッドが持ちます。

## 検査してから動かす

AI エージェントが書いた台本は、動かす前に、`yomi check` で検査します。診断は、エラーと警告が、位置つきで出ます。Rust のホストなしで検査するには、ホストの登録表を宣言ファイル（JSON）に書き出して、渡します。

```sh
yomi check agent-script.yomi --decls host.decls.json
```

宣言ファイルは、Rust のホストが、登録表から書き出します（`yomi decls` は、組み込みの登録表の宣言ファイルを書きます。仕様は [host/02-registry.md](../spec/host/02-registry.md)）。`yomi mcp` は、同じ検査を、MCP のサーバーとして、AI エージェントに提供します。
