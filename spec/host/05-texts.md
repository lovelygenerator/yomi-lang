# 5. 本文の差し替え（多言語化）

複数形・性による変化は、v0 では持たない（5.9）。

この章は、台本の本文（素の行・引用行・選択肢の文）と、identity の表示名・入力の促しを、言語ごとの訳文に差し替える約束を定める。差し替えは、キーを使って、コアが行う。

## 5.1 基本の形

- 本文は、台本に**原文**として書く。訳文は、ホストが、言語ごとの**差し替え表**（`TextTable`）として渡す。
- VM は、糖衣を停止型コマンドに展開するとき（language/05-sugar.md の 5.1）、本文のキーが表にあれば、訳文に差し替えて、コマンドへ渡す。表になければ、原文をそのまま渡す。
- 差し替えの対象は、素の行・引用行の本文と、選択肢の文に、5.2a の 2 つ（引用行の identity の表示名と、登録表で「訳せる」と印を付けた `@` のコマンドの引数。入力の促しなど）を加えたものである。それ以外の `@` のコマンドの引数（`@flow.wait` など）と、データ中の文字列リテラルは、対象にしない。ホストが登録表で束縛した糖衣のコマンドの引数の形（本文は `str`、選択肢は `list<str>`）は、変わらない。
- 言語の選択は、ホストが決める。コアは、言語を知らない。セーブには、言語を含めない。表を設定しても、位置・変数・ハッシュ・通過済みの停止点（`seen`）・ロールバック・履歴は変わらない。
- 停止点の履歴は、原文と評価済みの値を持ち、表示のとき、今の言語で引く（host/04-save.md の 4.3、5.6）。

## 5.2 キー

- キーは、本文の行の安定 ID から作る：`モジュール名.ラベル名#id`（host/04-save.md の通過済みの停止点と同じ形）。選択肢の文は、選択肢の `#id` から作る（同じラベルの中の ID は、素の行・引用行・選択肢で重ならない。language/01-lexical.md の 1.9）。
- 安定 ID のない本文の行は、差し替えられない（原文のままになる）。ホストは、コンパイルの設定 `require_text_ids` で、ID のない本文の行を、コンパイルエラーにできる（5.5）。
- 台本の更新で、ID は変わらないので、訳文が追従する。identity の表示名は、宣言の名前（`案内人`）で追従する。本文の内容が変わっても、同じ ID の訳文が使われる（訳文の更新は、翻訳のツールの仕事）。

## 5.2a identity の表示名と、コマンドの訳せる引数

### identity の表示名

- 引用行の identity（`案内人「…」`）の表示名（`identity 案内人 = "リオン"` の `"リオン"`）は、差し替え表で訳せる。キーは `identity:モジュール名.名前`（`identity:chara.案内人`）。宣言したモジュールの名前で決まる（`import` 先の identity も同じ）。行のキー（`モジュール.ラベル#id`）には `#` があるので、重ならない。
- 引用行の停止の知らせの `identity`（`Option<Identity>`）の `name` だけが、訳文になる（`id` は変わらない）。引用行に安定 ID がなくても、表示名は訳せる。
- 訳文は、文字列そのもの（`「」` は付けない）。`${n}` は使えない（原文に `${式}` がないので、`bad_number`）。
- 引用行の `Identity` 以外は、訳せない。式の中の `案内人.name`・`${案内人.name}`、変数・引数・戻り値に入れた `Identity`、`@` のコマンドへ渡す `Identity` は、原文の表示名のままである（言語はセーブに含めないので、変数の値は変えない）。

### コマンドの訳せる引数（入力の促しなど）

- ホストは、停止型コマンドの `str` の引数を 1 つ、「訳せる」と登録できる（host/02-registry.md の 2.2。`PackageReg::text_param`・`Registry::text_param`）。組み込みの `input` パッケージは、`input.text`・`input.integer`・`input.confirm` の `prompt`（0 番目）を、訳せるようにしている。
- 台本が、その引数を**文字列リテラル**で書き、**行に安定 ID を付けた**ときだけ、差し替えの対象になる。キーは、その行の `モジュール.ラベル#id`（本文の行と同じ形。同じラベルの中の ID は、すべての行で重ならない）。
- 訳文は、原文と同じ形（文字列リテラルの中身）。`${n}` は、その引数の原文の `n` 番目の `${式}` の値を、文字列にして埋め込む。ほかの引数（`default` など）は、変えない。
- 引数が変数・式のとき、行に ID がないときは、差し替えない（原文のまま）。訳せると登録していないコマンドの引数も、表にキーがあっても、差し替えない。
- 戻り値・引数の検査（`max_len` など）・履歴の「原文と評価済みの値」・位置のハッシュは、原文で決まる。訳文は、停止の知らせの引数にだけ入る。

## 5.3 差し替え表と VM

```rust
let mut table = TextTable::new("en");
table.insert("chapter1.start#a3f9k2", "${1}: Good morning.")?;
vm.set_texts(Some(table))?;      // None で、原文に戻す
```

### 差し替え表（`TextTable`）

- `TextTable::new(言語名)`：空の表。言語名（`en` など）は、コアが意味を決めない。`language()` で読める。
- `insert(キー, 訳文)`：訳文を入れる。同じキーがあれば置き換える（入れた順は変わらない）。訳文は、入れるときに解析して持つ。誤りは `TextError`（コードと引数だけ。表は変わらない）。`get(キー)`・`len()`・`is_empty()`・`iter()`（入れた順）で読める。
- 値は、**原文と同じ形の本文**である。引用行・選択肢の文は、`「` `」` を含めて書く（language/05-sugar.md の 5.4）。
- 値の中では、本文のエスケープ（language/01-lexical.md の 1.10）が使える（`\「` `\」` `\$` `\\` `\=` `\#`）。これ以外の `\` の組み合わせは、誤り（`invalid_escape`）。`\$` に続く `{` は、ただの文字である（`\${` は文字の `${`）。`$` の直後が `{` でないときの `$` は、文字の `$`。
- 値の中の `${n}`（`n` は 1 以上の整数）は、原文の `n` 番目の `${式}` の値を、文字列にして埋め込む。語順が違う言語でも、変数の位置を変えられる。
  - 原文の `${式}` を、訳文で使わなくてもよい。同じ `n` を、複数回使ってもよい。
  - `${n}` の形でない `${…}`（`${name}`・`${0}`・`${ 1 }`・`${}`・閉じていない `${`）は、誤り（`invalid_placeholder`）。
  - `${n}` の `n` が、原文の `${式}` の個数を超えるときは、表を設定するとき（`set_texts`）と検査（5.4）で、エラー（`bad_number`）になる。原文は、コンパイルした台本から分かる。台本にないキーの訳文は、設定のときには、誤りにしない（5.4 の警告）。

### VM

- `vm.set_texts(Option<TextTable>) -> Result<(), Vec<TextIssue>>`：いつでも呼べる。次の停止点から、差し替えが変わる。今の停止点の `Yield`（`vm.current()`）は、変わらない。`None` で、原文に戻す。番号の誤りがあるときは、すべての誤りを返し、表は設定しない（前の表のまま）。`vm.texts()` で、今の表を読める。
- 差し替えるのは、停止の知らせの引数だけである（変数・セーブ・履歴は、原文）。VM は、停止点に着くとき、原文の引数と、`${式}` の評価済みの値を持つ（履歴の記録と同じもの）。

### 停止中の言語切り替え

```rust
vm.set_texts(Some(table_en))?;
let y = vm.refresh_current()?;   // 今の停止点を、新しい表で作り直す
```

- `vm.refresh_current()` は、停止中だけ呼べる（そうでなければ実行時エラー `NotStopped`）。今の停止点の本文を、今の差し替え表で作り直した `Yield` を返す。返した `Yield` が、以後の `vm.current()` になる。
- VM は、今の停止点の、原文と、`${式}` の評価済みの値を、持っている。作り直すとき、式は、評価し直さない（変数の値が、変わっていても、同じ値を使う）。乱数も引かない。ロードした直後の停止点でも、同じである（ロードで引数を作り直したときの値を持つ）。
- 作り直すのは、本文（素の行・引用行・選択肢の文）の引数と、引用行の identity の表示名と、訳せる引数（5.2a）だけである。ほかの引数と、`id` は、そのまま。
- 位置・変数・通過済みの停止点・履歴・乱数・セーブは、変わらない。履歴に、記録を足さない。
- 本文を持たない停止点（`flow.wait` など）では、同じ `Yield` を返す。
- ロールバック（`vm.restore`）で戻した停止点の本文は、**戻すときの**差し替え表で作り直す（スナップショットは、原文の引数と値を持つ。言語は、状態に含めない）。ロード（`Vm::load`）は新しい VM を返すので、ホストが、新しい VM に `set_texts` と `refresh_current` を呼ぶ。
- 永続データの読み込み（`load_persistent`）が停止点の引数を作り直すときも、いまの表で作り直す。

## 5.4 表の検査

- `TextTable::check(&program) -> Vec<TextIssue>` は、台本の本文のキーと、表を突き合わせる。結果は、台本の順（足りない訳・番号の誤り）、続いて表の順（余った訳）に並ぶ。
  - **足りない訳**（`missing`。警告）：台本の、安定 ID つきの本文（5.2a の identity の表示名と、訳せる引数を文字列リテラルで書いた安定 ID つきの行を含む）にあって、表にないキー。
  - **余った訳**（`unused`。警告）：表にあって、台本にないキー。
  - **番号の誤り**（`bad_number`。エラー）：`${n}` が、原文の個数を超える。引数 `number`（超えている最大の `n`）・`count`（原文の個数）。
- `TextIssue` は、重大度・キー・種類（`TextIssueKind`。コード `code()` と引数）を持つ。文面は持たない。
- 検査は、ツール（`yomi-cli` の `yomi texts check`。5.8）からも使える（翻訳の抜けの確認）。
- `TextTable::template(&program, 言語名)` は、台本の安定 ID つきの本文のすべて（identity の表示名と、訳せる引数を含む。並びは、宣言の順の identity、続いて台本の順）について、原文を値にした表（ひな形）を作る。`${式}` は、番号つきの `${n}`（書かれた順）になり、`\` と `{` の前の `$` はエスケープする。ひな形は、そのまま `set_texts` できて、設定すると、原文と同じ本文になる。

## 5.5 ID の必須化

- ホストは、コンパイルの設定 `CompileOptions::require_text_ids(true)` を、有効にできる（既定は無効）。`compile_modules_with_options` に渡す。
- 有効なとき、安定 ID のない素の行・引用行・選択肢の文は、コンパイルエラー（診断 `missing_text_id`。引数 `kind` は `plain`・`quote`・`choice`）。`@` のコマンドの行は、訳せる引数（5.2a）を文字列リテラルで書いたときだけ、同じエラー（`kind` は `command`）にする。それ以外の `@` のコマンドの行は、対象にしない。
- 糖衣が「無視」に指定されている（language/05-sugar.md の 5.3）ときも、書き方の検査として、同じエラーにする。
- `assign-ids`（5.10）は、ID のない本文の行に、自動の ID を書き戻す。書き戻したあとの台本は、`require_text_ids` が通る。

## 5.6 履歴を今の言語で引く

- `vm.render(&StopRecord) -> Vec<Value>`：履歴の 1 件の引数を、今の差し替え表で作り直して返す（表になければ原文）。引用行の identity の表示名と、訳せる引数（5.2a）も、作り直す（コマンドの引数は、履歴の `label` と安定 ID から、台本で探す）。それ以外の `@` のコマンドは、そのままの引数。
- `vm.history_text(&StopRecord) -> Option<String>`：素の行・引用行の本文を、今の表で作り直した文字列で返す（identity の表示名は含まない。`render` の 0 番目の引数）。`@` のコマンドと選択は `None`（選択は、`render` の 0 番目の引数が、選択肢の文の `list`）。
- 履歴は、原文と評価済みの値を持ち（host/04-save.md の 4.3）、ラベル（`label`）と種類（`kind`。`StopKind`）も持つ。そのため、ロードしたあとの履歴でも、今の言語で引ける。履歴そのものは、言語を切り替えても変わらない。

## 5.7 表のファイルの形式（ツール用）

`yomi-cli` が読み書きする、行指向の形式（`TextTable::from_file`・`to_file`）。コアのほかのツールも、同じ形式を使える。

```
# コメント
@lang en
chapter1.start#a3f9k2<TAB>${1}: Good morning.
chapter1.start#b8x2m1<TAB>「Hi\nthere」
```

- 文字コードは UTF-8。行の終わりは、`\n` か `\r\n`。先頭の BOM は読み飛ばす。
- 空行は、読み飛ばす。行頭が `#` の行は、コメント（`#` は行頭のときだけ。キーの途中や訳文の途中の `#` は、ふつうの文字）。
- `@lang 言語名` の行で、言語名を決める（なければ、言語名は空）。ほかの `@…` の行は、誤り（`unknown_directive`）。
- ほかの行は、`キー` TAB `訳文`（最初の TAB で分ける）。TAB がない行は誤り（`missing_tab`）、キーが空は誤り（`empty_key`）、同じキーが 2 度あるのも誤り（`duplicate_key`）。訳文の前後の空白は、そのまま残す。
- 訳文の中の改行・TAB・復帰は、`\n`・`\t`・`\r` で書く（読むときに、改行・TAB・復帰にする）。それ以外の `\` の組み合わせは、訳文のエスケープ（5.3。`\\` が `\`）として、そのまま `insert` に渡す。
- 誤りは、`TextError`（コード・引数・キー・行）で返す。

## 5.8 `yomi-cli` の対応

- `yomi run <台本> --texts <表>`：起動時に表を読んで設定する。読めない・設定できないときは、標準エラーに書いて、実行せずに終了コード 1。
- `yomi run <台本> --auto`：自動プレイ。本文（素の行・引用行）と `flow.wait`・`flow.wait_input` の停止点では、入力を読まずに進む。選択（`choice`）と `input.*` の停止点だけ、標準入力から 1 行読む。選択の答えは、一覧の番号か、選択肢の安定 ID（`#a3f9k2`。`#` つき）。一覧にない ID・選択の答えにならない入力・選択の前に入力が尽きたときは、続けずに、標準エラーに書いて終了コード 1。`:save`・`:load`・`:back`・`:texts`・`:vars` などの対話コマンドは、入力を読む停止点で使える。選択肢の ID（ない選択肢は、なし）を、表示の行の終わりに ` #id` として出す（`--auto` では常に出る）。台本の回帰テストの入力を、`if`・`once` による選択肢の番号のずれに影響されずに書ける。
- `yomi run <台本> --show-ids`：選択肢の安定 ID を表示に出す（`--auto` でなくても。選択は、番号のほかに `#id` でも答えられる。一覧にない ID は、番号と同じく、求め直す）。
- 対話コマンド `:texts <ファイルまたは off>`：停止中に表を切り替え、`refresh_current` で今の停止点を作り直して、もう一度表示する（`off` は原文）。表が読めない・設定できないときは、標準エラーに書いて、同じ停止点で待つ。`:back`・`:load` のあとも、今の表で出る。
- `yomi texts check <台本> <表> [--root ディレクトリ]`：足りない訳・余った訳（警告）・番号の誤り（エラー）を、標準エラーに 1 件 1 行で出し、標準出力に件数を出す。エラーがあれば終了コード 1、警告だけなら 0。
- `yomi texts template <台本> [--root ディレクトリ] [--text-language 言語名]`：ひな形（5.4）を、表のファイルの形式で、標準出力に書く。
- `yomi assign-ids <台本…>`：5.10。
- `yomi codes [--json] [--packages]`：コードの一覧（language/06-diagnostics.md の 6.11）。
- 文面は、`yomi-cli` の FTL（en・ja）にだけある。

## 5.9 複数形

- 複数形・性による変化は、v0 では持たない。数による文の出し分けは、台本の `if`・`match` で、ID の違う行に分けて書く。

## 5.10 安定 ID の自動付与（`assign-ids`）

ID のない行に、自動の安定 ID を、行末などへ書き足す。元のテキストは、書き足す所以外を変えない。

### コア（純粋な関数）

- `Program::missing_ids() -> Vec<MissingId>`：ID を付けられるが付いていない行（language/02-lines.md の 2.7 の 4 種類）を、台本の順に返す。`MissingId` は、モジュール・ラベル・種類（`StopKind`。選択肢の文は `Choice`、停止型コマンドの行は `Command`）・書き足す位置（行・桁。桁は Unicode スカラ値の数で、1 始まり）を持つ。糖衣が「無視」に指定されている種類の行も、含める（`require_text_ids` と同じ。5.5）。
- `Program::written_ids(モジュール, ラベル)`：そのラベルに、すでに書かれている ID。
- `plan_ids(sources, registry, options, &mut IdRng) -> Result<Vec<Insertion>, Vec<Diagnostic>>`：台本をコンパイルし、ID のない行ごとに、付ける ID と書き足す位置（バイト）・文字列を返す。コンパイルエラーがあれば、診断を返し、何も計画しない。ただし、エラーのすべてが**ID の欠落が原因のもの**（`once` の選択肢に ID がない `once_without_id`、`require_text_ids` が有効なときの `missing_text_id`）なら、その行にも ID を付けて計画する（`once` の ID も、ほかの選択肢と同じ `=>` の直前に書く）。付けたあとの台本を、同じ設定でもう一度コンパイルして、エラーがないことを確かめてから返し、確かめられなければ、そのコンパイルの診断を返す（何も計画しない）。`Insertion` は、モジュール・ラベル・種類・行・桁・バイト・ID・書き足す文字列を持つ。
- `apply_insertions(source, &[Insertion]) -> String`：ソースに書き足しを適用する。書き足す文字列以外は、一文字も変えない（改行コード `\n`・`\r\n`・先頭の BOM を含む）。同じモジュールの書き足しだけを渡す。
- `IdRng::new(seed)`：ID を作る乱数（xorshift64\*。外部の依存なし。同じ種なら同じ ID の並び。暗号用ではない）。`next_id()` は小文字英数字 6 文字、`unique_id(&mut used)` は `used` にないものを作って加える。コアは、時刻を読まない（種は呼び出し側が決める）。
- 書き足す文字列は、素の行・引用行・停止型コマンドの行では ` #id`、選択肢の文では `#id `（`=>` の前に空白があるとき）か ` #id `（ないとき）。付けた ID の重なりは、`(モジュール, ラベル)` ごとに避ける。
- 冪等：書き足したあとの台本に、もう一度計画すると、空になる。付ける前後で、停止点の列（ID を除く）・位置のハッシュ・`once`・`seen` の記録は変わらない（ID の有無は、ハッシュに入らない。language/02-lines.md の 2.7）。

### `yomi assign-ids`

```
yomi assign-ids <台本のパス…> [--root <ディレクトリ>] [--decls <宣言ファイル>] [--seed <数>] [--check] [--dry-run]
```

- 台本のパスは、ファイルか、ディレクトリ（下の `.yomi` すべて）。書き換えるのは、指定したファイルだけ。モジュールは、最初の台本のあるディレクトリ（`--root` で変えられる）の下の `.yomi` をすべて集めて、コンパイルする（`yomi check` と同じ）。指定したファイルが、そのディレクトリの下になければ、エラー。
- `--decls`：宣言ファイルから作った登録表で計画する（ホストの Rust なし。host/02-registry.md の 2.8）。なければ、組み込みの登録表。
- `--seed`：ID の乱数の種。なければ、起動した時刻（CLI だけの話で、コアは時刻を読まない）。同じ台本・同じ種・同じ登録表なら、同じ ID。
- 既定：すべてのファイルの計画が立ってから、まとめて書く。各ファイルは、同じディレクトリの一時ファイルに書いて、名前を付け替える（権限は、元のファイルのまま）。途中で失敗したら、一時ファイルを消し、エラーを標準エラーに書いて終了コード 1。標準出力に、付けた件数とファイル数を書く。付ける ID がなければ、何もせず、終了コード 0。
- `--dry-run`：書かずに、付ける ID と位置（`ファイル:行:桁: #id …`）を、標準出力に書く。終了コード 0。
- `--check`：書かない。ID のない行を、標準エラーに 1 件 1 行で出し、あれば終了コード 1、なければ 0。`--dry-run` と同時に指定しても、書かない。
- コンパイルエラーがあるときは、どのファイルも書かず、エラーを標準エラーに出して終了コード 1（警告は出さない）。ただし、エラーのすべてが `once` の選択肢の ID の欠落（`once_without_id`）なら、その選択肢にも ID を付けて書く（付けたあとの台本にエラーがないことを確かめてから書く）。`--check` は、`once` の ID の欠落も、ID のない行として数える（あれば終了コード 1）。指定していないファイルの `once` の ID の欠落は、書き換えないので、そのファイルを指定するまで、コンパイルエラーのまま残る。
- 文字コードは UTF-8 だけ（読めないファイルは、読み込みの誤りで終了コード 1）。BOM と改行コード（LF・CRLF）は、そのまま保つ。
