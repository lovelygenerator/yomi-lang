# 7. REPL

この章は、REPL（対話の実行環境）の約束を定める。式を評価し、文を実行し、台本の行（素の行・引用行・`choice`）を入力して、動いている台本の変数・`fn`・型の上で試せる。試した結果は、既定では台本に影響せず、`:apply` で明示したときだけ、停止中の台本へ書き戻せる（7.3.6）。コマンドラインの `yomi repl` と、`yomi run` の停止中に入る `:repl`（7.1・7.6）、ホストが自分の REPL を作るためのコアの API（7.8）を定める。

REPL は、台本を動かす道具（host/06-cli.md の 6.3）と同じ登録表・同じ表示の規則を使う。台本の文法は、language/ の各章のとおりで、この章は、REPL の入力として足す規則だけを書く。この章の Rust のコードは、形を示すためのもので、型の細部は rustdoc を正とする。文中の出力例は、表示言語が `en` のときのものである（host/06-cli.md の冒頭）。

## 7.1 概要と起動

REPL は、次の 2 つの形で使う。

| 形 | 内容 |
| --- | --- |
| `yomi repl [<台本>]` | REPL だけを起動する。台本があれば、台本を読み込み、まだ実行していない開始点の環境の上で動く。台本がなければ、空の環境で動く |
| `:repl`（`yomi run` の停止中） | 動いている台本の、いまの停止点の環境の複製の上で、REPL に入る。`:exit` で、同じ停止点へ戻る。`:apply` で、複製で変えた変数を台本へ反映できる（7.3.6） |

この章の例は、次の台本 `game.yomi` を使う。

```
identity 案内人 = "リオン"

save var favor: int = 3
save var items: list<str> = ["お面"]

enum Mood { Happy, Normal, Sulky }
struct Prize { name: str, hp: int }

fn mood_of(level: int) -> Mood {
  if level >= 6 {
    return Mood.Happy
  }
  if level >= 3 {
    return Mood.Normal
  }
  return Mood.Sulky
}

label start {
  let gold = 100
  gold += 0
  案内人「旅の人、遅い！」
  jump shop
}

label shop {
  choice {
    「買う」 => favor += 1
    「帰る」 => end
  }
}
```

### `yomi repl`

```
yomi repl [<台本>] [--root <ディレクトリ>] [--seed <数>] [--persistent <ファイル>]
```

| 引数・オプション | 内容 |
| --- | --- |
| `<台本>` | 起動ファイル。なければ、台本のない空の環境で始める |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（host/06-cli.md の 6.1）。`<台本>` があるときだけ意味を持つ |
| `--seed <数>` | 乱数の種（0 以上の整数）。なければ、起動した時刻から決める |
| `--persistent <ファイル>` | 永続データ（host/04-save.md の 4.5）を、**読むだけ**。起動時に読み、REPL の中の変更は書き戻さない。ファイルがなければ、新規の永続データから始める |

起動の手順は、次のとおり。

1. `<台本>` があれば、台本を集めてコンパイルする（host/06-cli.md の 6.1）。警告は標準エラーに出して、そのまま続ける。エラーがあるときは、診断を標準エラーに出し、REPL を始めずに終了コード 1。
2. `--persistent` を読む。読めない・正しくないときは、標準エラーに書いて、REPL を始めずに終了コード 1。
3. 環境を作る。台本があるときは、起動ファイルのモジュールの開始ラベルの先頭の状態（台本は、まだ 1 行も実行していない。モジュール変数は初期値、ローカル変数はない）。開始ラベル（`start`）がなくてもよい。台本がないときは、モジュールもラベルもない空の環境。
4. 標準入力から入力を読み、7.2 以降の規則で処理する。

- 登録表は、`yomi run` と同じ（組み込みの標準パッケージと、糖衣の束縛。host/06-cli.md の 6.1）。台本がなくても、`import std::math` のように、パッケージを使える。
- REPL で書いた宣言と式は、モジュール `<repl>` の中にあるものとして扱う（7.3）。`<repl>` は識別子ではないので、台本のモジュールの名前と重ならない。

### `:repl`

- `yomi run` の対話コマンド（host/06-cli.md の 6.3.4）に、`:repl` を足す。入力を読む停止点（`--auto` では、選択と `input.*` の停止点）で使える。
- `:repl` は、いまの停止点の環境（台本のすべてのモジュール、いまのラベルのローカル変数、ホストの変数、パッケージの状態）を**複製して**、その複製の上で REPL を始める。動いている台本は、`:apply`（7.3.6）を使わないかぎり、変わらない（7.3.4）。
- 始めるとき、REPL に入ったことを示す 1 行を標準出力に出す。`:exit` で REPL を終えると、同じ停止点に戻り、次の入力を待つ。停止点は、表示し直さない（`:apply` で変数を反映したときだけ、作り直した停止点を表示し直す。7.3.6）。`:repl` に入るたびに、REPL は、新しい複製と、空の宣言から始まる。
- REPL の中の入力は、標準入力から読む。`--auto` の自動プレイでも、REPL の中の停止点は、入力を読む（7.4）。

### 端末への入出力

- 式の値・`let` の表示・`:vars` などの結果は標準出力、診断とエラーは標準エラーに書く（host/06-cli.md の 6.1）。
- 標準入力が端末のときだけ、入力を促す文字列（プロンプト）を標準出力に出す。通常は `yomi> `、複数行の入力の続き（7.5）は `...> `。端末でないとき（パイプ・リダイレクト）は、出さない。
- 行の編集・入力の履歴・補完は、端末の機能であり、この章では定めない。

### 終了

- `:exit`・`:quit`・標準入力の終わり（EOF）で終わる。入力の途中（7.5）の EOF は、その入力を確定して（未完了なら診断を出して捨てて）から終わる。`yomi repl` は、終了コード 0。`:repl` の中の `:exit`・EOF は、REPL だけを終えて、停止点へ戻る。`:quit` は、`yomi run` の `:quit` と同じ（実行全体をやめる。終了コード 0）。
- 入力の誤り（診断・実行時エラー）では、終わらない。誤りは報告して、次の入力を待つ（7.7）。EOF のときの未完了の診断（7.5.2）でも、終了コードは 0。

| 終了コード | 場合 |
| --- | --- |
| 0 | `:exit`・`:quit`・EOF で終わった |
| 1 | `<台本>` のコンパイルエラー。ファイルを読めない。`--persistent` の誤り。標準出力が閉じた |
| 2 | 引数の誤り（host/06-cli.md の 6.9） |

## 7.2 入力の種類と判定

REPL は、1 つの**入力**を、1 行、または複数行（7.5）で読む。入力は、次のいずれかとして処理する。

| 種類 | 例 | 結果 |
| --- | --- | --- |
| 対話コマンド | `:vars` | 7.6 |
| 式 | `favor`・`mood_of(favor)` | 値を表示する |
| 文 | `favor += 1`・`let x = 3`・`for … { }`・`@flow.wait(1.0)` | 実行する。`let` は、変数を表示する |
| 宣言 | `fn …`・`struct …`・`enum …`・`import …`・`identity …` | REPL の宣言に足す（7.3） |
| 台本の行 | 素の行・引用行・`choice { }` | 停止点を作り、7.4 の流れで処理する |

### 7.2.1 判定の規則

入力の判定は、**入力の文字だけ**で決まる。どの名前が宣言されているかには、よらない。次の順に調べ、最初に当てはまったものにする。

| 順 | 条件 | 種類 |
| --- | --- | --- |
| ① | 空行、または行頭（空白を除く）が `//` | 無視する。何も表示しない（入力の途中の空行は、入力の一部。7.5） |
| ② | 行頭（空白を除く）が `:` | 対話コマンド |
| ③ | 入力が 1 行で、全体が 1 つの式（language/03-statements.md の 3.2 の `expression`）として読める | 式 |
| ④ | それ以外 | language/02-lines.md の 2.1 の ②〜⑥ の順に分類する（コマンド行・文の行・引用行・素の行） |

- ③は、式を、②〜⑥より先に調べる。`true`・`None`・`Some(3)`・`map { "a": 1 }` のように、予約語で始まる式も、式として読む。
- 式として読めるが、名前が宣言されていないときは、素の行にはならず、`unknown_name` などの診断になる（`gld` を入力したら、素の行ではなく、書き間違いとして報告する。language/06-diagnostics.md の 6.4）。
- `None` や `map {}` のように、型を決められない式は、診断（型を決められない。language/06-diagnostics.md の 6.3）になる。`let` に型注釈を付けて宣言する（`let m: map<str, int> = map {}`）。
- 素の行にしたい入力は、行頭に `\` を付ける（language/01-lexical.md の 1.10）。`\はい` は、本文 `はい` の素の行になる。`:` で始まる素の行も、`\:` で始める。
- ④の分類は、台本のファイルに書いたときと同じである。`案内人「…」`（④）は、宣言された identity の名前のときだけ引用行になる（language/02-lines.md の 2.3）。使える identity は、7.3 の環境で決まる。
- 入力に、安定 ID（`#id`）は付けられない（7.7 の `repl_not_allowed`）。

### 7.2.2 式

- 式は、型検査をして（language/06-diagnostics.md の 6.3）、評価し、値を標準出力に 1 行で表示する（7.2.4）。
- 式の中で呼べるのは、台本の式と同じ（問い合わせ型のコマンド・組み込み関数・`fn`・変数・リテラル。language/03-statements.md の 3.2、3.8）。副作用型・停止型のコマンドを呼ぶときは、文として `@` で書く。値を見たいときは、`let v = @cmd(…)` で受けてから `v` と書く。
- 値のない式（戻り値のない呼び出し）は、式として書けない（台本と同じ）。
- 式の評価は、台本の実行と同じに、命令数・値の大きさ・呼び出しの深さの上限を受ける（host/01-execution.md の 1.9）。

### 7.2.3 文・宣言

- 文は、台本の文（language/03-statements.md の 3.3、3.6）と同じに書く。`let`・代入・`if`・`while`・`for`・`match`・`break`・`continue`・更新するメソッド（`push` など）・`@` のコマンド・`call`・`choice` を書ける。`call` は、ラベルを一時的に呼ぶ（7.4）。
- `let` は、REPL の変数を宣言し、宣言した変数を `名前 = 値` の形で 1 行、標準出力に表示する（`let bonus = 25` → `bonus = 25`）。値は、7.2.4 の表示形。型注釈は、台本と同じに書ける。
- 代入・`push` などの更新は、何も表示しない。値を見るときは、変数を式として入力する。
- `if`・`while`・`for`・`match` の中にある式は、表示しない。表示するのは、入力全体が 1 つの式のときだけである。
- 宣言は、`fn`・`struct`・`enum`・`import`・`identity`。台本の宣言と同じに書く（language/03-statements.md の 3.5、3.7、language/04-labels-modules.md の 4.2、language/02-lines.md の 2.3）。何も表示しない。`import` は、台本と違い、いつでも書ける（`import_not_first` にならない）。`struct`・`enum`・`fn` は、複数行にまたがってよい（7.5）。
- 書けないもの：`save var`・`persistent var`・`label`・`jump`・`end`・`return`（`fn` の中の `return` を除く）・`once` つきの選択肢。`repl_not_allowed`（7.7）。
- 1 行の入力は、1 つの式か、1 つの文（または宣言）である。複数の文は、1 行ずつ別の入力にする。

### 7.2.4 値の表示形

式の値・`let` の値・`:vars` の値は、次の形で表示する。language/03-statements.md の 3.2 の `${}` に埋め込む文字列と同じ形だが、`str` は、入れ子の中も含めて、引用符で囲む。`yomi run` の `:vars`（host/06-cli.md の 6.3.4）も、同じ形で表示する。

| 型 | 表示 | 例 |
| --- | --- | --- |
| `int` | 10 進数 | `-3` |
| `float` | 元の値に戻る最短の 10 進表記。整数値には `.0` を付ける | `2.5`・`3.0` |
| `bool` | `true`・`false` | `true` |
| `str` | `"` で囲み、`\"`・`\\`・`\n`・`\t`・`\$` でエスケープする | `"お面"` |
| `list<T>` | `[要素, …]` | `["お面", "札0"]` |
| `map<K, V>` | `map { キー: 値, … }`。挿入順。空は `map {}` | `map { "a": 1 }` |
| `Option<T>` | `Some(値)`・`None` | `Some(3)` |
| `struct` | `型名 { フィールド: 値, … }`。宣言の順 | `Prize { name: "お面", hp: 3 }` |
| `enum` | `型名.バリアント`、引数があれば `型名.バリアント(値, …)` | `Mood.Happy` |
| `Identity` | `Identity { id: "案内人", name: "リオン" }` | |
| 関数の型 | `<fn>` | |

- モジュールの名前は付けない（`game.Mood.Happy` ではなく `Mood.Happy`）。
- 最上位の `let` に、関数の型（それを含む型）の値は入れられない（`fn_not_saveable`。`what` は `repl`。REPL の変数は入力をまたいで残るが、関数の値は、次の入力では別のプログラムを指しうるため）。式の値として表示するのは構わない。`:repl` で入るときも、停止点で使い終わっている関数の型のローカル変数は、REPL の変数にしない。
- この表示形は、`yomi run` の `:vars` と、REPL の `:vars`・`:apply`（7.3.6・7.6）で共通である。`${}` に埋め込む文字列（`Value::to_text`）は、これとは別で、変わらない。

## 7.3 状態と有効範囲

### 7.3.1 環境

REPL の入力は、次の層に対して評価する。

| 層 | 内容 | REPL からの扱い |
| --- | --- | --- |
| ホスト | 登録表のコマンド、ホストが宣言した変数・型、パッケージの状態 | コマンドを呼べる。変数は読み書きできる（`read_only` への代入は、台本と同じにエラー `assign_to_read_only`） |
| 台本のモジュール | すべてのモジュールの `save var`・`persistent var`・`fn`・`struct`・`enum`・`identity`・ラベル | 読み書きできる（`fn` の中の書き込みの禁止は、台本と同じ） |
| 停止点のローカル変数 | `:repl` では、いまのラベルの引数と `let`。`yomi repl` では、なし | 読み書きできる。`call` で積まれた呼び出し元のラベルのローカル変数は、見えない |
| REPL | REPL で宣言した `let`・`fn`・型・`import`・`identity`（7.3.3） | 読み書きできる |

- **現在のモジュール**は、`:repl` では、停止点のラベルのモジュール、`yomi repl <台本>` では、起動ファイルのモジュール、台本がなければ、なし。REPL の入力は、現在のモジュールの中に書いたものとして、名前を解決する。現在のモジュールの変数・`fn`・型・identity・ラベルは、名前だけで書ける。現在のモジュールが `import` したモジュール・パッケージは、`モジュール.名前` で書ける（language/04-labels-modules.md の 4.2、4.6）。
- ほかのモジュールの名前を使うときは、REPL で `import モジュール` を書く（現在のモジュールが `import` していなくてもよい）。
- 使える identity は、現在のモジュールで宣言した identity と、現在のモジュールが `import` したモジュールの identity（language/02-lines.md の 2.3）。REPL で `identity` を宣言すれば、足される。

### 7.3.2 名前の衝突

REPL の宣言の名前は、台本の宣言と同じ規則で検査する。重なるときは、`duplicate_name`（language/06-diagnostics.md の 6.5）。

- `let`：language/03-statements.md の 3.4 の規則に従う。見えている `let`・ローカル変数・モジュール変数と同じ名前はエラー。ラベルの名前と同じでもエラーにしない。モジュールの名前・パッケージの名前と同じ名前もエラー（language/04-labels-modules.md の 4.2）。
  - ただし、REPL で宣言した `let` と同じ名前の `let` は、前の変数を置き換える（型が変わってもよい）。
- `fn`：language/03-statements.md の 3.5 の規則に従う。ただし、REPL で宣言した `fn` と同じ名前の `fn` は、引数と戻り値の型が同じときに限り、本体を置き換える。型が違うときは、`duplicate_name`。
- `struct`・`enum`・`identity`：同じ名前の宣言は、`duplicate_name`。置き換えはできない（その型の値が、REPL の変数に残っていることがあるため）。
- `import`：すでに `import` した名前を、もう一度書いても、何も起こらない（エラーにしない）。
- REPL の `fn` の本体からは、台本の `fn` の規則（language/03-statements.md の 3.5）のとおり、モジュール変数とホストの変数は読めるが、REPL の `let` は見えない（REPL の `let` は、REPL の最上位のローカル変数として扱う）。
- REPL で宣言した型は、モジュール `<repl>` の型として扱う。診断では `<repl>.Prize` の形で示す。

### 7.3.3 REPL の宣言の有効範囲

- REPL の `let`・`fn`・型・`import`・`identity` は、**その REPL の中だけ**で有効である。台本のファイルには書かれず、台本のコンパイル結果・安定 ID・位置のハッシュ・セーブの形式・永続データに影響しない。`yomi assign-ids`・`yomi texts` などの道具にも見えない。
- REPL を終えると（`:exit`・`:quit`・EOF）、すべて消える。`:reset`（7.6）でも消える。`:repl` に入るたびに、空から始まる。`:apply`（7.3.6）も、これらを台本へ反映しない（変数の値だけを反映する）。
- REPL の入力は、セーブに入らない。REPL の中では、セーブ・ロード・ロールバックを使えない（7.6）。
- `{ }` の中の `let` は、ブロックの中のローカル変数で、台本と同じに、ブロックを出ると消える。入力の最上位の `let` だけが、REPL の変数として残る。

### 7.3.4 台本への影響

REPL の実行は、環境の**複製**の上で行う。複製は、`:repl` に入ったとき（`yomi repl` では起動したとき）に作り、REPL を終えるまで使う。

- 台本の実行位置・コールスタック・ローカル変数・モジュール変数・ホストの変数・パッケージの状態・乱数の状態・停止点の履歴（`:back` で戻れる停止点を含む）・通過済みの停止点（`seen`）・入ったラベル（`visited`）・選び済みの `once` は、`:repl` に入る前と同じまま、変わらない。**`:apply`（7.3.6）を使ったときだけ**、その規則で決まる変数の値が、台本へ書き戻される。
- REPL の中での変更（`favor += 1` や、`call` したラベルが変えた変数、`persistent var` の変更を含む）は、複製の中にだけ起こり、REPL の中の後の入力からは見える。台本へ戻す（反映する）手段は、`:apply` だけである。
- 永続データのファイルは、REPL の中の変更では、書き換えない（`yomi run` が `:repl` のあとに書く永続データは、`:repl` の前と同じ内容。`persistent var` は `:apply` の対象でもない。7.3.6）。
- 複製の乱数は、複製の中で進む。`random` を REPL で呼んでも、台本の以降の乱数の列は変わらない（`:apply` も、乱数の状態は反映しない）。
- REPL を終えると、複製を捨てる。`:apply` をしていなければ、`:exit` のあとの台本は、REPL を使わなかったときと、同じ状態から続く（host/01-execution.md の 1.7）。`:apply` をしたあとは、反映した変数の値だけが違う状態から続く。

### 7.3.5 副作用のあるコマンドと上限

- 副作用型のコマンドは、複製の中のパッケージの状態を変える。問い合わせ型は、複製の状態を読む。停止型のコマンドは、7.4 の流れで止まる。
- コアは、画面・音・時間・ファイルを持たない（host/01-execution.md の 1.1）。副作用型のコマンドが、外の世界（音を鳴らす、画像を出す）へ反映されるかは、ホストが決める。CLI は、合図（`[audio]`・`[image]`）を、停止点と同じに表示するだけで、反映するものはない。
- 入力ごとに、命令数の上限（`max_steps_per_run`）を数え直す。終わらないループは、実行時エラー（`step_limit_exceeded`）で止まり、その入力は取り消される（7.7）。値の大きさ・変数の大きさの合計・呼び出しの深さの上限も、台本と同じである（host/01-execution.md の 1.9）。REPL の変数も、変数の大きさの合計に数える。

### 7.3.6 `:apply`（台本本体への反映）

`:apply` は、REPL の複製で変えた変数の値を、停止中の台本本体（`yomi run` の VM）へ書き戻す。REPL を使っただけでは、台本は変わらない（7.3.4）。`:apply` を打ったときだけ、次の規則で、変数の値が、台本の「いまの停止点」の状態になる。

#### 使える場所

- `yomi run` の停止中の `:repl` の、入力を待つプロンプト（7.5）だけで使える。
- `yomi repl`（`<台本>` の有無によらず）では使えない。台本本体が、まだ動いていないか、台本がないため。また、REPL の入力の実行の途中の停止点（7.4）でも使えない。使うと、標準エラーに使えないことを知らせて、REPL に残る。

#### 何を反映するか

| 区分 | 変数・状態 | `:apply` |
| --- | --- | --- |
| 反映する | モジュールの `save var` | 値を書き戻す |
| 反映する | ホストが宣言した `Kind::Save` の変数 | 値を書き戻す |
| 反映する | 停止点のラベルのローカル変数（引数と `let`。`for` の隠し変数を除く） | 値を書き戻す |
| 反映しない | `persistent var`・ホストが宣言した `Kind::Persistent` の変数 | 書き戻さない（下の「`persistent var`」） |
| 反映しない | パッケージの状態（音・画像の合図を含む）・乱数の状態・`seen`・`visited`・選び済みの `once`・停止点の履歴・コールスタックと呼び出し元のローカル変数 | 書き戻さない。複製の中だけで変わったままで、REPL の中では見える |
| 反映しない | REPL の宣言（`let`・`fn`・型・`import`・`identity`）・`read_only` の変数 | 台本にない・書けないので、対象にならない |

- 反映するのは、複製の値と、台本本体のいまの値が**違う**変数だけである。変更の記録は使わず、いまの値を比べる。`favor += 1` のあとに `favor -= 1` で元の値に戻せば、`favor` は反映する対象にならない。
- 反映する変数がなければ、何も変えずに、その旨を 1 行、標準出力に出す。

#### `persistent var`

`persistent var`（と `Kind::Persistent` の変数）は、`:apply` の対象に**しない**。理由は、`persistent var` が、全セーブで共有され、ロールバックでも戻らず（host/04-save.md の 4.5・4.7）、台本が停止中でも `yomi run` が永続データのファイルへ書き出す経路を持つため、REPL での試し書きを、あとで取り消せなくなるからである。

- 複製で値が変わっている `persistent var` があるときは、`:apply` は、ほかの変数だけを反映し、反映しなかった変数の名前を、標準エラーに知らせる（エラーにはしない。終了コードにも影響しない）。
- `persistent var` を変えたいときは、台本の側（台本の文）で変える。`:apply` に、対象を広げる指定はない。

#### 検査と原子性

`:apply` は、全部を反映するか、何も反映しないかの、どちらかである（原子的）。台本本体は、次の検査にすべて通ったときだけ変わる。

1. 型：反映する値が、変数の宣言の型に合う。REPL で宣言した型（`<repl>` の型）の値は、台本の変数に入らないので、含まれていれば失敗する。
2. 上限：値の大きさ（`max_value_bytes`）と、変数に保持された値の合計（`max_total_bytes`）が、反映後も上限以内（host/01-execution.md の 1.9）。
3. セーブできる形：入れ子の深さが 64 以内で、`float` が有限（host/04-save.md の 4.3）。
4. 停止点の引数を、反映後の値で作り直せる（`${式}`・`if` などを評価して、実行時エラーにならない。0 での割り算など）。

どれかに失敗したときは、台本本体を `:apply` の前のままにして、失敗した変数の名前（または実行時エラー。7.7 の形）を、標準エラーに出す。REPL の複製は、変わらず、続けて使える。

台本の流れと矛盾する値（`visited` と合わない `favor` など）は、検査しない。`:apply` は、変数の値を、そのまま入れる。

#### 反映したあと

- 停止点の引数を、反映後の値で**作り直す**（host/04-save.md の 4.5 の `load_persistent` と同じ）。乱数は、台本本体が、停止点の引数を求め始めたときの状態から使うので、REPL で `random` を呼んだことは、影響しない。`if` の条件で選択肢の数が変わるなど、停止点の内容が変わることがある。
- 反映した変数を、`名前 = 値`（値は 7.2.4 の表示形。モジュールが複数のときは、モジュール変数を `モジュール.名前` で）の形で 1 行ずつ、標準出力に出す。
- `:exit` で停止点へ戻るとき、変数を 1 回でも反映していれば、作り直した停止点を、`:texts` のあとと同じに、表示し直して待つ（host/06-cli.md の 6.3.4）。
- `:reset`（7.6）は、最後に `:apply` が反映したあとの台本本体の環境の、新しい複製へ戻す（反映しなかった差分は捨てる）。`:apply` が何も反映しなかったとき（反映する変数がない・失敗）は、基準は変わらない。
- REPL は続く。続けて、REPL の入力と `:apply` を繰り返せる。

#### ロールバック・履歴・セーブとの関係

反映した値は、台本の「いまの停止点」の、セーブできる状態（`save var`・ローカル変数）に、そのまま入る。過去の停止点は、書き換えない。

| 対象 | `:apply` のあと |
| --- | --- |
| `:save`（host/04-save.md） | いまの停止点のセーブに、反映後の値が入る。`:load` で読むと、反映後の値で再開する |
| `:back`（host/04-save.md の 4.7） | `yomi run` が停止点ごとに取るスナップショットのうち、**いまの停止点のものを、反映後の状態で取り直して置き換える**。それより前のスナップショットは、変えない |
| `:back` で前の停止点へ戻ったとき | 前の停止点の状態（反映前の値）に戻る。反映した値は、いまの停止点より前には効かないので、失われる。同じ入力で進み直しても、反映した値は、自動では入らない |
| 停止点の履歴（`vm.history()`） | いまの停止点の記録の `args`・`values` だけを、作り直した値にそろえる（host/04-save.md の 4.3）。それより前の記録は、変えない |
| `seen`・`visited`・`once` の選び済み・乱数 | 変わらない |
| 永続データのファイル | 変わらない（`persistent var` は、反映の対象外） |

## 7.4 台本の行と停止の流れ

素の行・引用行・`choice { }`・停止型コマンド（`@flow.wait(1.0)`・`let n = @input.integer(…)`）、また、`call` したラベルの中の停止点で、実行が止まる。止まった入力は、`yomi run` と同じ流れで進める（host/06-cli.md の 6.3.1・6.3.2）。

```
yomi> 案内人「信頼度は${favor}」
リオン「信頼度は3」

yomi> choice {
...>   「買う」 => favor += 1
...>   「帰る」 => favor -= 1
...> }
1: 「買う」
2: 「帰る」
1
yomi> favor
4
```

（1 つ目の停止点（本文）の次の空行は、停止点の待ちに Enter だけを打った入力。`1` は、選択の答え。停止点の待ちでは、プロンプト `yomi> ` を出さない。`yomi run` と同じ）

- **表示**：停止点は、host/06-cli.md の 6.3.1 の表のとおりに、標準出力に表示する。音・画像の合図も、同じ位置（停止点の前、入力の終わりの前）に出す。
- **入力**：停止点ごとに、標準入力から 1 行読む。停止点の待ちには、プロンプト（`yomi> `・`...> `）を出さない（`yomi run` と同じ。host/06-cli.md の 6.3.2）。規則は、host/06-cli.md の 6.3.2 のとおり（本文・待ちは空行で進む。選択は番号。`input.*` は値）。EOF のときの既定の答えも同じ。
  - REPL の入力には、安定 ID がない。選択を `#id` で答えることは、できない（番号だけ）。`call` したラベルの中の選択肢の ID は、台本のとおりに持つので、`#id` でも答えられる。
- **`--auto`**：`yomi run --auto` の中の REPL でも、停止点では入力を読む。
- **入力の誤り**：`yomi run` では終了コード 1 になる入力の誤り（`input.integer` に整数でない入力、`input.confirm` に正しくない入力、範囲の外の値、`input.text` の長すぎる入力）は、REPL では終了せず、エラーを標準エラーに出して、その入力の実行を取り消す（7.7）。選択の答えの誤り（範囲外・一覧にない ID）は、`yomi run` と同じに、同じ停止点で求め直す。
- **停止点での対話コマンド**：REPL の中の停止点では、`:vars`・`:abort`・`:quit`・`:help` を使える（7.6）。`:apply`・`:reset`・`:exit` などは、入力を終えてから（プロンプトで）打つ。
- **`call`**：`call ラベル(引数)` は、台本のラベルを、一時的に呼ぶ。ラベルの中の素の行・引用行・`choice` は、停止点になり、`jump` は、ラベルの中で台本のとおりに働く。ラベルが `return` かラベルの末尾に着くと、`call` の次へ戻る（その入力の終わり）。ラベルの中で `end` に達すると、`(end)` を表示して、その入力を終える（REPL は続く）。
- **台本の位置**：REPL の入力は、台本の実行位置にならない。`call` したラベルに入っても、台本の停止点の履歴・`seen`・`visited` は、変わらない（7.3.4）。
- **差し替え表**：`yomi run` で設定している本文の差し替え表（host/05-texts.md）は、`call` したラベルの中の、安定 ID つきの行に効く。REPL の入力そのものは、安定 ID がないので、差し替えられない。
- **ホストが作る REPL** は、停止型で止まったとき `Yield::Stop` と同じ形の知らせを受け、ホストが処理して、`Input::Return` で再開する（7.8）。

## 7.5 複数行入力と継続の判定

ブロックや複数行の引用行は、複数の行にまたがる。REPL は、行を読むたびに、それまでに読んだ行をつないだ入力が**完了**・**未完了**・**不正**のどれかを、構文だけで判定する。確定の合図は、**構文が完了したこと**であり、空行ではない。

| 判定 | 意味 | 動作 |
| --- | --- | --- |
| 完了 | 1 つの入力として読める | その場で確定して、実行する。空行を待たない |
| 未完了 | 入力の終わりに達したために読めない。続きを書けば、読める可能性がある | 継続のプロンプト（`...> `）を出して、次の行を読み、入力に足す。**空行も、入力の一部として足す** |
| 不正 | 入力の途中に誤りがあり、続きを書いても直らない | 診断を出して、入力を捨てる |

### 7.5.1 判定の規則

入力は、先頭から読む。次の場合に限り、**未完了**とする。

- 読んだ範囲に、入力の終わり以外の誤りがなく、かつ、
- 入力の終わりで、次のいずれかが閉じていない。
  1. `{ }` のブロック。`if`・`else`・`while`・`for`・`match`・`choice`・`fn`・`struct`・`enum` の `{`（診断のコードは `unterminated_block`）。
  2. identity つきの引用行と、選択肢の文の `「` の、対応する `」`（language/02-lines.md の 2.4。続けて読む行は 256 行まで。診断のコードは `unterminated_quote`）。

次のものは、未完了ではなく、**不正**（または、それ自体の誤り）とする。

- 文・`@` のコマンドの行が、続きの足りないところで終わる（`let x =`・`let x = (1 +`・`@flow.wait(` のような、閉じていない `(`・`[` を含む。`unexpected_eol`）。式は、1 行に書く（language/03-statements.md の 3.2）。文でも `@` の行でもなく、式としても読めない行（`(1 +` など）は、素の行になる（language/02-lines.md の 2.1）。
- 閉じていない文字列リテラル（`unterminated_string`）。文字列は、改行を含められない。
- 対応する開きのない `}`（`unexpected_close`）。
- identity のない `「` で始まる行の、閉じていない `「`。台本のファイルと同じに、素の行（1 行）として扱う（language/02-lines.md の 2.4）。これは**完了**で、その場で実行する。
- 続けて読む行が、256 行を超えた引用行。

判定は、入力の文字だけで決まり、REPL の環境（宣言された名前）によらない。名前や型の誤り（`unknown_name`・`type_mismatch` など）は、構文が完了してから、実行の前に、型検査で見つける（7.7）。

- 複数行にまたがる入力が完了するのは、閉じる `}`・`」` の行を読んだときである。`if` の `else` は、台本のファイルと同じに、`} else {` と同じ行に書く（`else` だけの行は、新しい入力として読み、`else_without_if`。language/06-diagnostics.md）。そのため、`}` で完了した入力に、あとから行が足されることはない。
- ブロックの中の空行は、台本のファイルと同じに、何も起こさない行である。複数行の引用行の中の空行は、台本のファイルと同じに読む（language/02-lines.md の 2.4）。どちらも、未完了のあいだは入力の一部なので、空行を含むブロックを、そのまま貼り付けられる。
- 完了した入力のあとの空行は、新しい入力の空行（7.2.1 の①）で、何も起こらない。貼り付けた文字列に、入力の間の空行があっても、動作は変わらない。

### 7.5.2 入力の流れ

1. プロンプト `yomi> ` で、1 行読む。`:` で始まる行は、対話コマンドとして、その場で処理する（複数行にしない）。
2. 完了なら、確定して実行する。不正なら、診断を出して、捨てる。
3. 未完了なら、プロンプトを `...> ` にして、次の行を読み、前の行に改行でつないで、もう一度判定する（2 へ戻る）。続きの行は、空行でも、`:` で始まっても、入力の一部である。ただし、行全体が `:cancel` のときだけは、取り消しのコマンドとして処理する（下の「入力の取り消し」）。
4. **EOF** は、入力の途中でも、入力を確定する。確定した入力が、未完了のままなら、その原因の診断（`unterminated_block`・`unterminated_quote`）を出して、入力を捨てる。そのあと、REPL は終わる（7.1 の終了）。

```
yomi> fn bonus(n: int) -> int {
...>   return n * 2
...> }
yomi> bonus(favor)
6
yomi> if favor >= 3 {
...>   favor = 0
...>
...>   favor += 1
...> }
yomi> favor
1
yomi> if favor >= 1 {
...>   favor = 99
...> :cancel
yomi> favor
1
```

- 空行を含むブロックも、そのまま入力できる（`if` の本体の途中の空行は、ブロックの中の行）。
- 最後の例は、書きかけの入力を `:cancel` で取り消したもの。`favor = 99` は実行されず、`favor` は変わらない。
- 診断の位置は、確定した入力全体での行・桁である（7.7）。入力の途中の行で不正になったときも、その時点までの入力を 1 つの入力として報告する。そのあとの行は、新しい入力として読む。

### 入力の取り消し

書きかけの入力（`...> ` の途中）を、実行せずに捨てる操作は、次のとおり。取り消した入力は、何も実行せず、診断も出さず、REPL の状態も変えない。

| 操作 | 動作 |
| --- | --- |
| `:cancel`（行全体） | 書きかけの入力を捨てて、`yomi> ` へ戻る。書きかけでないとき（`yomi> ` で打ったとき）は、何も起こらない |
| EOF（Ctrl-D など） | 取り消しではない。入力を確定して、REPL を終える（上の 4） |

- 端末の Ctrl-C は、`yomi repl` の CLI では扱わない（端末の既定の働きで、プロセスが終わる）。CLI で書きかけの入力を捨てるには `:cancel`、REPL を終えるには入力の終わり（EOF）か `:exit`・`:quit` を使う。
- ホストが自分の REPL を作るときは、Ctrl-C を `:cancel` と同じ取り消しにしてよい。その場合、`...> ` の途中では書きかけの入力を捨て、`yomi> ` の途中では打ちかけの行を捨てて新しいプロンプトを出す。REPL は終わらない。
- 複数行の引用行の本文に、`:cancel` だけの行を含めることはできない（行全体が `:cancel` なら、取り消しになる）。
- 入力の実行中（停止点の待ちや、終わらない処理）の Ctrl-C は、この章では定めない（`:abort` は、停止点の待ちでの取り消しである。7.6）。
- `:cancel` と `:abort` は、別のものである。

| コマンド | 取り消すもの | 使う場面 | 実行された副作用 |
| --- | --- | --- | --- |
| `:cancel` | **実行前**の、書きかけの入力 | `...> ` で入力を打っているとき | なし（まだ実行していない） |
| `:abort` | **実行中**の入力（停止点で止まっている） | 入力の途中の停止点（7.4）で待っているとき | その入力の前の状態へ戻す（7.7）。表示済みの出力は、取り消せない |

## 7.6 対話コマンド

`:` で始まる行は、対話コマンドである（入力の途中の行を除く。7.5.2 の 3。途中で使えるのは、行全体が `:cancel` のときだけ）。コマンドと引数は、空白で区切る（引数は、残りの行全体。前後の空白は取り除く。host/06-cli.md の 6.3.4）。処理のあとは、REPL は、次の入力を待つ。

| コマンド | 動作 |
| --- | --- |
| `:help` | 使えるコマンドの一覧を、1 行に 1 つ、標準出力に出す |
| `:vars` | 変数を、`名前 = 値` で 1 行ずつ、標準出力に出す。台本の変数（host/06-cli.md の 6.3.4 の `:vars` と同じ並びと名前の付け方）に、続けて、区切りの 1 行（`en` では `-- REPL variables --`）と、REPL の `let` の変数（`名前 = 値`）。REPL の変数がないときは、区切りの行も出さない。値は、7.2.4 の表示形（`yomi run` の `:vars` と同じ） |
| `:defs` | REPL で宣言した `fn`・`struct`・`enum`・`import`・`identity` を、宣言の順に、`fn bonus(n: int) -> int`・`struct Prize`・`enum Mood`・`import std::math`・`identity 案内人` の形で、1 行ずつ出す |
| `:type <式>` | 式の型を、台本での書き方（`int`・`list<str>`・`Mood`）で出す。現在のモジュールと REPL の型は、モジュール名を付けず、ほかのモジュールの型は `モジュール.型名`（`chara.Mood`）で書く。式は評価しない（コマンドも呼ばない）。式でない入力は、エラー |
| `:apply` | 複製で変えた変数の値を、停止中の台本本体へ書き戻す（7.3.6）。`yomi run` の停止中の `:repl` の、入力を待つプロンプトだけで使える |
| `:reset` | REPL の宣言をすべて捨て、環境を、REPL を始めたときの複製（`:apply` が反映したあとは、そのときの台本本体の環境の複製）に戻す。変数の変更も戻る。何も表示しない |
| `:exit` | REPL を終える。`:repl` からは、停止点へ戻る。`yomi repl` は、終了コード 0 |
| `:quit` | 実行全体をやめる。終了コード 0（host/06-cli.md の 6.3.4 の `:quit` と同じ） |
| `:cancel` | 書きかけの入力（`...> `）を、実行せずに捨てて、`yomi> ` へ戻る（7.5.2）。書きかけでなければ、何も起こらない |
| `:abort` | 停止点の途中（7.4）でだけ使える。**実行中**の入力を取り消して、プロンプトへ戻る（7.7 の取り消しと同じ）。`:cancel` とは別（7.5.2） |
| `:repl` | `yomi run` の中でだけ使える（7.1）。REPL の中で打つと、エラー |

### `yomi run` のコマンドとの関係

`yomi run` の停止点の対話コマンド（host/06-cli.md の 6.3.4）と、REPL のコマンドの関係は、次のとおり。

| コマンド | REPL の中 |
| --- | --- |
| `:vars` | 使える。REPL の変数も出す。値の形は、`yomi run` と同じ（7.2.4） |
| `:quit` | 使える。同じ動作 |
| `:save`・`:load`・`:back`・`:texts` | 使えない。標準エラーに、REPL の中では使えないことを知らせて、REPL に残る。使うときは、`:exit` で停止点へ戻ってから打つ |

- `:repl` は、`yomi run` の停止点で使える対話コマンドである。`:exit` は、`yomi run` の停止点では、知らないコマンドになる（`:quit` を使う）。
- 知らないコマンド・必要な引数がないコマンドは、標準エラーに知らせて、次の入力を待つ。使えるコマンドの一覧を添える。

## 7.7 エラー表示

### 診断

REPL の入力の診断（構文・型検査・名前の検査）は、`yomi run` や `yomi check` と同じ**コードと引数**で出す（language/06-diagnostics.md の 6.5）。1 件 1 行で、標準エラーに書く（host/06-cli.md の 6.1 の書式）。

```
<repl>:1:1: error: unknown name 'gld' (did you mean: gold?)
```

- 診断の位置の「ファイル」は `<repl>`（モジュール名も `<repl>`）。行・桁は、**確定した入力全体**での位置で、1 始まり。複数行の入力は、最初の行が 1 行目。桁は、Unicode スカラ値の数（language/06-diagnostics.md の 6.1）。
- 近い綴りの候補（`suggestions`）は、REPL の変数・`fn`・型も含めて探す（language/06-diagnostics.md の 6.4）。
- エラーがあれば、入力は、実行しない。REPL の状態は、変わらない。警告だけのときは、警告を標準エラーに出して、実行する。
- `<repl>` の型は、`<repl>.Prize` の形で示す（7.3.2）。

### REPL だけのコード

REPL の入力にだけ、次のコードがある。重大度はエラー。`yomi codes` にも出る（host/06-cli.md の 6.8）。

| コード | 引数 | 意味 |
| --- | --- | --- |
| `repl_not_allowed` | `what` | REPL の入力に書けないもの。`what` は、`stable_id`（安定 ID）・`once`・`save`・`persistent`・`label`・`jump`・`end`・`return`（`fn` の外） |

### 実行時エラー

- 実行時エラー（language/06-diagnostics.md の 6.6）は、`<repl>: error: <文面>` の形で、標準エラーに書く。入力の中の行がわかり、入力が**複数行**のときは、文面の後ろに `(line 行)` を（1 行の入力では付けない。行は 1 つに決まっている）、`call` したラベルの中で起きたときは、`(label モジュール.ラベル, line 行)` を付ける（host/06-cli.md の 6.1）。
- **入力は、取り消される**。実行時エラーになった入力と、`:abort` した入力は、その入力が始まる前の状態へ戻す。REPL の変数・宣言と、複製の台本の状態（変数・パッケージの状態・乱数）の、入力の中の変更は、すべてなくなる。すでに表示した出力（停止点の表示・合図）は、取り消せない。
- 取り消したあとも、REPL は続く（`yomi run` と違い、実行時エラーで終了しない）。

```
yomi> let xs = [1, 2]
xs = [1, 2]
yomi> xs[5]
<repl>: error: the list index 5 is out of range (the list has 2 items)
yomi> xs
[1, 2]
```

## 7.8 コア API

ホストは、コアの API で、自分の REPL を作れる。`yomi repl` と `:repl` は、同じ API の上にある（表示と入力は、CLI の責務である）。形は、host/01-execution.md の 1 章と同じ書き方で示す。

```rust
let mut repl = Repl::attach(&vm)?;                 // 停止中の vm の複製の上で始める（vm は変わらない）

loop {
    let text = read_input(&mut repl);              // 7.5 の流れで 1 つの入力を作る（行を足すたびに completeness。空行では確定しない）
    match repl.submit(&text) {
        Err(diags) => report(diags),               // 構文・型検査の診断（実行しない）
        Ok(submitted) => loop {
            match repl.run() {
                Ok(ReplYield::Stop { command, args, id }) => {
                    let result = host.handle(command, args, id);      // host/01-execution.md の 1.1 と同じ
                    repl.resume(Input::Return(result))?;
                }
                Ok(ReplYield::Done { value, declared, ended }) => { show(value, declared, ended); break }
                Err(e) => { report_runtime(e); break }                // 入力は取り消され、repl は続けて使える
            }
        },
    }
}
```

### 7.8.1 `Repl`

```rust
pub struct Repl<'a> { /* 複製の環境と、REPL の宣言 */ }

impl<'a> Repl<'a> {
    /// 台本のない、空の環境で始める。
    pub fn empty(registry: &'a Registry, cfg: VmConfig) -> Result<Self, VmError>;
    /// 台本の開始ラベルの先頭の状態（実行前）の複製の上で始める。開始ラベルがなくてもよい。
    pub fn from_program(program: &'a Program, registry: &'a Registry, cfg: VmConfig) -> Result<Self, VmError>;
    /// 停止中の VM の複製の上で始める。`vm` は変わらない（`apply` を呼ぶまで）。停止中でなければ `Err`。
    pub fn attach(vm: &Vm<'a>) -> Result<Self, VmError>;

    /// 入力を、型検査して、実行の準備をする（実行はしない）。
    pub fn submit(&mut self, input: &str) -> Result<Submitted, Vec<Diagnostic>>;
    /// 準備した入力を、次の停止点（または終わり）まで進める。
    pub fn run(&mut self) -> Result<ReplYield, VmError>;
    /// 停止中の入力を、停止型コマンドの戻り値で再開する。
    pub fn resume(&mut self, input: Input) -> Result<(), VmError>;
    /// 実行中（停止中を含む）の入力を取り消す。
    pub fn abort(&mut self);
    /// パッケージ `P` の状態スライスを読む（読むだけ。合図の表示に使う）。
    pub fn package_state<P: Package>(&self) -> Option<&P::State>;

    /// 式の型を調べる（評価しない）。式でなければ `Err`。
    pub fn type_of(&self, input: &str) -> Result<Ty, Vec<Diagnostic>>;
    /// 複製の変数の一覧。REPL の変数は、`module` が `Some("<repl>")`。
    pub fn variables(&self) -> Vec<Variable>;
    /// REPL で宣言した `fn`・型・`import`・`identity`（宣言の順）。
    pub fn defs(&self) -> Vec<Def>;
    /// REPL の宣言を捨て、複製を、始めたとき（`apply` が反映したあとは、そのとき）の状態に戻す。
    pub fn reset(&mut self) -> Result<(), VmError>;
    /// 複製で変えた変数を、`attach` した `vm` へ反映する（7.3.6）。全部反映するか、何も反映しないか。
    pub fn apply(&mut self, vm: &mut Vm<'a>) -> Result<Applied, ApplyError>;
}

/// 構文だけで、入力が完了しているかを判定する（環境によらない。7.5）。
pub fn completeness(input: &str) -> Completeness;

#[non_exhaustive]
pub enum Completeness {
    Complete,
    Incomplete,
    Invalid(Vec<Diagnostic>),     // 7.5.1 の不正。診断は、入力の位置の順
}
```

- `Repl` は、台本の `Program` を変えない。`Vm` も、`apply`（7.3.6）を呼ばないかぎり変えない。REPL の宣言は、`Repl` の中にだけある（7.3.3）。
- `completeness` は、7.5.1 の規則のとおりに、`Complete`・`Incomplete`・`Invalid` を返す。`Incomplete` は、診断のコードが `unterminated_block` か `unterminated_quote` のものだけのときである。コマンド（`:` で始まる行）は、`Complete` を返す。
- ホストは、行を足すたびに、それまでの入力全体（行を改行でつないだもの。空行を含む）に `completeness` を呼ぶ。`Complete` なら確定して `submit` へ、`Incomplete` なら次の行を足す（空行でも、確定しない）、`Invalid` なら診断を出して捨てる。空白だけの文字列（空行）は `Complete` で、`submit` は何もしない入力として受ける。入力の取り消し（`:cancel`・Ctrl-C）は、ホストが、入力の文字列を捨てるだけで行う（7.5.2）。入力の終わり（EOF）で `Incomplete` のままのときは、`submit` を呼ぶ。`submit` は、未完了の入力に、`unterminated_block`・`unterminated_quote` の診断を返す。
- `type_of` は、副作用なしで、`submit` と同じ検査を式にだけ行う。
- `package_state::<P>()` は、`run` のあと（入力の実行中は、その入力の、そうでなければ確定した複製の）パッケージ `P` の状態を読む（`Vm::package_state` と同じ。音・画像の合図を、停止点や入力の終わりの前に表示するために使う）。

### 7.8.2 入力の実行

```rust
#[non_exhaustive]
pub struct Submitted {
    pub kind: InputKind,
    pub warnings: Vec<Diagnostic>,            // 警告（位置の順）
}

#[non_exhaustive]
pub enum InputKind { Expression(Ty), Statement, Declaration }

#[non_exhaustive]
pub enum ReplYield {
    /// 停止型コマンドで止まった（`Yield::Stop` と同じ。`id` は、`call` したラベルの中の行のときだけ `Some`）。
    Stop { command: CommandId, args: Vec<Value>, id: Option<String> },
    /// 入力の実行が終わった。
    Done {
        value: Option<(Value, Ty)>,           // 式の値（式の入力だけ）
        declared: Vec<Declared>,              // この入力で宣言したもの（`let` の値を含む）
        ended: bool,                          // `call` したラベルの中で `end` に達した
    },
}

#[non_exhaustive]
pub enum Declared {
    Let { name: String, value: Value, ty: Ty },
    Fn { name: String },
    Type { name: String },
    Import { name: String },
    Identity { name: String },
}
```

- `submit` → `run` →（`Stop` なら `resume` → `run` を繰り返し）→ `Done` の順に呼ぶ。`submit` は、前の入力が終わって（`Done`・実行時エラー・`abort` のあと）いるときだけ呼べる。順序を守らない呼び出しは、`Err`（host/01-execution.md の 1.4 と同じ規則）。
- `submit` が `Err` のとき（診断）、`Repl` の状態は変わらない。
- **取り消し**：`run`・`resume` が実行時エラーを返したとき、または `abort` を呼んだとき、`Repl` は、その入力の前の状態に戻る（REPL の変数・宣言・複製の台本の状態・乱数・パッケージの状態。7.7）。`Vm` と違い、続けて `submit` できる（`poisoned` にならない）。
- `Done` のあとの `Repl` は、入力の変更を残す（7.3.4 の複製の中）。
- 命令数の上限（`max_steps_per_run`）は、`run` ごとに数え直す（host/01-execution.md の 1.9）。上限・決定性（同じ複製・同じ入力の列は、同じ結果。host/01-execution.md の 1.7）は、`Vm` と同じである。中断（host/01-execution.md の 1.9a）も `Vm` と同じで、`repl.interrupt_handle()` でトークンを得る。中断された入力は、取り消す。
- 表示形（7.2.4）の文字列は、`Value::to_repl_text()` で作れる。`yomi run` の `:vars` も、これを使う（`Value::to_text()` は、`${式}` の埋め込み用で、別）。

### 7.8.3 `apply` の結果

```rust
#[non_exhaustive]
pub struct Applied {
    pub variables: Vec<Variable>,     // 反映した変数（反映後の値。`vm.variables()` と同じ形・並び）
    pub skipped: Vec<Name>,           // 値が違っていたが、反映しなかった変数（`persistent var`・`Kind::Persistent`）
}

#[non_exhaustive]
pub enum ApplyError {
    /// `from_program`・`empty` で作った `Repl`（台本本体がない）。入力の実行の途中（停止点で止まっている間）にも、この値を返す。
    NotAttached,
    /// `attach` したときの停止点から、`vm` が進んだ・読み直した（`resume`・`restore`・`load` をした）、または別の `Vm`。
    VmChanged,
    /// 反映する値が、型・上限・セーブできる形の検査に失敗した。
    Invalid { name: Name, reason: ApplyInvalid },
    /// 反映後の値で、停止点の引数を作り直せなかった（実行時エラー）。
    StopArgs(VmError),
}
```

- `apply` が `Err` のとき、`vm` と `Repl` は、変わらない（`vm` は `poisoned` にならない）。`Ok` のとき、`Applied::variables` が空なら、何も変わっていない。
- `ApplyInvalid` は、`Type`・`ValueTooLarge`・`MemoryLimit`・`NotSavable`（7.3.6 の検査の 1〜3）のどれか。

### 7.8.4 ホストの責務

- 入力を読む・プロンプト・行の編集・継続の判定の呼び出し（`completeness`）は、ホストが行う（7.5.2 の流れは、CLI の例である）。
- 停止型コマンドの処理と、副作用型コマンドが外の世界へ与える影響は、ホストが決める（7.3.5）。REPL の中で外の世界へ反映したくないホストは、`ReplYield::Stop` を、表示だけにして、`Input::Return` を返す。
- `attach` を呼んだ `Vm` は、REPL を使っている間も、停止点のままである。ホストは、`Repl` を捨てれば、同じ停止点から `resume` を続けられる（7.3.4）。`apply` を呼んだときだけ、`Vm` は（反映した変数の値と、作り直した停止点の引数が）変わる。
- `apply` が `Ok` を返したら、ホストは、ロールバック用のスナップショットのうち、いまの停止点のもの（末尾）を、`vm.snapshot()` で取り直して置き換える。それより前のものは変えない（7.3.6）。表示は、`Applied::variables` と、`vm.current()`（作り直した停止点）から作る。
