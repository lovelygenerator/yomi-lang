# 3. 文と式

ラベルと遷移（`label` `jump` `call`）とモジュール（`import`）は [4 章](04-labels-modules.md) で定める。

## 3.1 型

| 型 | 内容 |
| --- | --- |
| `int` | 64 ビットの符号つき整数（`i64`） |
| `float` | 64 ビットの浮動小数（`f64`） |
| `bool` | `true` / `false` |
| `str` | UTF-8 の文字列 |
| `list<T>` | `T` の列 |
| `map<K, V>` | キーと値の対応 |
| `Option<T>` | `Some(x)` または `None`。null は持たない |
| `Identity` | 組み込みの型。`{ id: str, name: str }`（2.3、5.2） |
| `fn(T, …) -> R` | 関数の値（`fn` への参照・ラムダ式。3.5）。セーブに入れられない |
| enum / struct | 利用者が宣言する型 |

```ebnf
type = "int" | "float" | "bool" | "str"
     | "list" "<" type ">"
     | "map" "<" type "," type ">"
     | "Option" "<" type ">"
     | "fn" "(" [ type { "," type } ] ")" "->" type
     | identifier ;                (* enum / struct の名前 *)
```

- 型は静的に検査する。局所的な型推論を行い、関数のシグネチャには型注釈が必須である（3.5）。
- `int` と `float` の暗黙の変換はしない。変換は、組み込み関数 `to_int`・`to_float`（3.8）で書く。`int` と `float` を混ぜた演算・代入・比較は、型の不一致（`type_mismatch`）。
- `float` は有限の値だけを持つ。`NaN` と `±∞` は値として現れず、`-0.0` も持たない（`0.0` にそろえる。3.2）。
- `list<T>`・`map<K, V>`・`Option<T>` と、利用者が宣言した `struct`・`enum` は、**値**である。変数への代入・引数・戻り値・フィールドへの代入は、中身ごとのコピーで、コピーしたあとの更新は元に影響しない。`==` と `!=` は、同じ型どうしを、中身で比べる（`list` は要素の順に、`map` は同じキーが同じ値を持つか（挿入順は見ない）、`struct` はすべてのフィールド、`enum` はバリアントと引数、`Identity` は `id` と `name`）。`<` などの大小の比較は持たない。
- 空の `[]` と `None` は、型を持たない。変数の型注釈・代入先・フィールドの型・コマンドとラベルの引数の型・`==` `!=` の反対側の型から決まるときだけ書ける。決まらないときは、エラー（`cannot_infer_type`）。
- ホストが登録した `struct`・`enum`（host/02-registry.md の 2.5）も、同じ規則で使える。型の名前は `名前空間.型名`（`import 名前空間` して、`game.Chara { … }`・`game.Mood.Angry(2)`・型注釈 `game.Chara`）で、モジュールの型と名前がぶつかることはない。
- `struct` と `enum` は、モジュールの最上位にだけ宣言できる（3.7）。型の名前は、モジュールの名前を付けた `モジュール.型名` で区別する（ほかのモジュールの型は、`モジュール名.型名` と書く）。同じモジュールの中で、型の名前は、変数・ラベルの名前と重ならない。重なるとエラー（`duplicate_name`）。
- 型は、自分自身を（`list`・`Option` を通しても）含められない。含むとエラー（`recursive_type`）。型の入れ子（`list<list<…>>` と、フィールドや引数に入る型）は 32 段までで、超えるとエラー（`too_deep`）。
- `map<K, V>` のキー `K` にできる型は、`int`・`str`・`bool`・`Identity` と、フィールド（または値に付く型）がすべてキーにできる型の enum・struct。`float`・`list`・`map`・`Option` は、キーにできない（エラー `invalid_map_key`。引数 `type` はキーの型の名前）。型の宣言があとに書かれていても検査する。
- 関数の型 `fn(T, …) -> R` は、戻り値の型を省略できない（戻り値のない `fn` は、値にできない）。関数の値は、`==` と `!=` で比べられない（`invalid_operation`）。`map` のキーにできない。関数の型を含む型（`list<fn(int) -> int>` など）は、セーブに入る場所に置けない（3.5）。
- `Identity` は、変数・フィールド・引数などの型の注釈に書ける（`let who: Identity = 案内人`）。`.id`（`str`）と `.name`（`str`）で読め、`==` と `!=` で比べられる。
- map の反復の順序は、**挿入順**とする。既存のキーへの代入は、位置を変えない。キーを削除してから入れ直したら、末尾になる。セーブ・ロードでも順序は変わらない。キーの検索・更新・追加は、要素の数に比例しない時間で済む（キーの索引を持つ。索引はセーブしない）。キーの削除も、均すと要素の数に比例しない時間で済む。

## 3.2 式

```ebnf
expression = or_expr ;
or_expr    = and_expr { "||" and_expr } ;
and_expr   = eq_expr  { "&&" eq_expr } ;
eq_expr    = cmp_expr [ ( "==" | "!=" ) cmp_expr ] ;
cmp_expr   = add_expr [ ( "<" | "<=" | ">" | ">=" ) add_expr ] ;
add_expr   = mul_expr { ( "+" | "-" ) mul_expr } ;
mul_expr   = unary    { ( "*" | "/" | "%" ) unary } ;
unary      = ( "-" | "!" ) unary | postfix ;
postfix    = primary { call_args | "." identifier | "[" expression "]" } ;
call_args  = "(" [ call_arg { "," call_arg } [ "," ] ] ")" ;
call_arg   = [ identifier ":" ] expression ;   (* 名前つきの引数。3.5 *)
primary    = int_literal | float_literal | bool_literal | string_literal
           | identifier | "(" expression ")"
           | list_literal | map_literal | struct_literal
           | "Some" "(" expression ")" | "None"
           | lambda ;
lambda       = ( "||" | "|" [ lambda_param { "," lambda_param } ] "|" ) expression ;   (* 3.5 *)
lambda_param = identifier [ ":" type ] ;
list_literal = "[" [ expression { "," expression } [ "," ] ] "]" ;
map_literal  = "map" "{" [ map_entry { "," map_entry } [ "," ] ] "}" ;
map_entry    = expression ":" expression ;
```

- `list`・`map`・struct のリテラルと、呼び出しの引数は、最後の `,` を付けてもよい（`[1, 2,]`・`f(a, b,)`。意味は変わらない）。複数行に書けるのは、2.8 のとおり。
- map のリテラルは、先頭に `map` を付けて書く（例：`map { "a": 1, "b": 2 }`）。ブロックの `{ }` と区別するため。型名の `map<K, V>` とは、次の字句が `<` か `{` かで区別する。
- 空の map は `map {}` と書く。型は、変数の型注釈・代入先・フィールドの型・引数の型・`==` `!=` の反対側の型から決まるときだけ書ける。決まらないときは、エラー（`cannot_infer_type`）。
- リテラルの要素のキーどうし・値どうしの型は、そろっていなければならない（`type_mismatch`）。同じキーを 2 度書いたときは、あとの値が、最初の位置の値を更新する。
- `m[k]` は、キー `k` の値を読む。無ければ、実行時エラー（`KeyNotFound`。引数 `key` は、キーの `${}` での文字列）。
- `m.len()`（`int`）・`m.is_empty()`（`bool`）・`m.has(k)`（`bool`）・`m.get(k)`（`Option<V>`。無ければ `None`）・`m.keys()`（`list<K>`）・`m.values()`（`list<V>`）は、式の中で使える。`keys` と `values` は、挿入順で、コピーを返す。`remove(k)`・`clear()` は文（3.3）。`xs.is_empty()`（`list`）も使える。

- リストのリテラルは `[a, b]`。要素の型はそろっていなければならない（`type_mismatch`）。`xs[i]` は、`i` 番目（0 から）の要素。範囲外は、実行時エラー（`IndexOutOfRange`。引数 `index`・`len`）。
- `xs.len()`（`int`）と `xs.contains(x)`（`bool`）は、式の中で使える。関数を受け取るメソッド（`map`・`filter`・`any`・`all`・`find`・`count`・`fold`・`sort_by`・`min_by`・`max_by`）と、並べ替え・集計のメソッド（`sort`・`reverse`・`sum`）も、式の中で使える（3.5）。`push`・`insert`・`remove`・`clear`・`shuffle` は、式の中では使えない（`statement_method_in_expression`。3.3）。型に無いメソッドは、`unknown_method`。`str` には、メソッドがない。文字列の操作（長さ・切り出し・検索・変換など）は、`text` パッケージ（packages/text.md）のコマンドで行う。
- `Some(x)` と `None` は、`Option<T>` の値。
- `s.f` は、`struct` のフィールドの読み出し。無いフィールドは、`unknown_field`。struct のリテラルは、3.7。
- `enum` の値は `型名.バリアント`（引数があれば `型名.バリアント(式, …)`）。ほかのモジュールの型は `モジュール名.型名.バリアント`。無いバリアントは、`unknown_variant`。`a.b` は、`a` が変数ならフィールド、同じモジュールの型の名前なら enum のバリアント、そうでなければモジュール（パッケージ）の名前として読む。
- `${式}` に埋め込む複合値の文字列は、決まった書き方になる。`list` は `[a, b]`、`Option` は `Some(x)` と `None`、`struct` は `Chara { name: 案内人, hp: 10 }`（フィールドは宣言の順）、`enum` は `Dir.North`・`Dir.Item(1, a)`、`map` は `map { a: 1, b: 2 }`（挿入順。空は `map {}`）、`Identity` は表示名（`name`）、関数の値は `<fn>`。要素の文字列は、`${}` に埋め込む書き方のまま（`str` に引用符は付かない）。

### 優先順位と結合

高いほうから。Rust の順序に合わせる。

| 順 | 演算子 | 結合 |
| --- | --- | --- |
| 1 | 呼び出し `f(x)`、フィールド `.`、添字 `[ ]` | 左 |
| 2 | 単項 `-` `!` | 右 |
| 3 | `*` `/` `%` | 左 |
| 4 | `+` `-` | 左 |
| 5 | `<` `<=` `>` `>=` | なし |
| 6 | `==` `!=` | なし |
| 7 | `&&` | 左 |
| 8 | `\|\|` | 左 |

- 「結合なし」の演算子は、並べて書けない（`a < b < c` はエラー）。
- ラムダ式の本体は、続くかぎりの式である（`|x| x + 1 > 2` の本体は `x + 1 > 2`）。式の途中に書くときは、`( )` で囲むか、呼び出しの引数に書く。
- 代入（`=` `+=` など）は、式ではなく文である（3.3）。
- `&&` と `||` は、左から評価し、結果が決まったら右を評価しない。
- 整数のオーバーフローと、0 での割り算（`/` `%`）は、実行時エラー。
- 浮動小数の演算の結果が `NaN` か `±∞` になるとき（0.0 での割り算を含む）は、実行時エラー。0.0 での割り算は 0 での割り算（`DivisionByZero`）、それ以外は `NonFiniteFloat`。結果の `-0.0` は `0.0` にする（単項の `-` の結果を含む）。
- `+` `-` `*` `/` と、単項の `-` は、`int` と `float` に使える。二項演算の両辺は、同じ型でなければならない。`%` は `int` だけに使える（`float` の `%` は持たない）。使えない型への演算は、エラー（`invalid_operation`。引数 `op`・`type`）。複合代入（`+=` など）も同じ（`str += "a"` はエラー）。
- `${式}` に埋め込む値の文字列は、`int` は 10 進数、`bool` は `true` / `false`、`str` はそのまま、`float` は、元の値に戻る最短の 10 進表記（`0.30000000000000004`・`2.5`・`0.000001`）。指数表記は使わず、整数値には `.0` を付ける（`3.0`）。
- `int` どうしの `/` は、0 に向かって切り捨てる。`%` の結果は、被除数の符号に従う（`-7 / 2 = -3`、`-7 % 3 = -1`）。`a == (a / b) * b + a % b` が成り立つ。
- `<` `<=` `>` `>=` は、`int` と `float` だけに使える。`str` と `bool` は、`==` と `!=` だけ（同じ型どうし）。
- `str` の `+` は持たない。文字列の連結は `${式}` で行う（`"a" + "b"` は `invalid_operation`）。
- 副作用のない問い合わせコマンドは、式の中で、`@` を付けずに呼べる（例：`sprite.shown("案内人")`）。`@` は、文として呼ぶときだけ付ける（2.2、3.3）。

## 3.3 文

```ebnf
block        = "{" { statement } "}" ;
statement    = let_stmt | assign_stmt | if_stmt | while_stmt | for_stmt
             | match_stmt | "break" | "continue" | return_stmt
             | call_stmt
             | jump_stmt | label_call_stmt | end_stmt ;    (* 後ろの 3 つは 4 章 *)

call_stmt    = "@" call_target call_args [ stable_id ] ;   (* 戻り値は捨てる。2.2 *)
call_target  = identifier { "." identifier } ;

let_stmt     = "let" identifier [ ":" type ] "=" ( expression | call_stmt ) ;   (* call_stmt は戻り値を受ける。2.2a *)
method_stmt  = target "." ( "push" "(" expression ")"
                          | "insert" "(" expression "," expression ")"
                          | "remove" "(" expression ")" | "clear" "(" ")" ) ;
assign_stmt  = target assign_op expression
             | target "=" call_stmt ;                        (* 戻り値を受ける。`=` だけ。2.2a *)
target       = identifier { "." identifier | "[" expression "]" } ;
assign_op    = "=" | "+=" | "-=" | "*=" | "/=" | "%=" ;

if_stmt      = "if" expression block [ "else" ( if_stmt | block ) ] ;
while_stmt   = "while" expression block ;
for_stmt     = "for" loop_vars "in" expression block
             | postfix "." "each" "{" loop_vars "=>" { statement } "}" ;   (* each。`for` の糖衣 *)
loop_vars    = identifier [ "," identifier ] ;
return_stmt  = "return" [ expression ] ;
```

- 条件式は `bool` でなければならない（他の型からの暗黙の変換はしない）。
- `let` で宣言した変数は、同じブロックの中で使える。型注釈は省略でき、右辺から推論する。
- 変数は、宣言したあと、代入で更新できる。
- `for x in 式 { … }` は、`list<T>` の要素を、先頭から順に `x`（`T` 型）に入れて、本体を繰り返す。回すのは、ループを始めたときの**コピー**で、本体で元のリストを変えても、回数と要素は変わらない。`x` は本体の中のローカル変数で、本体の外からは見えない。式が `list` でなければ、`type_mismatch`。`map` は、変数 1 つでは回せない（`type_mismatch`）。`break`・`continue`・`return` は、`while` と同じ。ループの途中でもセーブ・ロードでき、続きから回る（host/04-save.md の 4.6）。
- `for i, x in 式 { … }` は、`list<T>` を、添字 `i`（`int`。0 から）と要素 `x`（`T`）で回す。`for k, v in 式 { … }` は、`map<K, V>` を、挿入順に、キー `k`（`K`）と値 `v`（`V`）で回す。どちらも、回すのはループを始めたときのコピーで、変数 1 つの `for` と同じ規則に従う（本体での変更は反復に影響しない、セーブ・ロードできる）。2 つの名前が同じなら、`duplicate_name`。`list`・`map` 以外なら、`type_mismatch`。
- ループの変数（`for` と `each`。変数 1 つでも 2 つでも）の名前 `_` は、**捨てる名前**で、値を受け取らない。何度書いてもよく（`for _, _ in m`）、本体からは参照できない（`unknown_name`）。キーだけを回すときは `for k, _ in m`、値だけなら `for _, v in m` と書く（`m.keys()` と違い、一覧を作らない）。
- `for i in range(a, b) { … }`（変数 1 つ）は、列を作らずに、`a` から `b - 1` までの整数を順に `i` に入れる。`a`・`b` は、ループを始める前に 1 度だけ、書いた順に評価する。列を作らないので、列の大きさの検査（`max_value_bytes`）は行わない（繰り返しの回数は、命令数の上限 `max_steps_per_run` で抑えられる）。
- `式.each { x => … }` は、`for x in 式 { … }` と同じ（`for` の糖衣）。`式.each { k, v => … }` は、`for k, v in 式 { … }` と同じ。`{ x =>` で行を終え、本体を次の行から書く。本体には、`for` の本体と同じく、素の行・引用行・`choice` などの停止点を書ける（ラムダ式ではないので、3.5 の制限を受けない）。`each` は、この位置でだけ意味を持つ語で、予約語ではない（1.6）。
- `while` は、条件を評価し、真のあいだ、本体を繰り返す。条件は、繰り返しのたびに評価する（最初から偽なら、本体は 1 度も実行しない）。本体の `let` は、1 回の繰り返しの中のローカル変数で、本体の外からは見えない。
- `break` は、一番内側のループを抜ける。`continue` は、一番内側のループの条件の評価（`for` では次の要素）へ戻る。`break` / `continue` は、`while` と `for` の中だけで使える。ループの外ではエラー（`outside_loop`。引数 `what`）。ループの中の `jump` は、ループを抜けて、別のラベルへ移る。
- 1 回の `run` で実行できる命令の数には、上限がある（`while` の繰り返しも数える。host/01-execution.md の 1.9）。終わらないループは、実行時エラー（`StepLimitExceeded`）で止まる。
- `return` は、`fn` と、ラベルの中で使える（3.5、4.5）。
- 代入文は、行頭が識別子 + 代入演算子の行になる（2.6）。左辺（`target`）は、変数・フィールド・添字を連ねた場所（`xs[1]`・`c.hp`・`p.members[0].hp`）。複合代入（`+=` など）も同じ。場所の型に合った演算だけができる。
- **map の更新**：`m[k] = v` は、キーが無ければ末尾に足し、あれば位置を変えずに値を替える。`m[k] += v` などの複合代入と、`m[k].f = v` のような入れ子の更新は、キーが無ければ実行時エラー（`KeyNotFound`）。`m.remove(k)` はキーを取り除く（無いキーは何もしない）。`m.clear()` は空にする。
- **リストを更新するメソッド**：`push(x)`（末尾に足す）・`insert(i, x)`（`i` 番目に差し込み、元の `i` 番目以降を 1 つ後ろへずらす。`0 <= i <= len` で、`i == len` は `push` と同じ。範囲外は `IndexOutOfRange`）・`remove(i)`（`i` 番目を取り除き、後ろを詰める。範囲外は `IndexOutOfRange`）・`clear()`（空にする）・`shuffle()`（要素を、コアの乱数で並べ替える。Fisher–Yates：後ろの位置 `i` から順に、`random(0, i)` の位置と入れ替える）は、文として、行頭の `変数.メソッド(…)` の形で書く（`@` は付けない。戻り値は無い）。代入できる場所（変数・フィールド・添字）にだけ使える。`insert` の引数は、`int` と要素の型（違うと `type_mismatch`）。差し込んだあとの値の大きさは、`push` と同じに検査する（`ValueTooLarge`、合計メモリの上限）。この 5 つの名前以外の `識別子.名前(…)` で始まる行は、素の行のまま。
- `let` で、コマンドの戻り値として `list`・`map`・`Option`・`Identity` を受けられる（2.2a）。
- `let` と `=` の右辺は、式のほかに、全体が `@` の呼び出し（`call_stmt`）であるものを書ける。コマンドの戻り値を受ける（2.2a）。式の途中の `@` は、`invalid_command_use`。
- 式だけの文は、`@` を付けた呼び出し（`call_stmt`）だけである。呼び出し以外の式（例：`1 + 2`）は、文として書けない。`{ }` の中でも同じ。

## 3.4 変数の宣言

```ebnf
save_decl       = "save" "var" identifier ":" type "=" expression ;
persistent_decl = "persistent" "var" identifier ":" type "=" expression ;
```

- ホストが宣言した変数も、同じ種類（セーブ・永続）を持つ（host/02-registry.md の 2.7）。
- `save var` と `persistent var` は、モジュールの最上位にだけ書ける。型注釈と初期値が必須。初期値は、定数（リテラル）である（`not_constant`）。ラベルの中に書くと、エラー（`declaration_not_allowed`）。
- `save var` の値は、セーブに入り、ロールバックで元に戻る。`persistent var` の値は、**永続データ**に入り（host/04-save.md の 4.5）、セーブには入らず、ロールバックでも元に戻らない。台本からは、どちらも同じように読み書きできる（モジュールの外からは、`モジュール名.変数名`）。
- `save var` と `persistent var` は、同じ名前の表に入る。同じモジュールの中で、同じ名前を二度宣言するとエラー（`duplicate_name`。種類が違っても同じ）。ラベルの名前・`let` の名前とも、重ならない。
- **同名の宣言**：`let` で宣言する名前が、見えている `let` の変数・モジュール変数（`save var`）と同じときは、エラー（`duplicate_name`）。ラベルの名前と同じでも、エラーにしない。
- ラベルの中の `let` は、ローカル変数である。`jump` で破棄される（4 章）。

## 3.5 関数

```ebnf
fn_decl = "fn" identifier "(" [ param { "," param } ] ")" [ "->" type ] block ;
param   = identifier ":" type [ "=" expression ] ;   (* 既定値。定数だけ *)
```

- `fn` は、モジュールの最上位にだけ宣言できる（ラベルの中に書くと `declaration_not_allowed`）。引数と戻り値の型注釈は必須（戻り値がなければ省略。引数がなくても `( )` は要る）。名前は、同じモジュールの変数・ラベル・identity・型・ほかの `fn`・直接登録したコマンドと重ならない（`duplicate_name`）。宣言の順は問わず、前からも後ろからも呼べる。
- **呼び出し**：式の中で `名前(式, …)` と書く（`let y = double(x)`・`"${double(x)}"`・条件式・引数・`match` の対象など）。ほかのモジュールの `fn` は `モジュール名.名前(…)`（`import` の規則は、変数・ラベルと同じ。4.2）。`@名前(…)`（`@モジュール名.名前(…)`）の形でも呼べる。文として書けば戻り値を捨て、`let`・`=` の右辺に書けば戻り値を受ける（2.2）。戻り値のない `fn` の値を受けるとエラー（`call_without_value`）。安定 ID は付けられない（`invalid_stable_id`）。宣言されていない `fn` は `unknown_function`（近い名前があれば `suggestions`。3.8、6.4）。
- **本体に書けるもの**は、計算のための文だけ：`let`・代入・`if`・`while`・`for`・`match`・`break`・`continue`・`return`・変数を更新するメソッドの文（`xs.push(x)` など）・`fn` の呼び出し。書けない文は、コンパイルエラー（`not_allowed_in_fn`。引数 `what` は、`plain`（素の行）・`quote`（引用行）・`choice`・`jump`・`call`・`end`、副作用型・停止型のコマンドは `@` を付けた名前）。副作用のない問い合わせコマンドと組み込み関数（`random`・`random_float`・`seen`・`visited` を含む）は、式の中で呼べる。`random` は PRNG の状態を進めるが、その状態は、いつもの `random` と同じく、セーブ・ロールバックの対象であり、決定的に同じ列を返すので、`fn` の中で呼んでよい。
- **変数の見え方**：`fn` の中から、モジュール変数（`save var`・`persistent var`）とホスト宣言の変数を**読める**。**書けない**（代入・複合代入・フィールド・添字・`push` などの更新。エラー `assign_in_fn`。引数 `name` は書かれた変数の名前）。書けるのは、`fn` 自身のローカル変数と引数だけ。呼び出し元のローカル変数は見えない（`unknown_name`）。
- **引数**は値で渡す（3.1 の値セマンティクス）。`fn` の中で引数へ代入しても、更新するのは `fn` の中の引数だけで、呼び出し元に影響しない。
- **戻り値**：戻り値の型があれば、すべての経路で `return` で値を返さなければならない（末尾に達しうると `missing_return`。引数 `name`。末尾に達しうるかの判定は 4.5 と同じ）。`return` の値の型は `type_mismatch`、値のない `return` は `missing_return_value`、戻り値のない `fn` の値つき `return` は `unexpected_return_value`（4.5）。`return` のあとの、到達しない文は、診断にしない。
- **再帰**（相互再帰を含む）を許す。呼び出しの深さは、ラベルの `call` と合わせて数え、`max_call_depth`（既定 256。host/01-execution.md の 1.9）を超えると、実行時エラー（`CallDepthExceeded`）。`fn` の中の命令も、命令数の上限（`max_steps_per_run`）に数える。`fn` の中のローカル変数も、変数の大きさの合計の上限（`max_total_bytes`）に数える。
- `fn` の呼び出しは、1 回の `run` の中で終わる（停止点を持てない）。そのため、`fn` の呼び出しの途中の状態（フレーム・ローカル変数）は、セーブ・スナップショットに入らない。`fn` の宣言や本体を変えても、セーブの位置の解決（安定 ID・ハッシュ・序数。host/04-save.md の 4.4）には影響しない。停止点の引数や本文の `${}` の中の `fn` の呼び出しは、ロードで引数を作り直すときに、いまの台本の `fn` で再び呼ばれる。

### 関数の値とラムダ式

- **関数の値**：`fn` の名前を、`(` を付けずに書くと、その `fn` を指す関数の値になる（`apply(double, 3)`。ほかのモジュールの `fn` は `モジュール名.名前`）。型は `fn(引数の型, …) -> 戻り値の型`。既定値と名前つきの引数は、関数の値を通しては使えない（すべての引数を、順に渡す）。戻り値のない `fn` は、値にできない（`call_without_value`）。
- **ラムダ式**：`|x, y| 式`（引数なしは `|| 式`）は、本体の式の値を返す関数の値である。本体は、式 1 つだけ（文を書くときは、`fn` を宣言する）。引数の型は、注釈（`|x: int| x * 2`）か、渡す先の型（関数の型の変数・引数、3.2 のメソッドの引数）から決まる。決まらないときは、`cannot_infer_type`。本体の型が、渡す先の戻り値の型と違えば、`type_mismatch`。引数の数が違えば、`arg_count`。
- **捕捉**：ラムダ式の本体は、外側のローカル変数（ラベルの `let`・引数、`fn` の引数とローカル変数、外側のラムダ式の引数）を使える。使った変数の値は、ラムダ式を評価したときに**写す**（値渡し）。そのあと外側の変数を変えても、関数の値は変わらない。本体から外側の変数へは書けない。モジュール変数とホスト宣言の変数は、`fn` と同じく、呼ばれたときの値を読む。自分自身を名前で呼ぶことはできない（再帰には、`fn` を使う）。
- **ラムダ式の本体の制限**：本体は `fn` の本体と同じく、停止しない（停止点・`call`・コマンドの文を書けない）。本体の中の実行時エラーは、`<lambda>` という名前の `fn` の中のものとして報告する。
- **呼び出し**：関数の型の変数は、`名前(式, …)` で呼べる。同じモジュールに同じ名前の `fn` があれば、`fn` を呼ぶ（3.8）。式の結果を直接呼ぶ書き方（`fs[0](1)`・`(f)(1)`）は持たない（`not_yet_supported`）。呼び出しの深さ・命令数・合計メモリの上限は、`fn` と同じに数える。
- **list のメソッド**：`xs` が `list<T>` のとき、次のメソッドを式の中で使える。関数は、要素を先頭から順に受け取る。`map` と `filter` は、新しい `list` を返す（元は変わらない）。

| メソッド | 関数の型 | 戻り値 | 意味 |
| --- | --- | --- | --- |
| `xs.map(f)` | `fn(T) -> U` | `list<U>` | 各要素に `f` を適用した列 |
| `xs.filter(f)` | `fn(T) -> bool` | `list<T>` | `f` が真の要素だけの列 |
| `xs.any(f)` | `fn(T) -> bool` | `bool` | `f` が真の要素があるか（見つかったら、残りを調べない。空なら偽） |
| `xs.all(f)` | `fn(T) -> bool` | `bool` | すべての要素で `f` が真か（偽が見つかったら、残りを調べない。空なら真） |
| `xs.find(f)` | `fn(T) -> bool` | `Option<T>` | `f` が真の最初の要素 |
| `xs.count(f)` | `fn(T) -> bool` | `int` | `f` が真の要素の数 |
| `xs.fold(init, f)` | `fn(A, T) -> A` | `A` | `init` から始めて、`f(途中の値, 要素)` を順に適用した値（`A` は `init` の型） |
| `xs.sort_by(f)` | `fn(T) -> K` | `list<T>` | `f` が返すキーの昇順に並べた列（安定。キーが等しい要素は元の順） |
| `xs.min_by(f)` | `fn(T) -> K` | `Option<T>` | キーが最小の要素（等しいときは先頭に近いほう。空なら `None`） |
| `xs.max_by(f)` | `fn(T) -> K` | `Option<T>` | キーが最大の要素（等しいときは先頭に近いほう。空なら `None`） |

- **並べ替え・集計のメソッド**（関数を取らない）：`xs.sort()`（`list<T>`。要素の昇順。安定）・`xs.reverse()`（`list<T>`。逆順）・`xs.sum()`（要素が `int` なら `int`、`float` なら `float`。空なら `0`・`0.0`）。
- **キーと要素の型**：`sort_by`・`min_by`・`max_by` のキー `K`（と、`sort` の要素 `T`）は、`int`・`float`・`str`・`bool` のどれか。`int`・`float` は数の大きさ、`str` は文字コード（Unicode スカラ値）の順、`bool` は `false` が先。ほかの型（`list`・`struct` など）は `unsupported_element_type`（引数 `method`・`type`）。`sum` は `int`・`float` の列だけ（ほかは同じ診断）。降順にするときは `reverse` を続ける（`xs.sort_by(f).reverse()`。キーが等しい要素の順も逆になる）。
- **元は変わらない**：`sort_by`・`sort`・`reverse` は、新しい `list` を返し、元の列は変えない（その場で並べ替えるメソッドはない。`xs = xs.sort()` と書く）。`sum` の途中の値が `int` の範囲を超えると `integer_overflow`、`float` が有限でなくなると `non_finite_float`（実行時エラー。`+` と同じ）。キー関数は、要素ごとに先頭から 1 回ずつ呼ぶ（`min_by`・`max_by` も、すべての要素を呼ぶ）。

- **セーブとの関係**：関数の値は、セーブに入れられない。次の場所に、関数の型（それを含む型）を置くとエラー（`fn_not_saveable`。引数 `type`・`what`）：`save var`・`persistent var`（`what` は `var`）、`struct` のフィールドと `enum` の引数（`field`）、REPL の最上位の `let`（`repl`。host/07-repl.md）。ラベルのローカル変数（`let`・引数・`for` の変数・`match` の束縛）には置けるが、停止点（素の行・引用行・`choice`・停止型のコマンド。`what` は `stop`）か `call`（`call`）のあとで、その変数を使うとエラー。ただし、停止点のあとで、変数に値ごと代入し直して（`f = …`）から使うのは、エラーにしない。代入は、使う場所と同じブロックか、それを囲むブロックに書く（`if` の中だけで代入し直したものは、代入を通らない経路があるので、エラー）。`push` などの更新や、フィールド・添字への代入は、前の値を使うので、使ったものとみなす。停止点を含むループの中で、ループの外で宣言した関数の型の変数を、同じ繰り返しの中で代入し直さずに使うのも、エラー（次の繰り返しで、停止点のあとに使われる）。関数の値の `list` を `for` で回すループの中には、停止点を書けない。停止点の時点で使い終わっている関数の型の変数は、セーブには値を入れず、ロードで既定の値になる（使われないので、影響しない）。変数の一覧（host/01-execution.md）にも出さない。

### 既定値と名前つきの引数

- **既定値**：引数に `= 式` を付けると、呼び出しで省いたときの値になる（`fn give(item: str, count: int = 1)`）。式は定数（3.4 の `save var` の初期値と同じ）だけで、型は引数の型に合わなければならない（`type_mismatch`。定数でなければ `not_constant`）。既定値のある引数のあとに、既定値のない引数は書けない（`required_after_default`。引数 `name`・`arg`）。
- **名前つきの引数**：呼び出しで `名前: 式` と書くと、その名前の引数に渡す（`give("薬草", count: 3)`）。位置で渡す引数を先に、名前つきの引数をあとに書く。名前つきの引数は、宣言の順に並べる（途中を飛ばしてよい）。
- 誤りは、次の診断になる（引数 `name` は呼び出し先、`arg` は引数の名前）：ない名前（`unknown_argument`）、同じ引数を 2 度（`duplicate_argument`）、宣言の順でない（`argument_out_of_order`）、名前つきのあとに位置の引数（`positional_after_named`）、既定値のない引数を省いた（`missing_argument`）。省いた引数がなく、名前つきの引数もない呼び出しで、数が合わなければ、これまでどおり `arg_count`。
- 使える呼び出しは、`fn`、引数を持つラベルの `call`（4.5）、ホストのコマンド（`@` の副作用型・停止型と、式の中の問い合わせ型。既定値と引数の名前は、登録で付ける。host/02-registry.md）。組み込み関数（3.8）・メソッド・糖衣構文には、名前つきの引数を渡せない（`unknown_argument`）。
- 省いた引数は、呼び出しのときに既定値で埋めてから渡す。呼ばれる側から見ると、すべての引数が渡されたのと同じ。

## 3.6 match

```ebnf
match_stmt = "match" expression "{" { match_arm } "}" ;
match_arm  = pattern "=>" ( block | statement ) [ "," ] ;
pattern    = "_" | int_literal | string_literal | bool_literal
           | "Some" "(" ( identifier | "_" ) ")" | "None"
           | identifier [ "(" ( identifier | "_" ) { "," ( identifier | "_" ) } ")" ] ;   (* enum のバリアント *)
```

- `match` は文である。対象の式を評価し、上から順に、合う最初のアームの本体を実行する。ほかのアームは実行しない。アームの本体は、ブロックか、1 つの文（行末の `,` は省ける）。
- パターンは、`_`（なんでも合う）・`int`/`str`/`bool` のリテラル・`Some(名前)`・`None`・enum のバリアント（バリアントの名前だけを書く。型名は付けない）。浮動小数のリテラルは、パターンにできない。パターンの型は、対象の型と同じでなければならない（`type_mismatch`）。
- `Some(名前)` とバリアントの `(名前, …)` は、中身を名前に束縛する。束縛の個数は、バリアントの引数の数と同じ。`_` は束縛しない。束縛した名前は、そのアームの本体の中だけで使え、ほかの変数と同じ名前（`duplicate_name`）になってはならない。
- **網羅性の検査**：対象の型のすべての値が、どれかのアームに合わなければならない。足りないとき、`match` の位置でエラー（`non_exhaustive_match`。引数 `missing` に、足りないパターンの一覧）。`_` があれば網羅している。`bool` は `true` と `false` の両方、`Option` は `Some` と `None` の両方、enum はすべてのバリアントが現れれば網羅している。`int` と `str` は、`_` が必要。
- **到達しないアーム**：前のアームですべて合っている（`_` の後ろ・網羅した後ろ・同じパターンの繰り返し）アームは、警告（`unreachable_pattern`）。コンパイルは通る。1 つのアームには、警告 1 つ。
- 入れ子のパターン（`Some(Some(x))` など）は、持たない。

## 3.7 enum と struct

```ebnf
enum_decl   = "enum" identifier "{" variant { "," variant } [ "," ] "}" ;
variant     = identifier [ "(" type { "," type } ")" ] ;
struct_decl = "struct" identifier "{" field { "," field } [ "," ] "}" ;
field       = identifier ":" type ;
```

- `enum` と `struct` の宣言は、モジュールの最上位にだけ書ける。宣言は、`{ }` の中で複数の行にまたがってよい。型は、宣言より前でも後ろでも使える。ラベルの中に書くと、`declaration_not_allowed`。
- 同じ名前の型は、同じモジュールの中に 2 つ宣言できない（`duplicate_name`）。`struct` の中のフィールドの名前、`enum` の中のバリアントの名前も、重ならない。
- 型は、自分自身を含められない（3.1）。
- ほかのモジュールの型は、`モジュール名.型名` と書いて使う（型注釈・struct のリテラル・enum の値）。

### struct の値

```ebnf
struct_literal = identifier "{" [ field_init { "," field_init } [ "," ] ] "}" ;
field_init     = identifier ":" expression ;
```

- struct の値は、型名の後ろに `{ フィールド: 値 }` を書いて作る（例：`Chara { name: "案内人", hp: 10 }`）。すべてのフィールドを、宣言と同じ型で与えなければならない。順序は問わない。足りないフィールドは `missing_field`、同じフィールドの繰り返しは `duplicate_field`、無いフィールドは `unknown_field`。リテラルは、1 行に書く。フィールドの値の式は、書いた順に評価する。
- `if` `while` `for` `match` の条件・対象の式の中では、struct のリテラルをそのまま書けない（直後の `{` がブロックと紛らわしいため）。書くときは `( )` で囲む。
- フィールドの更新は、代入文で書く（例：`c.hp -= 1`、`c.items.push("薬")`）。値セマンティクスなので、他の変数にコピーした値には影響しない。

### enum の値

- `enum` の値は、`型名.バリアント` か `型名.バリアント(引数, …)` で作る（3.2）。引数の個数と型は、宣言と同じ。引数のないバリアントに `( )` は付けない。
- バリアントの中身の取り出しは、`match`（3.6）で行う。

### 値の大きさ

- `list`・`map`・`struct`・`enum` の値の大きさ（入れ子の中身を含む）は、`max_value_bytes`（host/01-execution.md の 1.9）で数える。超えるときは、実行時エラー（`ValueTooLarge`）。

## 3.8 組み込み関数

コアは、台本から呼べる、組み込み関数を持つ。`@` を付けずに、式の中で呼ぶ。

| 関数 | 戻り値 | 意味 |
| --- | --- | --- |
| `random(最小: int, 最大: int)` | `int` | 最小以上、最大以下の整数を返す（両端を含む） |
| `random_float()` | `float` | `0.0` 以上 `1.0` 未満の小数を返す |
| `seen(位置: str)` | `bool` | 通過済みの停止点か（5.7） |
| `visited(ラベル: str)` | `bool` | そのラベルに入ったことがあるか（5.7） |
| `to_int(x: float)` | `int` | 0 に向かって切り捨てる。範囲外は実行時エラー |
| `to_float(x: int)` | `float` | 最も近い `float` に丸める |
| `range(a: int, b: int)` | `list<int>` | `a` 以上 `b` 未満の整数の列（`a >= b` なら空）。`for i in range(0, n)` で使う（`for` の変数 1 つで回すときは、列を作らない。3.3）。列を作る前に、大きさを `max_value_bytes` で検査する |

- `random`・`random_float` と、リストのメソッド `shuffle()`（3.3）は、コアの PRNG を使う。PRNG の状態は、セーブに含め、ロールバックで元に戻る（host/04-save.md の 4.3）。`random_float` は、乱数の上位 53 ビットを、`2^-53` 倍した値を返す。
- `random` の `最小 > 最大` は、実行時エラー（`InvalidRandomRange`）。`最小 == 最大` は、その値を返す。`random` は、式の中で呼ぶ（`let n = random(1, 6)`、`"${random(1, 6)}"`）。
- PRNG は、xoshiro256++（状態は `u64` が 4 つ）で、種（`VmConfig::seed`）から、splitmix64 で状態を作る。範囲の整数への割り当ては、Lemire の方法（乱数の上位 64 ビットと範囲の幅の積を使い、偏りが出る下位は、棄却して引き直す）で行う。環境によらず、同じ値を返す。アルゴリズムと割り当て方を変えるときは、セーブの形式の版数を上げる。
- 停止点の引数の中で乱数を引いてもよい。セーブは、引数を求め始めたときの乱数の状態を持ち、ロードで引数を作り直すと、保存したときと同じ値になる（host/04-save.md の 4.3）。
- 組み込み関数と同じ名前の、変数・`fn`・コマンドは、宣言できる。宣言したほうが、組み込み関数より優先する（影にする）。変数か `fn` を宣言して影にしたときは、警告（`shadowed_builtin`。引数 `name`）を出す。この警告は、この表のすべての名前にかかる。同じモジュールの `fn` と同じ名前のローカル変数があっても、`名前(…)` の呼び出しは `fn` を呼ぶ（変数は、`(` なしで書く）。関数の型の変数は、`名前(…)` で呼べる（3.5）。
- 呼び出しは、名前の直後に `(` を書く（`to_int(x)`。`to_int (x)` ではない）。引数の数と型は、静的に検査する。未宣言の関数の名前は、`unknown_function`（近い綴りの候補は、組み込み関数と、同じモジュールの `fn` の名前から選ぶ。3.5、6.4）。
- `to_int(x)` は、`x` を 0 に向かって切り捨てる（`to_int(-2.9)` は `-2`）。`-9223372036854775808.0` 以上 `9223372036854775808.0` 未満でなければ、実行時エラー（`FloatOutOfRange`）。`to_float(n)` は、IEEE 754 の最も近い値（同じ近さなら偶数）に丸める。

## 3.9 式の標準書式

式を、構文木から、決まった 1 つの文字列に直す書き方を、標準書式という。位置のハッシュ（host/04-save.md の 4.4）の入力に使う。ソースの書き方の違い（空白・冗長な括弧・整数の桁区切りや先頭の `0`・末尾の `,`）は、標準書式では、なくなる。

- 標準書式は、構文だけで決まる。型や名前の解決の結果には、よらない。
- 1 行で、改行を含まない。空白は、半角スペース（`U+0020`）だけである。ソースで複数の行に書いた式（2.8）も、1 行の書式に直す。最後の `,` は、入れない。
- 構文木の形（演算の順序・フィールドの書いた順・引数の順）は、変えない。
- コードの整形（`yomi fmt`）も、式にこの書式を使う。冗長な括弧は、整形で消える（下の「括弧」）。

| 構文 | 標準書式 |
| --- | --- |
| 二項演算子（`\|\|` `&&` `==` `!=` `<` `<=` `>` `>=` `+` `-` `*` `/` `%`） | `左 演算子 右`（演算子の前後に半角スペース 1 つ） |
| 単項演算子（`-` `!`） | `-x`・`!x`（空白なし。`--x`・`!!x` のように重ねても空白は入れない） |
| 呼び出し・名前つきの引数 | `f(a, b)`・`f(x: 1, y: 2)`・`a.b(c)`（名前と `(` の間に空白なし。`,` の前に空白なし、後ろに半角スペース 1 つ。`名前:` の後ろに半角スペース 1 つ） |
| フィールド・添字 | `a.b`・`a[i]`（空白なし） |
| `Some`・`None` | `Some(x)`・`None` |
| list のリテラル | `[a, b]`・`[]` |
| map のリテラル | `map { k: v, k2: v2 }`・`map {}`（末尾の `,` は付けない） |
| struct のリテラル | `型名 { フィールド: 値, … }`（書いた順。フィールドが 0 個のときは `型名 {}`） |
| ラムダ式 | `\|x, y\| 本体`・`\|x: int\| 本体`・`\|\| 本体`（`\|` の内側に空白なし、閉じる `\|` の後ろに半角スペース 1 つ） |
| 整数のリテラル | 10 進数。桁区切りの `_` と先頭の `0` を除く（`1_000` は `1000`、`007` は `7`、`0` は `0`） |
| 浮動小数のリテラル | 元の値に戻る最短の 10 進表記。指数表記は使わず、整数値には `.0` を付ける（`1.50` は `1.5`、`3.0` は `3.0`。3.2 の `${}` の規則と同じ） |
| 真偽のリテラル | `true`・`false` |
| 文字列のリテラル | `"…"`。引用符の中の文字は、書かれたまま（エスケープも書かれたまま）。`${式}` の中の式は、標準書式に直し、`${` と `}` の内側に空白を入れない |
| 識別子・名前 | NFC に直した名前（1.5）。`a.b.c` のように `.` でつなぐ名前も同じ |

### 括弧

ソースの `( )` は、構文木に残らない。標準書式は、構文木の優先順位と結合（3.2）で必要な場合にだけ、`( )` を付ける。

- 二項演算子の項が、その演算子より優先順位の低い演算（または、ラムダ式）のときは、`( )` で囲む。
- 左結合の演算子（`||` `&&` `+` `-` `*` `/` `%`）で、**右**の項が同じ優先順位の演算のときも、`( )` で囲む（`a - (b - c)`。左の項は囲まない）。
- 比べる演算子（`==` `!=` と、`<` `<=` `>` `>=`）は、結合しない。項が同じ優先順位の演算（`==` の項が `==` など）のときは、`( )` で囲む。
- 単項演算子の対象が、二項演算か、ラムダ式のときは、`( )` で囲む（`-(a + b)`・`!(a && b)`）。
- 後置（`.`・`( )`・`[ ]`）の対象が、二項演算・単項演算・ラムダ式のときは、`( )` で囲む（`(a + b).len()`・`(-x).f`）。
- ラムダ式は、式の全体・呼び出しの引数・list や map の要素・struct のフィールドの値・`Some( )` の引数・別のラムダ式の本体・`${ }` の中の式の位置では、`( )` で囲まない。演算子の項・後置の対象の位置では、囲む（3.5。本体は続くかぎりの式のため）。
