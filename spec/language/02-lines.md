# 2. 行の分類

台本は行を単位とする。パーサは、各行を次の順に判定し、最初に当てはまったものに分類する。判定に使う字句は [1 章](01-lexical.md) による。

## 2.1 判定の順序

| 順 | 条件 | 分類 |
| --- | --- | --- |
| ① | 空行、または行頭（空白を除く）が `//` | 無視する |
| ② | 行頭が `@` | コマンド行 |
| ③ | 行頭が予約語、または `}`、または代入文の始まり（2.6） | 文の行 |
| ④ | 行頭が、使える identity の名前（2.3）で、そのすぐ後ろが `「` | identity つきの引用行 |
| ⑤ | 行頭が `「` で、対応する `」` で行が終わる | identity なしの引用行 |
| ⑥ | それ以外 | 素の行 |

- 「行頭」は、インデントの空白を除いた最初の文字をいう。
- ①の「空行」は、半角スペースとタブだけの行（と、長さ 0 の行）をいう。全角スペースだけの行は、本文の一部（字下げ。1.5）として、素の行になる（停止点になる）。
- ④の「すぐ後ろ」には、空白を挟まない。
- 行頭が `\` の行は、1.10 の規則による。
- 式の中の括弧を開いたまま終わる行の次の行は、分類せず、続きとして読む（2.8）。
- `choice { }` の中の行は、この表ではなく、選択肢の文法で読む（`「文」 #id => 文`。5 章で定める）。選択肢の行は `」` で終わらないため、⑤では判定できないからである。

## 2.2 コマンド行

```ebnf
command_line = "@" call_target "(" [ arguments ] ")" ;
call_target  = identifier { "." identifier } ;
arguments    = expression { "," expression } ;
```

- `@` で始まる行は、呼び出しの文である。呼ぶ相手は、ホストが登録したコマンド（`@bg("room")`）か、台本で宣言した `fn`（`@f(x)`）のどちらか。文として書いたときは、戻り値を捨てる。戻り値を受けるには、`let`・`=` の右辺に書く（2.2a）。
- コマンド名は、`audio.play` のように、パッケージ名を付けて書く。パッケージのコマンドは、`import パッケージ`（4.2）のあとで使える（していなければ `module_not_imported`）。パッケージに属さない停止型コマンド（ホストが `Registry::stop` で直接登録したもの）は、`import` なしで呼べる。
- `@` の文で呼べるのは、副作用型と停止型のコマンドである。問い合わせ型を `@` の文で呼ぶと、`invalid_command_use`（引数 `name`・`kind`）。
- 安定 ID（`#id`）は、停止型のコマンドの行にだけ付けられる。副作用型の行に付けると、`invalid_stable_id`。
- 引数の数が合わないと `arg_count`、型が合わないと `type_mismatch`。登録されていない名前は `unknown_command`（近い名前があれば `suggestions`）。
- コマンドは、ホストが型つきで登録したものだけが使える。登録されていない名前や、型が合わない引数は、コンパイルエラー（06 章）。
- コマンドと `fn` の名前が同じになったら、エラー。
- 副作用のない問い合わせコマンドは、式の中で、`@` を付けずに呼べる（例：`math.abs(x)`、`sprite.shown("案内人")`）。`@` は、文として呼ぶか、戻り値を受ける `let`・`=` の右辺の全体に書くときだけ付ける。副作用型・停止型を式の中で呼ぶと、`invalid_command_use`。式の途中に `@` で書いた呼び出し（`1 + @f()`・`if @f()`・引数の中・`( )` の中）も、`invalid_command_use`。
- コマンドとメンバーの名前（`math.abs` の `abs`）には、予約語（`label`・`list` など。1.6）も使える。名前空間（`math`）には使えない（登録のときに `InvalidName`）。
- `{ }` の中の文でも、呼び出しは `@` を付けて書く（例：`選択肢 => { @f(x); jump a }`）。

## 2.2a コマンドの戻り値を受ける

```ebnf
let_bind    = "let" identifier [ ":" type ] "=" command_call ;
assign_bind = target "=" command_call ;
command_call = "@" call_target "(" [ arguments ] ")" [ stable_id ] ;
```

```
let name = @input.text("名前は？", "", 8)
let age: int = @input.integer("年齢は？", 10, 0, 120)
name = @input.text("もう一度、名前は？", "", 8)
```

- 右辺の**全体**が `@` の呼び出しのときだけ、戻り値を受けられる。代入は `=` だけである（`+=` など複合代入の右辺には書けない。`invalid_command_use`）。
- 受けられるのは、戻り値が `()` でない、副作用型と停止型のコマンドである。戻り値が `()` のコマンドと、問い合わせ型は、受けられない（`invalid_command_use`。問い合わせ型は、`@` なしで式の中で呼ぶ）。戻り値の型が `list`・`map`・`Option`・`Identity` のコマンドも受けられる。
- `let` の変数の型は、戻り値の型である（型注釈があって違えば、`type_mismatch`）。代入は、変数の型と戻り値の型が合わなければ、`type_mismatch`。代入先は、ふつうの代入と同じ（ローカル変数・`save var`・`persistent var`・ホストが宣言した変数）。
- 副作用型は、呼んだその場で、値を変数に入れる。停止型は、停止点で止まり、ホストが `resume(Input::Return(値))` で返した値を、変数に入れてから、次の文へ進む（host/01-execution.md の 1.4）。
- 安定 ID は、停止型のときだけ、行末に付けられる（`let name = @input.text("名前は？", "", 8) #name`）。
- `let` の変数は、右辺の評価のあとで宣言される（右辺で、その変数は使えない。`unknown_name`）。
- ブロック（`if`・`while`・`choice` の本体）の中でも、ラベルの引数・`call` した先のラベルの中でも、同じように書ける。

## 2.3 identity の宣言

```ebnf
identity_decl = "identity" identifier "=" string_literal ;
```

- `identity 案内人 = "案内人"` のように、名前（識別子）と、表示名（文字列）を対応づける。
- **使える identity**は、次のものである。
  - 同じモジュールで宣言した identity。
  - `import` したモジュールで宣言された identity（`import` したモジュールが、さらに `import` したものは含めない）。
- 表示名は、差し替え表で、引用行の `Identity` の `name` だけ訳せる（host/05-texts.md の 5.2a）。
- 宣言した名前は、式の中で `Identity` 型の定数としても使える（`案内人.name` は `"案内人"`、`案内人.id` は `"案内人"`）。`save var` の初期値にも書ける。同じ名前の変数があるときは、変数が優先する。別のモジュールの identity は `モジュール.案内人`（`import` が要る）。
- 使える identity は、名前だけで書ける（`案内人「おはよう」`）。④の判定に使う。
- 同じ名前の identity が、複数の `import` 先にあって曖昧なときは、エラー（`ambiguous_identity`）。診断のヒントで、`モジュール.名前` の形（`chapter1.案内人「おはよう」`）を示す。この形は、曖昧でないときも書ける。
- 同じモジュールで宣言した identity は、`import` 先の同じ名前の identity より優先する（曖昧にならない）。
- `import` 先の identity の名前が、自分のモジュールの変数・ラベルの名前と同じでも、エラーにしない。identity として読まれるのは、行頭が `名前「` の形のときだけ。
- 宣言した名前が、変数・ラベルなどの名前と重なったら、エラー。

## 2.4 引用行

```ebnf
quote_line    = [ identity_name ] quoted_text [ stable_id ] ;
identity_name  = identifier ;
quoted_text   = "「" { body_char | body_escape | interpolation } "」" ;
body_escape   = "\\" ( "「" | "」" | "$" | "\\" | "=" | "#" ) ;
```

- `「` と `」` は、入れ子を数えて対応づける。`\「` と `\」` は数えない。
- 対応する `」` は、同じ行でも、後の行でもよい（複数行の引用行）。複数行の引用行は、`「` から対応する `」` までを 1 つとする。続けて読む行は、最初の行を除いて 256 行までとする。
- 複数行の引用行では、ソース上の改行と、その直後の行頭の空白（半角スペース・タブ）を取り除く。表示上の改行は、本文の `[br]` で書く。
- 引用行の `」` の後ろには、空白と安定 ID だけを書ける。安定 ID は、最後の行の末尾に書く。
- identity つきの引用行で、対応する `」` が見つからないときは、エラー（`unterminated_quote`）。identity なしの `「` で始まる行は、対応する `」` が見つからなければ、素の行として扱う。
- **identity つきの引用行で、`」` の後ろに他の文字が続く行は、エラー**（`text_after_quote`。例：`案内人「おはよう」と言った。`）。診断では、直し方のヒントを示す（identity を宣言しない名前にする、後ろの文字を引用行に含める、など）。
- identity つきの引用行で、`」` の後ろの `#…` が安定 ID の形（1.9）に読めないとき（例：`案内人「い」 #A`・`案内人「い」 #`）も、`invalid_stable_id` ではなく、同じ `text_after_quote` になる。
- identity なしの引用行（⑤）で、`」` の後ろに他の文字が続く行は、素の行として扱う（例：`「…」と案内人が言った。`）。
- 本文は、yomi が解釈しない。文字列として、束縛されたコマンドに渡す（5.4）。

## 2.5 素の行

- ⑥に当てはまった行は、素の行とする。接頭辞は持たない。
- 未宣言の名前の後に `「` が続く行（例：`門番「おはよう」`）は、素の行である。
- 未宣言の名前が、宣言済みの identity に近い綴りのときは、警告（typo 警告。`identity_typo`）を出す。綴りの近さの基準は、6.4 で定める。
- 素の行の行末にも、安定 ID を付けられる（引用行と同じ。1.9）。多言語化の差し替えのキーになる（host/05-texts.md）。

## 2.6 文の行

③に当てはまる行は、文の行である。文の文法は [3 章](03-statements.md) で定める。この章では、どの行が文の行になるかだけを定める。

- 行頭が予約語、または `}` の行は、文の行である。
- **代入文の始まり**：行頭が識別子で、その次（空白は挟んでよい）が代入演算子（`=` `+=` `-=` `*=` `/=` `%=`）である行は、文の行である（例：`favor += 1`）。`==` と `=>` は代入演算子ではない（`a => b` は、素の行である）。
- 代入文は、台本の途中にも書ける（`let` や `{ }` の中に限らない）。
- 素の行が、名前 + 代入演算子の形で始まる行（例：`朝 = 昼のはじまり`）は、代入文として読まれる。この `=` は `\=` と書くと、素の行として読まれる（例：`朝 \= 昼のはじまり`）。全角の `＝`（`U+FF1D`）は代入演算子ではないので、そのまま書ける。行頭が予約語などで始まる素の行は、行頭に `\` を付けて書く（1.10）。

## 2.7 安定 ID を付けられる行と、付ける位置

安定 ID（1.9）を付けられる行は、次の 4 種類である。どれも、行の中の決まった位置に `#id` を書く。ツール（`yomi assign-ids`。host/05-texts.md の 5.10）は、ID のないこれらの行に、同じ位置へ自動の ID を書き足す。

| 行 | ID を書く位置 | 例 |
| --- | --- | --- |
| 素の行（2.5） | 本文の終わり（行末の空白の前） | `おはよう #a3f9k2` |
| 引用行（2.4） | 閉じの `」` の直後（複数行の引用行は、最後の物理行） | `案内人「おはよう」 #b8x2m1` |
| 選択肢の文（5.5） | `=>` の直前（`once`・`if` の後ろ） | `「はい」 if ok #yes => …` |
| 停止型コマンドの行（2.2・2.2a） | 呼び出しの `)` の直後（複数行の呼び出しは、最後の `)` の直後。2.8） | `@flow.wait(1.5) #pause`、`let n = @input.text("名前", "", 8) #name` |

- `once` を付けた選択肢には、ID が要る（ないと `once_without_id`。5.5）。この欠落だけが原因のコンパイルエラーなら、ツールが、ほかの行と同じ位置（`=>` の直前）へ ID を書き足して直せる。
- `choice { }` の文そのもの・副作用型コマンドの行・`jump` などの文には、付けられない（付けると `invalid_stable_id`）。
- 自動の ID は、`#` と小文字英数字（`a`〜`z`・`0`〜`9`）6 文字。同じラベルの中で一意で、すでに書かれている ID と重ならない（同じ ID を別のラベルで使うことはある。1.9）。
- 位置のハッシュ（host/04-save.md の 4.4）は、台本の書き方から、書式の違い（空白など）を除いて作り、ID の有無に依存しない。ID を付けても、旧いセーブは、同じ停止点に戻る。

## 2.8 式の継続（複数行の式）

文の行（②③）と、選択肢の行（5.5）の中の式は、複数の行にまたがって書ける。

```
let items = [
    "薬草",
    "毒消し",
]
@shop.open("道具屋", map {
    "薬草": 10,
    "毒消し": 20,
})
let c = Chara {
    name: "案内人",
    hp: 10,
}
```

- 式の中で、開いた括弧が閉じないまま行が終わるとき、次の行は続きである。続きの行は、2.1 の分類をせず、前の行に空白 1 つでつないで、1 つの文として読む。
- 数える括弧は、式の `(`（呼び出しの引数・`Some(`・まとめの括弧）、`[`（`list` のリテラル・添字）、リテラルの `{`（`map {` と、struct のリテラルの `{`。3.7）である。ブロックの `{`（`if`・`while`・`for`・`match`・`choice`・`label`・`fn` の行の `{`）は、数えない。ラベルと `fn` の宣言の引数の `( )` も、式ではないので、数えない。
- 括弧の数えかたは、文字列リテラルの中と、コメントの中を、数えない。コメントは、物理行ごとに読む（1.4）。続きの行の間の、空行とコメントだけの行は、読み飛ばす。
- 開いた括弧がすべて閉じたところで、式が終わる。閉じる括弧の直後に、文の続き（`#id`・`=>`・`;`・ブロックの `{` など）を書ける。
- 続きは、最初の行を除いて 256 行までである。閉じる前にファイルが終わる、または 256 行を超えるときは、エラー（`unclosed_bracket`。引数 `open` は、閉じていない括弧の字。位置は、その括弧）。
- 診断の位置は、各字句の物理行・桁である。`unclosed_bracket` の位置は、閉じていない括弧のうち、いちばん外側のものである。
- モジュールの先頭の `save var`・`persistent var` の行も、この節に従う。選択肢の行は、閉じの `」` のあとの括弧（条件と、`=>` のあとの文の式）を数える。`=>` のあとが文の行でなければ、数えない。REPL の入力には、この節を適用しない（host/07-repl.md の 7.5.1）。
- 引用行・素の行・選択肢の本文は、この節の対象ではない（本文の中の括弧は、数えない）。複数行の引用行は、2.4 の規則で読む。
- リテラルと呼び出しの引数の最後の `,` は、あってもよい（3.2。意味は変わらない）。
