# 8. 整形（`yomi fmt`）

台本の書式を、1 通りに揃える。設定はない。コマンドラインの使い方は host/06-cli.md の 6.13 で定める。この章は、整形の結果の規則を定める。

## 8.1 原則

- **冪等**：整形した結果を、もう一度整形しても、同じ結果になる。
- **意味を変えない**：整形の前後で、コンパイルの結果（停止点・安定 ID・本文・位置の `hash`。host/04-save.md の 4.4）が同じである。整形は、この性質を、結果を書く前に確かめる。確かめられないときは、何も書かず、エラーにする。
- **構文エラーのある台本は整形しない**。診断を返す。型の誤りは、整形に関係しない。
- **変えないもの**：本文（引用行・素の行・選択肢の文字。`${式}` の中も含む）、文字列リテラル、安定 ID（`#id` の値）、コメントの文字、識別子・ラベル・identity の名前、改行コード（LF・CRLF）、先頭の BOM。
- 行の分類（2.1）と、複数行の引用行の範囲は、解析と同じ規則で決める。分類には、使える identity（2.3）が要るので、整形は、台本を集めて、identity を解決する（型検査はしない）。
- **行の数は、変えない**。ただし、連続する空行の数（8.3）、複数行の宣言（8.5）、複数行の式（8.5a）は除く。

## 8.2 インデント

- 1 段は、4 つの半角スペース。タブは使わない。
- 段の数は、`{` で開いたブロックの入れ子の深さである。行の終わりの `{` で 1 段深くなり、行頭の `}` で 1 段戻る（`} else {` の行は、`}` の分だけ戻ってから、`{` で深くなる）。1 行の中で閉じる `{ … }` は、段を変えない。
- 式の括弧を複数の行にまたがって書くときの行は、8.5a の規則で置く（行の終わりの `map {` の `{` などは、ブロックの段を変えない）。
- 引用行・素の行・コメントの行も、そのブロックの段に置く。素の行の行頭の全角スペースは、本文なので、変えない。
- 複数行の引用行の、2 行目以降は、1 段深くする（行頭の半角スペース・タブは、本文でないので、取り除いて置き直す）。**行末の空白は、本文なので、取り除かない**。引用行の中の空行は、そのまま残す。
- 行末の半角スペース・タブは、取り除く（上の複数行の引用行の中を除く）。ファイルの終わりは、改行 1 つ。

## 8.3 空行とコメント

- 連続する空行は、1 行にする（複数行の引用行の中を除く）。ファイルの先頭と、`{` の直後と、`}` の直前の空行は、取り除く。空行は、足さない。
- コメントだけの行は、置かれたブロックの段に揃える。文字は変えない。
- 行の途中のコメント（文・コマンドの行。1.4）は、行の本体の後ろに、半角スペース 2 つを置いて続ける。

## 8.4 文と式の書式

- 式は、標準書式（3.9）に直す。冗長な括弧は、消える。`if`・`while`・`match`・`for` の式も、同じである。
- 文は、次の形に揃える。キーワードの後ろは、半角スペース 1 つ。

| 文 | 書式 |
| --- | --- |
| ラベル・`fn` | `label 名前(引数: 型, 引数: 型 = 既定値) -> 型 {`（`->` の前後に空白を 1 つ。引数がなければ括弧なし） |
| `if`・`while`・`for`・`match` | `if 条件 {`・`} else if 条件 {`・`} else {`・`while 条件 {`・`for x in 式 {`・`for k, v in 式 {`・`match 式 {` |
| `let`・代入 | `let 名前: 型 = 式`・`名前 = 式`・`名前 += 式`（`:` の後ろに空白 1 つ、前は空けない。演算子の前後に空白 1 つ） |
| コマンド | `@名前(引数, 引数) #id`（`)` と `#id` の間は、空白 1 つ） |
| `jump`・`call`・`return` | `jump ラベル`・`call ラベル(引数)`・`return 式` |
| 宣言 | `identity 名前 = "表示名"`・`save var 名前: 型 = 式`・`persistent var 名前: 型 = 式`・`import a::b`・`import a::{b, c}`・`import a as b` |
| `match` のアーム | `パターン => 文`、または `パターン => {`。行末の `,` は、取り除く |
| 1 行のブロック | `{ 文; 文 }`（`{` の後ろと `}` の前に空白 1 つ、`;` の後ろに空白 1 つ、前は空けない。空のブロックは `{}`） |

- 素の行と引用行の `#id` は、本文（または `」`）の後ろに、半角スペース 1 つを置く。identity と `「` の間は、空けない。

## 8.5 複数行の宣言

- `struct`・`enum` の宣言が、複数の行にまたがるときは、次の形に直す（1 行に収まっているものは、1 行のまま）。
  - 1 行目は `struct 名前 {`、最後の行は `}`。
  - 中は、フィールド（バリアント）ごとに 1 行、1 段深く置き、各行の終わりに `,` を付ける。
  - `struct` のフィールドは、`名前:` の後ろの型の頭を、そろえる（8.6）。
- 1 行の宣言は、`struct 名前 { a: 型, b: 型 }`・`enum 名前 { A, B(型) }` の形にする（`{` の後ろと `}` の前に空白 1 つ、`,` の後ろに空白 1 つ、末尾の `,` はなし）。

```
struct Item {
    id:    str,
    count: int,
}
```

## 8.5a 複数行の式

式の括弧（`(`・`[`・`map {`・struct のリテラルの `{`。2.8）の組が、ソースで複数の行にまたがっているものを、**複数行の形**にする。またがっていない組は、1 行の標準書式（3.9）にする。

- 開く括弧で、行を終える。
- 要素（引数・`list` の要素・`map` の項目・struct のフィールドの初期値）は、1 つにつき 1 行で、開いた行より 1 段深く置く。各要素の終わりに、`,` を付ける（最後の要素にも）。
- 閉じる括弧は、独立した行に、開いた行と同じ段で置く。閉じる括弧の後ろに、文の続き（`)`・` #id`・` => …`）を、続けて書く。
- 要素の中の組が、またがっているときは、再帰して同じ形にする。そのほかの要素は、1 行にする（要素の中の演算子の途中で改行してあっても、つなげる）。
- まとめの括弧 `( 式 )` は、またがっていても、1 行にする（冗長な括弧は、消える。8.4）。
- 要素のない組（`[]`・`map {}`・`f()`）は、またがっていても、1 行にする。

```
@shop.open(
    "道具屋",
    map {
        "薬草":   10,
        "毒消し": 20,
    },
)
```

- `map` の項目と struct のフィールドの初期値は、`:` の後ろの値の頭を、同じ桁にそろえる（8.6）。
- 組の中のコメントは、次のように置く。要素と同じ行の後ろのコメントは、その要素の `,` の後ろに続ける。コメントだけの行は、すぐ後ろの要素の前に置く。開く括弧の行のコメントは、開く括弧の後ろに続ける。どれにも当てはまらないコメントは、文の後ろに続ける。コメントの文字は、変えない。

## 8.6 位置のそろえ

そろえるのは、次の 3 つだけである。ほかの `=>` や `:` は、そろえない（呼び出しの名前つきの引数も、そろえない）。

- **`choice` の `=>`**：1 つの `choice { }` の直下の選択肢のうち、`=>` の前の部分（`「…」`・`once`・`if 条件`・`#id`）が 1 行に収まるものを、1 つの組にする。組の中で、`=>` の前の部分の表示幅が最も大きいものに合わせて、ほかの選択肢の `=>` の前に半角スペースを足し、`=>` を同じ桁にそろえる（最も幅の大きい選択肢の `=>` の前は、空白 1 つ）。`=>` の前の部分が複数の行にまたがる選択肢（複数行の引用行）は、組に入れず、`=>` の前を空白 1 つにする。
- **複数行の `struct` 宣言のフィールドの型**：`名前:` の後ろに空白を足して、型の頭を同じ桁にそろえる（最も長い名前の `:` の後ろは、空白 1 つ）。
- **複数行の `map` のリテラルの項目と、struct のリテラルのフィールドの初期値**：同じ組の要素の、`キー:`（`名前:`）の後ろに空白を足して、値の頭を同じ桁にそろえる。キーは、1 行の標準書式にしたもの。

```
choice {
    「はい」 #yes                 => { jump accept }
    「いいえ、断る」 if brave #no => { jump refuse }
}
```

- **表示幅**は、文字ごとに、次の値の合計である。Unicode の版は、識別子の規則（1.5）と同じ。
  - East Asian Width が W または F の文字、および Emoji_Presentation の文字：2。
  - 一般カテゴリが Mn・Me・Cf の文字（結合文字・ゼロ幅の文字・異体字選択子など）：0。
  - それ以外（East Asian Width が A の文字を含む）：1。
- 環境や字体によっては、見た目の桁が、表示幅と少しずれることがある。そろえは、表示幅の規則だけで決まり、フォントには依らない。
- そろえるための空白は、本文ではない（`=>` と `:` の外にあるので、`hash` と安定 ID に影響しない）。

## 8.7 `migrations` モジュール

- `migrations.yomi`（7.4）も整形する。インデントは 4 つの半角スペース。`min_save_version N`・`migrate N {`・`}` は、最上位に置く。
- `rename 旧 -> 新`・`convert 旧: 型 -> 新: 型 = ラムダ式`・`drop 旧`は、キーワードの後ろに空白 1 つ、`->`・`=`・`:` の書式は 8.4 と同じ。`=` で行を終える `convert` の続きの行は、1 段深くする。
- 凍結スキーマ（`schema/vN.yomi`。7.3）は、整形しない（ハッシュが変わるため）。
