# 1. 字句

## 1.1 EBNF の記法

| 記法 | 意味 |
| --- | --- |
| `a b` | a の次に b |
| `a \| b` | a または b |
| `[ a ]` | a は省略できる |
| `{ a }` | a の 0 回以上の繰り返し |
| `( a )` | まとめ |
| `"x"` | 文字列そのもの |
| `U+XXXX` | Unicode のコードポイント |
| `(* … *)` | 文法の注釈 |

## 1.2 ソース

- ソースは UTF-8 とする。先頭の BOM（`U+FEFF`）があれば無視する。
- 改行は `LF`、`CR LF` のどちらも受け付け、`LF` として扱う。
- ファイルの拡張子は `.yomi` とする。
- 1 つのファイルは 1 つのモジュールである（04 章）。

```ebnf
newline = "\n" | "\r\n" ;
```

## 1.3 空白

- 半角スペース（`U+0020`）とタブ（`U+0009`）を、空白とする。
- 行頭の空白は、インデントとして無視する（インデントに意味を持たせない）。
- 全角スペース（`U+3000`）は、空白ではない。コードの中に現れたらエラー。本文（引用行・素の行）の中では、本文の一部として残す。
- 本文（引用行・素の行）の行頭の全角スペース（字下げ）は、本文の一部として残す。行頭の半角スペースとタブだけを、インデントとして無視する。

## 1.4 コメント

- `//` から行末までを、コメントとする。
- 文・コマンドの行では、行の途中の `//` もコメントの始まりとする（文字列リテラルの中は除く）。
- 本文の行（引用行・素の行）では、**行頭**の `//` だけがコメントである。本文の途中の `//` は、本文の一部とする（例：`https://` を含む素の行）。
- ブロックコメントは、v0 では持たない。

## 1.5 識別子

```ebnf
identifier     = ident_start { ident_continue } ;
ident_start    = XID_Start | "_" ;
ident_continue = XID_Continue ;
```

- `XID_Start` と `XID_Continue` は、Unicode の識別子の規則（UAX #31）による。日本語（ひらがな、カタカナ、漢字、長音符 `ー`、踊り字 `々`）、英数字、アクセント付きの英字、`_` を使える。数字と結合文字は、2 文字目以降に使える。
- 予約語（1.6）は、識別子にできない。ただし、`名前空間.名前` の `.` の後ろの名前（パッケージのコマンド・変数・型の名前）には使える（1.6）。
- `「` `」` `$` `@` `#` `\` などの記号、絵文字、空白類（全角スペースを含む）、`-` `+` などの演算子の記号、丸数字（`①`）は、`XID_Start`・`XID_Continue` にあたらないので、識別子に含まれない。識別子の位置に書くと、`unexpected_token`（全角スペースは `full_width_space`）。
- ソースから読んだ識別子は、Unicode の正規化形式 NFC に直して扱う。見た目が同じで、コードポイントの並びだけが違う識別子（例：`が` と、`か` + 濁点 `U+3099`）は、同じ名前になる。対象は、変数・ラベル・`fn`・`struct`・`enum`・フィールド・バリアント・引数・ローカル変数・`identity`・モジュール（ファイル名・ディレクトリ名から付く名前を含む）・`import` する名前（パスの各語と別名）・パッケージとコマンドの名前。診断の引数（`name` と、近い綴りの候補）は、NFC の形で出す。
- 次のものは、正規化しない。文字列リテラル、本文（引用行・素の行・選択肢の文字）、コメント、安定 ID（1.9。`a-z` `0-9` `_` だけ）。
- NFKC の変換はしない。全角の英数字と半角の英数字は、別の名前になる（例：`ａ` と `a`）。
- 位置のハッシュ（host/04-save.md の 4.4）の入力に含まれる識別子（コマンドの引数の式、本文の `${式}` の中）も、NFC に直してから使う（3.9。文字列リテラルと本文の文字は、書かれたまま）。分解形で書いた識別子は、合成形で書いた台本と、同じ名前、同じハッシュになる。
- ホストが登録する名前（コマンド・変数・型・パッケージ。host/02-registry.md の 2.2）も、同じ規則で検査する。NFC に直っていない名前は、登録のエラーになる（台本から引けなくなるため）。

## 1.6 予約語

次の語は、予約語である。

```
identity  label  jump  call  choice  import  end
save  persistent  var  let  fn
if  else  while  for  in  match  break  continue
true  false  enum  struct
return  Some  None
int  float  bool  str  list  map  Option  Identity
```
- 文脈つきの語は、予約語にしない。決まった位置でだけ意味を持ち、ほかの位置では識別子として使える。
  - `once`：`choice { }` の選択肢の先頭（5.5）。
  - `as`：`import` の別名の前（4.2）。
  - `std`：`import` のパスの先頭（標準パッケージの名前空間。4.2）。モジュールの名前には使えない。
  - `each`：文 `式.each { 名前 =>` の `.` の後ろ（3.4）。
- `random`・`random_float`・`seen`・`visited`・`to_int`・`to_float`・`range` は、組み込み関数の名前で、予約語にしない（3.8、5.7）。
- 予約語は、`名前空間.名前` の `.` の後ろの名前には使える（例：コマンド `input.int`、変数 `game.end`）。台本の `input.int(…)`・`@input.int(…)`・`game.end` のように、`.` の後ろは、いつも名前として読むので、曖昧にならない。使えないところ：名前空間（パッケージ名）・モジュールの名前・変数・ラベル・`fn`・`struct`・`enum` の名前、フィールドとバリアントの名前、名前空間のないコマンドの名前。
- 新しい構文のキーワード（`spawn` など）は、将来、足すときは、文脈つきのキーワードとし、既存の台本の名前を壊さない。
- 予約語は、増やすことがある。増やすときは、既存の台本が壊れないかを確かめる。

## 1.7 リテラル

```ebnf
int_literal   = digit { digit | "_" } ;
float_literal = digit { digit | "_" } "." digit { digit | "_" } ;
bool_literal  = "true" | "false" ;
digit         = "0" … "9" ;
```

- 整数は 10 進数のみ（v0）。型は `i64` である。範囲を超える値はエラー。リテラルは `0` 〜 `9223372036854775807` で、最小値 `-9223372036854775808` は、リテラルとして書けない（必要なら `-9223372036854775807 - 1`）。
- 浮動小数は `f64` である。小数点の前にも後ろにも、数字が要る（`1.5`・`0.25` は書けるが、`.5`・`1.` は書けない。`1.` は、整数 `1` のあとの `.`）。指数表記は、v0 では持たない。有限の `f64` に収まらないリテラルは、エラー（`invalid_number`）。
- `_` は桁区切りで、値に影響しない。整数部と小数部の、先頭と末尾には置けない（`1_.5`・`1.5_` はエラー）。

### 文字列リテラル

```ebnf
string_literal = '"' { string_char | string_escape | interpolation } '"' ;
string_escape  = "\\" ( '"' | "\\" | "n" | "t" | "$" ) ;
interpolation  = "${" expression "}" ;
```

- 文字列リテラルの中の `\` は、`\"` `\\` `\n` `\t` `\$` のどれかで始まる。それ以外はエラー。
- `${式}` は、式の値を文字列にして埋め込む（値の文字列にし方は、3.2）。式は静的に型検査する（06 章）。
- 文字列リテラルは、改行を含められない。

## 1.8 記号

```
(  )  {  }  [  ]  ,  :  ;  .  =>  ->
=  +=  -=  *=  /=  %=
+  -  *  /  %
==  !=  <  <=  >  >=
&&  ||  !
@  #
```

- 演算子の優先順位と結合は、03 章（3.2）で定める。
- `@` はコマンドの始まり、`#` は安定 ID の始まり（1.9）。

## 1.9 安定 ID

```ebnf
stable_id = "#" id_char { id_char } ;      (* 1〜32 文字 *)
id_char   = "a" … "z" | "0" … "9" | "_" ;
```

- 安定 ID は、停止型コマンドの呼び出しにあたる行（素の行・引用行・選択・`wait` など）の**末尾**にだけ付けられる（選択肢の文では、`=>` の直前。位置は 2.7 の表）。
- 長さは 1 文字以上 32 文字以下とする。
- 同じラベルの中で一意でなければならない。重複はエラー。
- 本文の途中の `#` は、本文の一部である。
- 素の行・引用行の行末が、空白 + 安定 ID の形のときは、安定 ID として読む。本文の末尾に `#` と英数字を置きたいときは、`\#` と書く（1.10）。
- 安定 ID の形に読めない `#…`（大文字・`#` だけ・`#` の後ろの空白など）は、identity つきの引用行の `」` の後ろでは `text_after_quote`（2.4。例：`案内人「い」 #A`）、選択肢の文・`@` のコマンドの行の末尾では `invalid_stable_id` になる。

## 1.10 本文のエスケープ

本文（引用行・素の行）の中では、`\` で次の 6 つを書く。

| 書き方 | 意味 |
| --- | --- |
| `\「` | 文字の `「` |
| `\」` | 文字の `」` |
| `\$` | 文字の `$` |
| `\\` | 文字の `\` |
| `\=` | 文字の `=`（行頭の「名前 + `=`」を代入文と読ませないために使う。2.6） |
| `\#` | 文字の `#`（行末の安定 ID と読ませないために使う。1.9） |

- これ以外の `\` の組み合わせは、エラーとする。
- **行頭の `\`**：行頭が `\` で、次の文字が上の 6 つのどれでもない行は、素の行である。この `\` は本文に残さない（例：`\in the room` は、本文 `in the room` の素の行。行頭が予約語・`@` などの行を、素の行として書くために使う）。行頭の `\` に 6 つのどれかが続く行は、素の行で、6 つの規則に従う。
- `[tag]` などの装飾のマークアップは、yomi は解釈しない。そのまま文字列として、束縛されたコマンドに渡す（5.4。ホストが扱う）。
- 本文の中の `${式}` は、変数の埋め込みとして扱う（文字列リテラルと同じ）。`$` の直後が `{` でないときの `$` は、そのまま文字の `$`（例：`$100`）。`${` を文字にしたいときは `\${` と書く。
