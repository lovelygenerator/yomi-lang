# 6. コマンドライン（`yomi`）

この章は、`yomi` コマンド（`yomi-cli`）の約束を定める。台本を動かす・検査する・ID を付ける・差し替え表を扱う、ホストなしの道具である。コアの API は host/01〜05 にあり、この章は、その上の CLI だけを書く。

CLI の文面（メッセージの文）は、表示言語（6.1）ごとに変わる。この章が定めるのは、サブコマンド・引数・オプション・終了コード・出力の先と形であり、文の言い回しは定めない。文中の出力例は、表示言語が `en` のときのものである。

## 6.1 共通の約束

```
yomi [--lang <言語>] <サブコマンド> [オプション…]
```

| サブコマンド | 内容 | 節 |
| --- | --- | --- |
| `version` | 版を表示する | 6.2 |
| `run` | 台本を実行する | 6.3 |
| `check` | 台本を実行せずに検査する | 6.4 |
| `decls` | 組み込みの登録表の宣言ファイルを書く | 6.5 |
| `assign-ids` | 安定 ID のない行に ID を書き足す | 6.6 |
| `texts check` | 台本と差し替え表を突き合わせる | 6.7 |
| `texts template` | 差し替え表のひな形を書く | 6.7 |
| `codes` | コードの一覧を表示する | 6.8 |
| `repl` | 対話の実行環境（REPL）を始める | 6.10（章は 7） |
| `mcp` | MCP サーバーを標準入出力で動かす | 6.11 |
| `lsp` | Language Server（LSP）を標準入出力で動かす | 6.12 |
| `fmt` | 台本を整形する | 6.13 |
| `schema freeze` | 版のスキーマを凍結して、ファイルに書く | 6.14 |
| `schema extract` | セーブ・永続データから、スキーマを復元する | 6.14 |
| `migrate-init` | `migrate` の雛形を作る | 6.15 |
| `release` | リリースの前の検査（厳格）と、スキーマの凍結を行う | 6.16 |
| `test` | 台本の分岐を探索して、golden と比べる | 6.17 |
| `debug` | 台本を、行の単位で止めながら実行する（対話） | 6.18 |
| `dap` | Debug Adapter（DAP）を標準入出力で動かす | 6.19 |

- 引数なしの `yomi`、サブコマンドなしの `yomi texts` は、使い方を表示して終了コード 2（6.9）。
- `-h` / `--help` は、使い方を標準出力に出して終了コード 0。`-V` / `--version` は `yomi version` と同じ。
- **登録表**：`run`・`check`・`assign-ids`・`texts` は、組み込みの登録表を使う（`texts` は `--decls` を取らず、組み込みの登録表だけを使う）。標準パッケージ（`flow` `math` `text` `audio` `image` `screen` `input` `event`。[packages/](../packages/)）と、糖衣の束縛（素の行・引用行・選択を停止型コマンドに束縛したもの。language/05-sugar.md、host/02-registry.md の 2.6）を持つ。`check`・`assign-ids`・`release` は、`--decls` で、宣言ファイル（host/02-registry.md の 2.8）から作った登録表に替えられる。

### 表示言語（`--lang`）

- `--lang <言語>` は、CLI の**表示言語**を決める。診断・メッセージ・使い方の文面の言語である。`en` と `ja` がある。どのサブコマンドでも、サブコマンドの前でも後ろでも指定できる。
- 指定がないときは、環境変数 `YOMI_CLI_LANG`、`LC_ALL`、`LC_MESSAGES`、`LANG` の順に、最初に有効なものを使う。どれもなければ、または対応しない言語名なら、`en`。
- 表示言語は、台本の本文の言語ではない。本文の言語（差し替え表。host/05-texts.md）とは別のもので、`run --texts`・`texts template --text-language`（6.3・6.7）が扱う。

### 台本の集め方

`run`・`check`・`texts`・`assign-ids` は、起動ファイル（台本のファイル）のほかに、同じ**探すディレクトリ**の下の `.yomi` を、すべてモジュールとして集めてコンパイルする。

- 探すディレクトリは、`--root <ディレクトリ>` で決める。なければ、起動ファイルのあるディレクトリ（`assign-ids` は、最初に指定した台本のあるディレクトリ）。サブディレクトリも探す（シンボリックリンクのディレクトリは辿らない。名前が `.` で始まるディレクトリとファイルは、集めない。起動ファイルは、集める）。
- モジュールの名前は、探すディレクトリからの相対パスから拡張子を除き、区切りを `::` にしたもの（`story/ch1.yomi` は `story::ch1`。language/04-labels-modules.md の 4.1）。ディレクトリの名前も、識別子でなければならない。
- 起動ファイルが、探すディレクトリの下になければ、エラー。読めないファイルがあれば、エラー。ファイルの文字コードは UTF-8 だけ。
- 探すディレクトリの下の `schema/` の `.yomi` と、`migrations.yomi` は、モジュールではなく、セーブの移行の入力として集める（language/07-migrate.md）。
- 起動ファイルのモジュールの `start` ラベルが、既定の開始ラベルである（`run` は `--start` で変えられる。6.3）。

### 出力の先と書式

- 診断（エラー・警告）・エラー・警告の報告は標準エラー、結果の本体（本文・件数・一覧）は標準出力に書く。ただし、各節で別に書いたものは、そちらに従う。
- 診断の 1 行は、`<ファイル>:<行>:<桁>: <重大度>: <文面>`（language/06-diagnostics.md の 6.1。行・桁は 1 始まり、桁は Unicode スカラ値の数）。ファイルは、診断が起きたモジュールのファイルのパス。重大度の語は表示言語による（`en` では `error`・`warning`）。
- 位置のないエラー（ファイルを読めない、起動ファイルが探すディレクトリの外、など）と、実行時エラーは、`<ファイル>: error: <文面>` の形。実行時エラーは、文面の後ろに、ラベルと行を付ける（`(label モジュール.ラベル, line 行)`）。
- 差し替え表の誤りは、`<表のファイル>:<行>: error: <文面>`（表の解析の誤り。host/05-texts.md の 5.7）と、`<表のファイル>: <重大度>: <文面>`（台本との突き合わせの結果。5.4）。

## 6.2 `yomi version`

```
yomi version
```

版を 1 行（`yomi <版>`）、標準出力に書く。終了コード 0。

## 6.3 `yomi run`

```
yomi run <台本> [--root <ディレクトリ>] [--start <ラベル>] [--persistent <ファイル>]
         [--seed <数>] [--texts <表>] [--auto] [--show-ids] [--lenient] [--watch]
```

台本を実行する。停止点（本文・選択・待ち・入力）で止まり、標準入力から 1 行ずつ読んで進める。ホストの役を、端末で演じる道具である（host/01-execution.md）。

### 引数・オプション

| 引数・オプション | 内容 |
| --- | --- |
| `<台本>` | 起動ファイル。必須 |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1） |
| `--start <ラベル>` | 開始するラベル。`モジュール.ラベル`、またはラベルの名前だけ（起動ファイルのモジュールのラベル）。なければ、起動ファイルのモジュールの `start`（language/04-labels-modules.md の 4.7） |
| `--persistent <ファイル>` | 永続データ（`persistent var` と通過済みの停止点。host/04-save.md の 4.5）のファイル。起動時に読み（なければ新規）、停止点ごとと終了時に書く（一時ファイルに書いて名前を付け替える） |
| `--seed <数>` | 乱数の種（0 以上の整数）。なければ、起動した時刻から決める |
| `--texts <表>` | 本文の差し替え表のファイル（host/05-texts.md の 5.7）。起動時に読んで設定する（5.8） |
| `--auto` | 自動プレイ（6.3.3） |
| `--show-ids` | 選択肢の安定 ID を表示に出す（6.3.2） |
| `--watch` | 台本・差し替え表のファイルを見て、変わったら、停止点を保ったまま読み込み直す（6.3.5）。`--auto` とは同時に使えない（引数の誤り） |
| `--lenient` | ロードの方針を `Lenient` にする（host/04-save.md の 4.6）。`--persistent` の読み込みと `:load` に効く。なければ `Strict`。型の変わった変数があると、`Strict` はエラー（終了コード 1）、`--lenient` は初期値に戻して続ける（標準エラーに知らせる） |

### 起動

1. 台本を集めてコンパイルする。警告は標準エラーに出して、そのまま実行する。エラーがあるときは、診断を標準エラーに出し、実行せずに終了コード 1。
2. `--persistent` と `--texts` を読む。読めない・設定できないときは、標準エラーに書いて、実行せずに終了コード 1。永続データの読み込みで知らせることがあれば（変数が増えた・消えた、など。host/04-save.md の 4.5）、標準エラーに書く。
3. 開始ラベルから実行する。開始ラベルがなければ、実行時エラー（終了コード 1）。

### 6.3.1 停止点の表示

停止点は、標準出力に次のように出る。

| 停止点 | 表示 |
| --- | --- |
| 素の行 | 本文 |
| 引用行 | identity の表示名に続けて、本文（`「」` を含む）。identity がなければ、本文だけ（例：`案内人「どうする？」`） |
| 選択 | 選択肢の文を、`1: 「話す」` のように、1 始まりの番号つきで 1 行ずつ。選択肢が持つ安定 ID は、6.3.2 のとき、行の終わりに ` #id` として付く |
| `flow.wait`・`flow.wait_input` | 待つ点であることを示す 1 行（実際には待たない。Enter で進む） |
| `input.text`・`input.integer`・`input.confirm` | `[input] 促し (種類と範囲。Enter で既定値)` の 1 行 |
| `event.wait` | `[event] 名前, 名前 (期限 秒)` の 1 行（期限がなければ、括弧の部分はない） |
| 音・画像・画面の合図 | `[audio] …`・`[image] …`・`[screen] …` の 1 行ずつ。合図を出したコマンドの後の停止点の前（または、終わりの前）に出る（packages/audio.md・packages/image.md・packages/screen.md） |
| 終わり | 終わりを示す 1 行（`(end)`） |

本文の差し替え表を設定しているときは、訳文で表示する（host/05-texts.md）。表示する本文の言語は、`--lang`（表示言語）とは関係ない。

### 6.3.2 入力

停止点ごとに、標準入力から 1 行読む。1 行の前後の空白は、取り除く（`input.text` の値は、取り除かない）。`:` で始まる行は、どの停止点でも対話コマンド（6.3.4）。

| 停止点 | 入力 |
| --- | --- |
| 本文・待ち | 空行で、次へ進む。標準入力の終わり（EOF）も同じ。空行でも `:` で始まる行でもない入力は、標準エラーに案内を出して、同じ停止点で待つ |
| 選択 | 一覧の番号（`1`〜選択肢の数）、または、選択肢の安定 ID を `#` つきで（`#talk`）。ID は、表示に出していなくても、答えられる（`--show-ids` は、表示に出すだけ）。範囲外・数でない入力・空行・一覧にない ID は、標準エラーに知らせて、同じ停止点で番号を求め直す。EOF は、1 番を選ぶ |
| `input.text` | 1 行をそのまま値にする。空行・EOF は、既定値。`max_len` を超えると、実行時エラー（終了コード 1） |
| `input.integer` | 整数。空行・EOF は、既定値。整数でない入力は、エラーで終了コード 1。範囲（`min`〜`max`）の外は、実行時エラー（終了コード 1） |
| `input.confirm` | `y`・`yes`・`はい`（大文字小文字を区別しない）・空行・EOF は「はい」、`n`・`no`・`いいえ` は「いいえ」。ほかの入力は、エラーで終了コード 1 |
| `event.wait` | `名前` または `名前 データ`（最初の空白で分ける。データの前後の空白は取り除かない）で、`Arrived(名前, データ)`（データがなければ空の文字列）。空行・EOF は、期限があれば `TimedOut`。期限がなければ、空行は標準エラーに案内を出して同じ停止点で待ち、EOF はエラーで終了コード 1。一覧にない名前は、標準エラーに知らせて、同じ停止点で求め直す |

`input.text` の値として `:` で始まる文字列は、入力できない（対話コマンドとして扱う）。

### 6.3.3 `--auto`（自動プレイ）

- 本文（素の行・引用行）と、`flow.wait`・`flow.wait_input` の停止点は、入力を読まずに進む。選択・`input.*`・`event.wait` の停止点だけ、標準入力から 1 行読む（入力の規則は、6.3.2 のとおり）。
- 選択の表示には、安定 ID が常に付く（`--show-ids` と同じ）。答えは番号か `#id`。`if`・`once` で選択肢の番号がずれても、ID で答えれば、入力の列は変わらない。台本の回帰テストに使える。
- 選択の答えにならない入力（範囲外・数でない・一覧にない ID・空行）と、選択の前に標準入力が尽きたときは、続けずに、標準エラーに書いて終了コード 1（自動プレイでは、答えのずれを黙って進めない）。
- 対話コマンド（6.3.4）は、入力を読む停止点（選択・`input.*`・`event.wait`）で使える。
- `event.wait` で、一覧にない名前・空行（期限がないとき）・標準入力の尽きは、続けずに、標準エラーに書いて終了コード 1。

### 6.3.4 対話コマンド

`:` で始まる行は、対話コマンドとして処理する。コマンドと引数は、空白で区切る（引数は、残りの行全体。前後の空白は取り除く）。処理のあとは、`:back`・`:load` で別の停止点へ移ったとき（と、`:texts` のとき）を除いて、同じ停止点で、次の入力を待つ。

| コマンド | 動作 |
| --- | --- |
| `:save <ファイル>` | いまの停止点で、セーブ（host/04-save.md）をファイルに書く。書けたら、1 行を標準出力へ。失敗は標準エラーで、同じ停止点に残る |
| `:load <ファイル>` | セーブを読んで、その停止点へ移る。`persistent var` と通過済みの停止点は、いまの VM のものを引き継ぐ。読み込みの報告（位置の解決のしかたが弱かった・変数が変わった、など。host/04-save.md の 4.6）は、標準出力へ。ファイルが読めないときは、標準エラーに書いて、同じ停止点に残る。セーブが壊れている・台本と合わないときは、エラーで終了コード 1。いまの差し替え表は、読み込んだあとも使い続ける |
| `:back` | 1 つ前の停止点へ戻す（ロールバック。host/04-save.md の 4.7）。戻れる停止点は、直近 200 件まで。前の停止点がなければ、1 行を標準出力に出して、同じ停止点に残る。`persistent var` と通過済みの停止点は、戻らない |
| `:texts <表のファイル>` | 差し替え表を切り替えて、いまの停止点を作り直して、もう一度表示する（host/05-texts.md の 5.8）。`:texts off` で原文に戻す。読めない・設定できないときは、標準エラーに書いて、同じ停止点で待つ |
| `:repl` | いまの停止点の環境の複製の上で、REPL に入る（入ったことを示す 1 行を標準出力へ）。`:exit` で、同じ停止点へ戻る。`:apply` で変数を反映したときだけ、作り直した停止点を表示し直す。入力を読む停止点で使える（`--auto` では、選択と `input.*` の停止点）。詳しくは host/07-repl.md の 7.1・7.3.6 |
| `:reload` | 台本（と、差し替え表）を読み込み直して、いまの停止点を保ったまま差し替える（6.3.5）。`--watch` なしでも使える |
| `:vars` | 変数を、`名前 = 値` で 1 行ずつ標準出力へ（モジュールが複数あるときは、モジュールの変数を `モジュール.名前` で）。値の形は、下の「`:vars` の値の形」 |
| `:quit` | 実行をやめる。終了コード 0 |

- `:reload` は引数を取らない。`:vars` や `:quit` と同じに、入力を読む停止点で使える。
- `:save`・`:load`・`:texts` に引数がないときは、標準エラーに知らせて、同じ停止点に残る。
- 知らないコマンドは、標準エラーに知らせて、同じ停止点に残る（使えるコマンドの一覧を添える）。`:exit` は、`yomi run` では知らないコマンドである（REPL の中のコマンド。`:quit` を使う）。
- `:texts` の `<表のファイル>` は、本文の差し替え表（5.7）である。`yomi texts template --text-language` で書く言語名や、`--lang`（表示言語）とは別のもの（6.7）。

### 6.3.5 ホットリロード（`--watch`・`:reload`）

- **読み込み直し**：起動のときと同じに、台本を集めてコンパイルし（6.1）、`--texts` を読む。成功したら、host/04-save.md の 4.10 の `reload` で、いまの停止点を保ったまま差し替える。起動ファイル・`--root`・`--persistent`・`--seed`・`--start` は、読み込み直さない（`--start` は、最初の実行にだけ効く）。
- **成功**：標準エラーに、`[reload]` で始まる 1 行（位置の解決のしかたを含む）を書き、新しい停止点を、標準出力に、もう一度表示する（6.3.1）。
- **失敗**：コンパイルエラー・差し替え表の誤り・`reload` の失敗（位置を保てない・スキーマが合わない）は、診断と理由を標準エラーに書き、**いまの実行を続ける**（終了コードには影響しない）。直して保存し直せば、また読み込む。
- **`--watch`**：探すディレクトリ（6.1）の下の `.yomi` と、`--texts` のファイルの、変更・追加・削除を見る。続けて起こる変更は、まとめて 1 回にする（間隔は約 200 ミリ秒）。標準入力は別に読むので、入力を待っているあいだの変更も、すぐ反映する。入力の規則（6.3.2）は変わらない。
- 読み込み直したあとは、`:back` で戻れるのは、そこから先の停止点だけである（古い台本のスナップショットは捨てる）。`:repl` の中は、`:reload` を受けない。
- 台本が最後まで進んだあと（`(end)`）は、終了する。読み込み直さない。
- 変更の通知は、OS によっては取りこぼすことがある。反映されないときは、`:reload` を使う。

### `:vars` の値の形

`:vars` は、値を、`str` を**入れ子の中も含めて引用符で囲む**形で書く。本文の `${式}` に埋め込む文字列とは、`str` の囲みと `Identity` の書き方が違う。

| 型 | `:vars` の形 | 例 |
| --- | --- | --- |
| `int`・`float`・`bool` | `${式}` と同じ。`float` は、整数の値に `.0` を付ける | `-3`・`2.5`・`3.0`・`true` |
| `str` | `"` で囲み、`\"`・`\\`・`\n`・`\t`・`\$` でエスケープする（language/01-lexical.md の 1.7 の文字列リテラルと同じ形） | `"お面"` |
| `list<T>` | `[要素, …]`。要素の `str` も囲む | `["お面", "札0"]` |
| `map<K, V>` | `map { キー: 値, … }`（挿入順。空は `map {}`）。キーの `str` も囲む | `map { "たこ焼き": 1 }` |
| `Option<T>` | `Some(値)`・`None` | `Some("a")` |
| `struct` | `型名 { フィールド: 値, … }`（宣言の順。モジュール名は付けない） | `Prize { name: "お面", hp: 3 }` |
| `enum` | `型名.バリアント`、引数があれば `型名.バリアント(値, …)` | `Mood.Run(2)` |
| `Identity` | `Identity { id: "案内人", name: "リオン" }` | |

### 終了コード

| 終了コード | 場合 |
| --- | --- |
| 0 | 台本が最後まで進んだ（`end`、またはラベルの終わり）。`:quit` でやめた |
| 1 | コンパイルエラー。ファイルを読めない。`--persistent`・`--texts` の誤り。実行時エラー。`:load` のセーブが壊れている。`input.integer`・`input.confirm` の入力の誤り。`--auto` の答えの誤り・入力の尽き。標準出力が閉じた |
| 2 | 引数の誤り（6.9） |

## 6.4 `yomi check`

```
yomi check <台本> [--root <ディレクトリ>] [--decls <宣言ファイル>]
```

台本を実行せずに検査する（ホストの Rust なし）。台本を集めてコンパイルし、診断（エラーと警告）を出す。

| 引数・オプション | 内容 |
| --- | --- |
| `<台本>` | 起動ファイル。必須 |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1） |
| `--decls <宣言ファイル>` | 宣言ファイル（`yomi decls` が書く JSON。host/02-registry.md の 2.8）から作った登録表で検査する。なければ、組み込みの登録表 |

- 診断は、標準エラーに 1 件 1 行（6.1 の書式）。続けて、標準出力に、問題がなければ「問題なし」の 1 行、あれば件数（エラー・警告）の 1 行。
- 終了コード：エラーが 1 件でもあれば 1、警告だけ・問題なしなら 0。
- 宣言ファイルを読めない・正しくないときは、標準エラーに書いて、終了コード 1（宣言ファイルの誤りのコードは、language/06-diagnostics.md の 6.9）。
- 検査には、language/07-migrate.md の検査（凍結スキーマのハッシュ・版の欠け・`migrate` の型検査・警告）と、未使用の変数の警告（language/06-diagnostics.md の 6.13）を含む。
- 台本の検査に開始ラベルは要らない。起動ファイルのモジュールに `start` がなくても、それだけではエラーにならない（どこからも呼ばれないラベルは、警告になる。language/06-diagnostics.md）。

例（`yomi check` の診断）：

```
$ yomi check game.yomi
game.yomi:4:3: error: unknown name 'gld' (did you mean: gold?)
check: 1 errors, 0 warnings
```

## 6.5 `yomi decls`

```
yomi decls
```

組み込みの登録表（標準パッケージ。6.1）の宣言ファイル（JSON）を、標準出力に書く。形式は host/02-registry.md の 2.8。同じ版なら、出力は毎回同じ。終了コード 0（標準出力に書けなければ 1）。

書いたファイルは、`yomi check --decls`・`yomi assign-ids --decls` に渡せる。ホスト独自のコマンドを持つ登録表の宣言ファイルは、ホスト（Rust）が `Registry::export_decls` で書き出す。

## 6.6 `yomi assign-ids`

```
yomi assign-ids <台本のパス…> [--root <ディレクトリ>] [--decls <宣言ファイル>]
                [--seed <数>] [--check] [--dry-run]
```

ID のない行に、自動の安定 ID を書き足す。規則（付ける行・位置・ID の形・冪等・コンパイルエラーのときの扱い・書き込みの手順・文字コードと改行コードの保持）は、host/05-texts.md の 5.10 に定める。ここには、CLI の面だけを書く。

| 引数・オプション | 内容 |
| --- | --- |
| `<台本のパス…>` | 台本のファイル、またはディレクトリ（下の `.yomi` すべて）。1 つ以上。書き換えるのは、指定したファイルだけ |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ。なければ、最初の台本のあるディレクトリ（6.1） |
| `--decls <宣言ファイル>` | 宣言ファイルから作った登録表で計画する。なければ、組み込みの登録表 |
| `--seed <数>` | ID の乱数の種。同じ台本・同じ種・同じ登録表なら、同じ ID。なければ、起動した時刻 |
| `--check` | 書かない。ID のない行を、標準エラーに `ファイル:行:桁: no stable ID (…)` の形で 1 件 1 行出し、件数を標準出力に出す。あれば終了コード 1、なければ 0。`--dry-run` と同時でも、書かない |
| `--dry-run` | 書かずに、付ける ID と位置を、標準出力に `ファイル:行:桁: will add #id (…)` の形で 1 件 1 行出し、件数を出す。終了コード 0 |

- 既定は、すべてのファイルの計画が立ってから、まとめて書く。付けた件数とファイル数を、標準出力に出す。付ける ID がなければ、何も書かず、その旨を標準出力に出して終了コード 0。
- 指定したファイルが、探すディレクトリの下になければ、エラー（終了コード 1）。指定したパスから `.yomi` が見つからないときも、エラー（終了コード 1）。
- コンパイルエラーがあるときは、何も書かず、診断を標準エラーに出して終了コード 1（`once` の選択肢の ID の欠落だけが原因のときを除く。5.10）。

## 6.7 `yomi texts`

本文の差し替え表（host/05-texts.md）の道具。

### `yomi texts check`

```
yomi texts check <台本> <表> [--root <ディレクトリ>]
```

台本と差し替え表を突き合わせる。規則は host/05-texts.md の 5.4（足りない訳・余った訳は警告、番号の誤りはエラー）。

- `<台本>` は起動ファイル、`<表>` は差し替え表のファイル（5.7）。`--root` は、モジュールを探すディレクトリ（6.1）。
- 結果を、標準エラーに 1 件 1 行（`<表>: <重大度>: <文面>`）で出し、標準出力に件数（エラー・警告）か、問題がないことを示す 1 行を出す。
- 終了コード：番号の誤りなどのエラーがあれば 1、警告だけ・問題なしなら 0。台本のコンパイルエラー（診断は標準エラー）・表を読めない・表の書式の誤り（5.7）も 1。警告の結果は、台本のコンパイルの警告ではなく、表の突き合わせの結果だけを出す。

### `yomi texts template`

```
yomi texts template <台本> [--root <ディレクトリ>] [--text-language <言語名>]
```

台本の、安定 ID つきの本文のすべて（identity の表示名と、訳せる引数を含む。5.4）について、原文を値にした差し替え表のひな形を、表のファイルの形式（5.7）で、標準出力に書く。そのまま `yomi run --texts` で使える（原文と同じ本文になる）。台本のコンパイルエラーがあるときは、診断を標準エラーに出して、終了コード 1。

| オプション | 内容 |
| --- | --- |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1） |
| `--text-language <言語名>` | ひな形の `@lang` の行に書く、**本文の言語名**（`en` など）。なければ、`@lang` の行の言語名が空になる |

### `--text-language` と `--lang` の違い

| オプション | 何の言語か | どこで使うか |
| --- | --- | --- |
| `texts template --text-language <言語名>` | 差し替え表が持つ**本文の言語名**。表の `@lang` の行に書かれる（5.7）。コアは、この名前の意味を決めない | `yomi texts template` だけ |
| `--lang <言語>` | `yomi` 自身の**表示言語**（`en`・`ja`）。診断やメッセージの文面の言語 | どのサブコマンドでも（6.1） |

たとえば、英訳の表を作るときは、`yomi texts template game.yomi --text-language en > game.en.texts` と書く。表の言語名は `en` になる。`yomi --lang ja texts template game.yomi --text-language en` なら、メッセージ（表示言語）は日本語で、表の言語名は `en` のまま。`--lang` は、表の中身にも、本文の表示にも、影響しない。

## 6.8 `yomi codes`

```
yomi codes [--json] [--packages]
```

コード（診断・実行時エラー・ロードエラー・差し替え表・宣言ファイルのコード）の一覧を、標準出力に書く。形式は language/06-diagnostics.md の 6.11。終了コード 0。

- 既定：1 コードを 1 行に、TAB 区切りで、組・コード・重大度・引数の名前（`,` 区切り）・表示言語での 1 行の説明。
- `--json`：表示言語によらない、機械可読の形。
- `--packages`：上の一覧に続けて、コマンドのエラーコード（標準パッケージのもの、続けてコアのもの）を足す。組の列は `package`・`core`、重大度は `error`。コードは `パッケージ名.エラー名`、引数の名前と説明は、言語のコードと同じ列に並ぶ（説明の文面は `std-error-<コード>`。host/02-registry.md の 2.4）。`--json` と合わせると、項目ごとに `kind`（`language`・`package`・`core`）を持つ形になる（language/06-diagnostics.md の 6.11）。`--packages` を付けないときの出力は、変わらない。

## 6.9 終了コードの一覧

| 終了コード | 意味 |
| --- | --- |
| 0 | 成功。`check` と `texts check` は、エラーがない（警告があってもよい）。`test` は、6.17 の失敗の条件に当たらない。`assign-ids --check` は、ID のない行がない。`fmt --check` は、整形が要るファイルがない |
| 1 | 失敗。エラーの診断がある・ファイルを読めない・実行時エラー・入力の誤り、など。`assign-ids --check` は、ID のない行がある。`fmt --check` は、整形が要るファイルがある |
| 2 | 引数の誤り（必須の引数がない・知らないオプション・サブコマンドがない）。使い方を標準エラーに出す |

- 標準出力・標準エラーへの書き込みの失敗（パイプが閉じたなど）は、書き込んだ側の終了コードを 1 にする。

## 6.10 `yomi repl`

```
yomi repl [<台本>] [--root <ディレクトリ>] [--seed <数>] [--persistent <ファイル>] [--lenient]
```

対話の実行環境（REPL）を始める。式の評価・文と宣言の実行・台本の行の試し打ちができる。規則（入力の判定・複数行・対話コマンド・停止の流れ・エラー表示・`:repl`）は、host/07-repl.md が定める。ここには、CLI の面だけを書く。

| 引数・オプション | 内容 |
| --- | --- |
| `<台本>` | 起動ファイル。なければ、台本のない空の環境で始める |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1）。`<台本>` があるときだけ意味を持つ |
| `--seed <数>` | 乱数の種（0 以上の整数）。なければ、起動した時刻から決める |
| `--persistent <ファイル>` | 永続データ（host/04-save.md の 4.5）を、**読むだけ**。書き戻さない。ファイルがなければ、新規から始める |
| `--lenient` | ロードの方針を `Lenient` にする（6.3 と同じ。`--persistent` の読み込みと `:load` に効く） |

- 診断・エラー・警告は標準エラー、式の値・`let` の表示・`:vars` などの結果は標準出力（6.1）。標準入力が端末のときだけ、プロンプト（`yomi> `・`...> `）を標準出力に出す。
- 終了コード：`:exit`・`:quit`・標準入力の終わりで 0。台本のコンパイルエラー・ファイルを読めない・`--persistent` の誤りは 1（REPL は始めない）。引数の誤りは 2（6.9）。入力の誤り（診断・実行時エラー）では終わらない。

## 6.11 `yomi mcp`

```
yomi mcp
```

MCP（Model Context Protocol）のサーバーを、標準入出力で動かす。クライアントが閉じると終わる。オプションはない。ビルドの feature `mcp`（既定で有効）を切ると、このサブコマンドはない。

- **表示言語**：MCP には言語を送る手段がないので、`--lang` は効かず、環境変数（`YOMI_CLI_LANG`・`LC_ALL`・`LC_MESSAGES`・`LANG`）で決まる。ツールの説明と引数の説明は、`YOMI_MCP_LOCALIZE_SCHEMA=true` のときだけ訳される（既定は英語）。結果の文面は、いつも表示言語になる。
- **ツール**：

| ツール | 内容 |
| --- | --- |
| `check` | 台本を実行せずに検査して、診断（モジュール・ファイル・行・桁・重大度・コード・文面）と件数を返す。台本は、`source`（起動ファイル。モジュール名は `main`）と `modules`（ほかのモジュール）で渡すか、`path`（このマシン上のファイル）と `root` で渡す。`path` と `source` は、どちらか一方だけ。`decls`（このマシン上の宣言ファイル。6.5 の出力）を渡すと、組み込みの登録表の代わりに、その登録表で検査する（6.4 の `--decls` と同じ） |
| `format` | 台本を整形して、結果の文字列を返す。台本は、`check` と同じく `source`・`modules` で渡し、`source` を整形する。構文エラーのときは、診断を返す |
| `reserved_words` | 予約語（語・種別・ブロックを開くか）と、文脈つきの語（語・位置）の一覧。language/01-lexical.md の 1.6 と同じ |
| `diagnostic_codes` | コードの一覧（組・コード・重大度・引数の名前・説明）。`packages` を真にすると、コマンドのエラーコードも返す（6.8 と同じ） |
| `spec` | 仕様書（この文書を含む `spec/` の Markdown）と、チュートリアル（`guide/` の Markdown）を返す。`part`（`language/01-lexical`・`guide/01-getting-started` など）を省くと、文書の名前と見出しの一覧だけ返す |
| `run` | 台本を隔離して、`--auto`（6.3.3）で実行する |
| `test` | 台本の分岐を隔離して探索し（6.17）、報告を返す |

- **`run` の隔離**：自分自身を子プロセス（`yomi run --auto`）として、一時ディレクトリの中で起動する。台本は `source`（`main`）と `modules` で渡し、`input` が標準入力（選択と入力の応答）になる。`seed`・`start` は、6.3 の同名のオプションと同じ。上限は次のとおり。

| 上限 | 値 | 超えたとき |
| --- | --- | --- |
| 実行の時間 | 5 秒 | 子プロセスを殺す（結果の `timed_out` が真） |
| 台本と入力の合計 | 1 MiB | 実行せずに、引数の誤りにする |
| 標準出力・標準エラー（それぞれ） | 1 MiB | 超えた分は捨てる（`truncated` が真） |
| メモリ（unix は仮想アドレス空間、Windows はコミット量） | 1 GiB | 確保が失敗する（子プロセスが失敗し、終了コードが 0 でない） |

- 子プロセスは、専用のプロセスグループ（unix）／Job（Windows）に入れる。子が終わったとき、または時間切れで殺したときに、孫プロセスも終わらせる。macOS は仮想アドレス空間の上限を守らせないことがあり、その場合は上限なしで動く。
- 子プロセスの環境変数は空。モジュール名は、英数字と `_` を `::` で区切った形だけ。`main` がなければ、引数の誤り。
- 結果は、`stdout`・`stderr`・`exit_code`（殺したときは `null`）・`timed_out`・`truncated`。

- **`check` の `decls`**：宣言ファイルを読めない、または形が違うときは、引数の誤り（診断は返さない）。

- **`test`**：台本は、`run` と同じく `source`（`main`）と `modules` で渡す（`path` は受けない）。ほかの引数は、6.17 の同名のオプションと同じ：`start`・`seeds`（既定 1）・`max_states`（既定 10000、上限 100000。超えると引数の誤り）・`max_steps`・`events`（イベントの名前 → データの配列。`--event` を、名前ごとにデータの数だけ繰り返したものと同じ。名前が空、または `=` を含むときは引数の誤り）。`run` と同じ隔離（上の表。ただし実行の時間の上限は 10 秒）で、`yomi test --json`（6.17）を動かす。golden は使わない（比べず、書かない）。結果は、`report`（6.17 の JSON から `golden` を除いたもの。台本のコンパイルエラーなど、報告を出せないときは `null`）・`stderr`（診断。表示言語）・`exit_code`（6.17 の終了コード。殺したときは `null`）・`timed_out`・`truncated`（`run` と同じ）。エラーの経路・答えられない停止点があるときは、`exit_code` が 1 で、`report` はある。
- **`spec` の `guide/`**：`guide/README` と各章の文書を、`spec/` の文書と同じ形で返す。本文は日本語。

## 6.12 `yomi lsp`

```
yomi lsp [--decls <ファイル>]
```

エディタ向けの Language Server（Language Server Protocol）を、標準入出力で動かす。クライアントが終了を求めるか、接続が閉じると終わる。ビルドの feature `lsp`（既定で有効）を切ると、このサブコマンドはない。

| オプション | 内容 |
| --- | --- |
| `--decls <ファイル>` | ホストの登録表の宣言ファイル（host/02-registry.md の 2.8）。なければ、組み込みの登録表 |

- **台本の範囲**：クライアントが知らせたワークスペースのルート（なければ、最初に開いたファイルのあるディレクトリ）の下の `.yomi` すべてを、1 つのまとまりとして解析する。モジュールの名前は、そのルートからの相対パスで決まる（6.1 の「台本の集め方」と同じ規則）。エディタで開いている内容は、ディスクの内容より優先する。
- **同期**：テキストの同期は全文。桁は UTF-16 の符号単位（LSP の既定）で、台本の桁（文字の数）と相互に変換する。
- **表示言語**：`--lang` は効かず、環境変数（`YOMI_CLI_LANG`・`LC_ALL`・`LC_MESSAGES`・`LANG`）で決まる。診断の文面は、表示言語になる。
- **機能**：

| 機能 | 内容 |
| --- | --- |
| 診断（`textDocument/publishDiagnostics`） | 開く・変える・保存・閉じるたびに、全ファイルの診断を送り直す（診断のないファイルは空の並びを送り、前の診断を消す）。コードは `diagnostic_codes`（language/06-diagnostics.md）のコード、`source` は `yomi` |
| 補完（`textDocument/completion`） | `@` の後ろはコマンド、`jump`・`call` の後ろはラベル、`import` の後ろはパッケージとモジュール、`名前.` の後ろはパッケージのコマンド・変数と、型が分かる値（引数・`let`・`for`・`match` の束縛・変数。型を書かなくても、コンパイラが決めた型を使う。`a.b.` のように、フィールドをたどれる）の `struct` のフィールドと `list`・`map` のメソッド、`enum` のバリアント、`struct` のフィールド、ほかのモジュールの宣言。それ以外は、予約語・文脈つきの語（language/01-lexical.md の 1.6）、パッケージ名、モジュールの宣言、いまのラベルの引数とローカル変数。トリガー文字は `.` と `@` |
| 定義へ移動（`textDocument/definition`） | ラベル・関数・変数・identity・型・バリアント・フィールド・引数・ローカル変数の宣言（ほかのモジュールのものも） |
| 参照（`textDocument/references`） | 上と同じ名前の使われている場所（`includeDeclaration` で宣言も） |
| 名前の変更（`textDocument/prepareRename`・`textDocument/rename`） | 宣言と、使われているすべての場所（別のファイルも）を書き換える編集を返す。新しい名前は、識別子で、予約語でないこと。名前の上でなければ、誤り |
| 同じ名前の強調（`textDocument/documentHighlight`） | 同じファイルの中の、宣言と使われている場所 |
| 整形（`textDocument/formatting`） | ファイル全体を、6.13 と同じ規則で整形する編集を返す。構文エラーのときは、編集を返さない |
| 宣言の木（`textDocument/documentSymbol`） | ファイルの最上位の宣言（ラベル・関数・変数・identity・型）。型のバリアントとフィールドは、その子 |
| ワークスペースの検索（`workspace/symbol`） | 最上位の宣言を、名前の一部（大文字小文字を区別しない）で探す |
| ホバー（`textDocument/hover`） | 宣言の 1 行の説明（`label start(n: int)` など。ローカル変数は、コンパイラが決めた型つき）、コマンドと変数の説明（登録表の説明つき）、予約語の種別 |

- 参照・定義は、名前の宣言を位置で結ぶ。`値.フィールド`・`値.メソッド()`・`値.フィールド = 式` の `値` が変数（ローカル変数・モジュールの変数）か identity なら、その参照になる（`import` した別名より先に見る）。`別名.型名.バリアント` は、型とバリアントの参照になる。
- 型に依存する名前（`値.フィールド` のフィールド・メソッド）と、ほかのモジュールの `enum` のバリアントをパターンに書いたもの（照合する値の型で決まる）の参照は、見つけない。壊れた台本では、解析器が読めた範囲だけが対象になる。

## 6.13 `yomi fmt`

```
yomi fmt <台本のパス…> [--root <ディレクトリ>] [--check] [--stdout]
yomi fmt - --stdin-path <パス> [--root <ディレクトリ>]
```

台本を、標準の書式（language/08-format.md）に整形する。設定はない。

| 引数・オプション | 内容 |
| --- | --- |
| `<台本のパス…>` | 台本のファイル、またはディレクトリ（下の `.yomi` すべて。`schema/` の下は除く）。1 つ以上。書き換えるのは、指定したファイルだけ |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1）。identity の解決に使う |
| `--check` | 書かない。整形が要るファイルを、標準エラーに `ファイル: needs formatting` の形で 1 件 1 行出し、件数を標準出力に出す。あれば終了コード 1、なければ 0 |
| `--stdout` | 書き換えずに、整形した結果を標準出力に出す（台本のパスは 1 つだけ） |
| `-` と `--stdin-path <パス>` | 標準入力を、そのパスのファイルの内容として整形し、結果を標準出力に出す（エディタ向け） |

- 既定は、整形が要るファイルだけを、書き換える。結果が元と同じファイルは、触らない（更新時刻も変えない）。書き換えた件数を、標準出力に出す。
- 書き込みの手順・文字コード・BOM・改行コードの保持は、`assign-ids`（host/05-texts.md の 5.10）と同じである。
- 構文エラーのあるファイルは、書かずに、診断を標準エラーに出して、終了コード 1。ほかのファイルは続ける（すべてのファイルの結果が出たあとに、まとめて書く。1 つでも失敗があれば、何も書かない）。
- `schema/` の下のファイルは、整形しない（language/08-format.md の 8.7）。パスで指定しても、書かずに、その旨を標準エラーに出す（エラーにはしない）。
- 整形は、`assign-ids` のあとの台本にも、前の台本にも、使える。安定 ID は、変えない。
- コアの関数 `format_source(modules, module) -> Result<String, FormatError>`：`modules`（名前とソースの組）の `module` を整形して返す。ソースの改行コード（`\n`・`\r\n`）と先頭の BOM は、そのまま保つ。`migrations` は、8.7 の形に整形する。構文エラーのときは `FormatError::Syntax(診断)`、結果が元と同じ意味と確かめられないときは `FormatError::Unverified`。

## 6.14 `yomi schema`

### `yomi schema freeze`

```
yomi schema freeze [--root <ディレクトリ>] [--decls <宣言ファイル>]
```

現在の台本のスキーマ（language/07-migrate.md の 7.1）を、`<探すディレクトリ>/schema/v<版>.yomi` に書く（7.3）。版は、台本の現在の版（`migrations.yomi` の `migrate N` の最大の `N`。なければ 1）。リリースのときに実行する。

- コンパイルエラーがあるときは、何も書かず、診断を標準エラーに出して終了コード 1。
- 書き先がすでにあるときは、書き換えない。内容が同じなら「最新」と出して終了コード 0。違えば、エラー（終了コード 1。凍結のあとにスキーマが変わったので、`migrate` を足して版を上げる）。
- `schema/` がなければ作る。出力は、7.3 の並び・ハッシュのとおり（LF。UTF-8）。書いたパスを、標準出力に出す。

### `yomi schema extract`

```
yomi schema extract <セーブ> [<永続データ>] [--out <ファイル>]
```

セーブ（と永続データ）に埋め込まれたスキーマ（host/04-save.md の 4.3）から、凍結スキーマの内容を復元する。凍結を忘れたリリースの救済に使う。

- セーブは `save var`、永続データは `persistent var` を復元する。両方を渡すと、1 つのファイルにまとめる（2 つのスキーマの版が違えば、エラー）。ホストが宣言した変数は、復元しない。
- マジック・形式の版数・チェックサムが正しくないファイルと、形式の版数が 12 より古いセーブは、エラー（終了コード 1）。
- 出力は、7.3 の形（ヘッダの版は、セーブのスキーマの版。ハッシュも計算して書く）。`--out` がなければ標準出力、あれば、そのファイル（すでにあるときは、エラー）。

### コアの関数

- `frozen_schema(&Program) -> String`：`schema freeze` が書く内容（7.3 の並び・ハッシュ）。
- `extract_schema(セーブ, 永続データ) -> Result<String, ExtractError>`：`schema extract` の内容。`ExtractError` は、読めないバイト列（`Load`）・版の食い違い（`VersionsDiffer`）・どちらも渡されない（`NothingGiven`）。
- `migrate_template(&Program, 凍結スキーマの内容, 版) -> Result<Option<String>, Vec<Diagnostic>>`：`migrate-init` の雛形。変数に差がなければ `None`。

## 6.15 `yomi migrate-init`

```
yomi migrate-init [--root <ディレクトリ>] [--decls <宣言ファイル>] [--write]
```

最新の凍結スキーマ（`schema/` の最大の版 `K`）と、現在の台本のスキーマの差から、`migrate K+1` の雛形を作る。

- 雛形は、すべて**コメントの行**（`// …`）で作る。自動では適用しない。使うときは、人がコメントを外して直す。
  - 消えた変数と、追加された変数で、型が同じもの：`// rename v2::game.favor -> game.affection`（候補は、すべて出す）。
  - 型が変わった変数（`struct`・`enum` の宣言が変わったものを含む）：`// convert v2::game.hp: int -> float = |v| v`（旧い型は `v<K>::`、新しい型は接頭辞なし）。
- 差がなければ、何も出さず、その旨を標準出力に出して、終了コード 0。
- 既定は、雛形を標準出力に出す。`--write` を付けると、`migrations.yomi` の末尾に書き足す（なければ作る。`min_save_version` は書かない）。書き足すと、台本の現在の版が `K+1` になる。
- `migrate K+1` がすでにあるとき、凍結スキーマがないとき、台本にコンパイルエラーがあるときは、エラー（終了コード 1）。

## 6.16 `yomi release`

```
yomi release [--root <ディレクトリ>] [--decls <宣言ファイル>] [--saves <パス>…] [--dry-run]
```

リリースの前の手順を、1 つにまとめる。厳格な検査・整形の確認・セーブのロードの確認をして、通れば、現在のスキーマを凍結する（6.14 の `schema freeze`）。台本は書き換えない（書くのは、凍結スキーマのファイルだけ）。

| 引数・オプション | 内容 |
| --- | --- |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1。なければ、カレントディレクトリ） |
| `--decls <宣言ファイル>` | 宣言ファイルから作った登録表で検査する。なければ、組み込みの登録表 |
| `--saves <パス>…` | ロードを確かめるセーブ・永続データのファイル、またはディレクトリ（ディレクトリは、下の**すべてのファイル**。マジックが `YOMS` ならセーブ、`YOMP` なら永続データとして読む。どちらでもないファイルは、エラー）。なければ、ロードの確認は行わない。`--decls` とは同時に使えない（宣言ファイルの登録表は、ロードできない。host/04-save.md の 4.6）。引数の誤りで、終了コード 2 |
| `--dry-run` | 検査だけ行い、凍結スキーマは書かない。書くはずのパスを、標準出力に出す |

次の順に進み、どこかで失敗したら、あとの段階には進まず、何も書かない（終了コード 1）。

1. **厳格な検査**：台本を集めてコンパイルする（`check` と同じ。language/07-migrate.md の検査を含む）。エラーに加えて、**警告もすべてエラーとして扱う**（未使用の変数・呼ばれないラベル・`unhandled_type_change`・`schema_changed_since_freeze` など）。診断は標準エラーに出す（6.1 の書式。警告も `error` として数える）。
2. **安定 ID の検査**：安定 ID のない行があれば、エラー（`assign-ids --check` と同じ書式で、標準エラーに出す）。
2a. **整形の検査**：整形が要る台本があれば、エラー（`fmt --check` と同じ書式で、標準エラーに出す。対象は、探すディレクトリの下の台本すべて。`schema/` の下は除く）。
3. **`migrations` の検査**：版の連番・`migrate` の欠け・凍結スキーマとの合致（language/07-migrate.md の 7.4・7.5）。1 の検査に含まれるので、ここでは新しい診断を足さない。台本の現在の版 `N` の凍結スキーマ `schema/vN.yomi` がすでにあるときは、内容が現在のスキーマと同じでなければ、エラー（凍結のあとにスキーマが変わった。`migrate` を足して版を上げる）。
3a. **セーブのロードの確認**（`--saves` があるとき）：指定したファイルを、**`Strict`**（host/04-save.md の 4.6）で、現在の台本にロードする。セーブは `Vm::load`、永続データは `load_persistent` と同じ。`migrate` は、現在の台本のものを使う。1 つでも `LoadError` になれば、ファイル名とエラー（`yomi run` の `:load` と同じ文面）を、標準エラーに出して、エラー（すべてのファイルを試してから、まとめて報告する）。`LoadReport` の警告（位置の解決のしかた・規則の版の変化など）は、エラーにしない。ロードに成功した件数を、標準出力に出す。
4. **凍結**：`schema/vN.yomi` を書く（`schema freeze` と同じ。内容が同じ既存のファイルは、書き換えない）。書いたパス（または「最新」）を、標準出力に出す。

- 標準出力の最後に、「リリースの準備ができました」の 1 行（`--dry-run` では「検査に通りました（凍結は書いていません）」）。
- 終了コード：すべて通れば 0、そうでなければ 1。引数の誤りは 2（6.9）。
- `schema freeze` と `assign-ids --check` と `check` は、それぞれ単独でも使える。`release` は、これらに `fmt --check` とセーブのロードの確認を加えて、この順に行う。

## 6.17 `yomi test`

```
yomi test <台本> [--root <ディレクトリ>] [--start <ラベル>] [--seeds <数>] [--max-states <数>]
          [--max-steps <数>] [--event <名前=データ>]... [--golden <ディレクトリ>] [--update] [--require-coverage] [--json]
```

台本の分岐を探索し（host/08-test.md）、経路ごとの表示を **golden** のファイルと比べる。登録表は、組み込みの登録表（6.1）で、標準パッケージのコマンドの答えは `test_answers`（host/08-test.md の 8.4）を使う。ただし、`yomi run --auto` で入力できない答えは、試さない：`answer` の 1 行に書けない文字列（改行を含む）と、`input.text` で `default` が空でないときの空の文字列（空の行は `default` になる）。

| 引数・オプション | 内容 |
| --- | --- |
| `<台本>` | 起動ファイル。必須 |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1） |
| `--start <ラベル>` | 開始するラベル（6.3 と同じ） |
| `--seeds <数>` | 乱数の種 `0`〜`数 - 1` で探索する（1 以上）。既定は 1（種 `0` だけ） |
| `--max-states <数>` | 調べる状態の数の上限（host/08-test.md の 8.1）。既定は 100000 |
| `--max-steps <数>` | 1 回の `run` の命令数の上限（host/01-execution.md の 1.9）。既定は `VmConfig` の既定 |
| `--event <名前=データ>` | `event.wait` で試すイベントのデータ。繰り返し指定できる。最初の `=` で名前とデータに分ける（データに `=` を含んでよい）。同じ名前を何度も指定すると、その数だけ候補になる（host/08-test.md の 8.4） |
| `--golden <ディレクトリ>` | golden のディレクトリ。既定は、探すディレクトリの下の `tests/golden` |
| `--update` | 比べずに、golden を書き直す（下） |
| `--require-coverage` | 着かなかった停止点・選ばれなかった選択肢・入らなかったラベルがあるとき、または打ち切ったときも、失敗にする |
| `--json` | 結果を、JSON で標準出力に出す（下） |

### 進み方

1. 台本を集めてコンパイルする（`check` と同じ）。警告は標準エラーに出す。エラーがあれば、終了コード 1。
2. 探索する。
3. golden のディレクトリがあれば、比べる（`--update` では、書き直す）。なければ、比べずに、その旨を出す。
4. 結果を出す。

### golden のファイル

経路（host/08-test.md の 8.3）ごとに 1 つ、`<経路の名前>.golden` のファイル。UTF-8・改行は LF。

```
yomi-golden 1
seed 0
answer #wake
answer 3
answer approved 承認済み
---
（表示）
```

- 1 行目は、形式の印と版。`seed` の行は、種。
- `answer` の行は、入力を読む停止点（選択・`input.*`・`event.wait`）ごとに 1 行、順に並ぶ。`answer` と空白 1 つのあとに、`yomi run --auto` に渡す 1 行（6.3.2・6.3.3）を書く。選択は、選んだ選択肢に安定 ID があれば `#id`、なければ番号（1 から）。`input.integer` は整数、`input.confirm` は `y`・`n`、`input.text` は文字列そのまま（空の文字列は、`answer` のあとの空白の後ろが空）、`event.wait` は `名前 データ`（データが空なら `名前`）。`TimedOut` は、`answer` のあとが空。
- `---` の後ろは、記録した種と答えで `yomi run --auto --seed <種>` を動かしたときの標準出力と同じ。表示言語（`--lang`）は、`en` に固定する。
- 比べる：
  - ディレクトリの中の `.golden` ごとに、記録した種と答えで動かし、表示を比べる。違えば、ファイル名と、最初に違う行（前後 3 行）を出して、**不一致**とする。
  - 答えが通らない（`--auto` なら終了コード 1 になる）ときは、**古い golden** とする。
  - 探索の経路のうち、同じ名前の golden がないものは、**新しい経路**として知らせる（失敗にしない）。
  - golden のうち、探索の経路にない名前のものは、比べたうえで、**探索に現れない golden** として知らせる（失敗にしない）。
- `--update`：比べずに、探索の経路ごとに golden を書く（ディレクトリがなければ作る）。内容が同じファイルは、書き換えない。経路にない `.golden` は消す。書いた・消したファイルの数を、標準出力に出す。`.golden` でないファイルには触れない。

### 出力

- 標準出力に、調べた状態の数・経路の数を 1 行ずつ。打ち切ったときは、その旨。
- エラーの経路ごとに、種・答えの列（`answer` の行と同じ形を `, ` でつないだもの）・エラー（`yomi run` と同じ文面）。答えられない停止点の経路ごとに、種・答えの列・停止点の名前とコマンド。
- 着かなかった停止点・選ばれなかった選択肢・入らなかったラベルの一覧（名前は host/08-test.md の 8.2）。
- golden の不一致・古い golden・新しい経路・探索に現れない golden の一覧。
- `--json` のときは、上の代わりに、次の形の JSON を 1 つ出す（診断・知らせは、標準エラーのまま）。答えの列は、`answer` の行の、`answer ` の後ろの文字列の配列。

```json
{
  "states": 120,
  "truncated": false,
  "paths": [{ "name": "wake", "seed": 0, "answers": ["#wake"] }],
  "errors": [{ "seed": 0, "answers": ["#sleep"], "code": "key_not_found", "args": { "key": "x" },
               "module": "main", "label": "bad_end", "line": 12 }],
  "unanswered": [{ "seed": 0, "answers": [], "stop": "main.start#ask", "command": "game.ask" }],
  "unreached_stops": ["main.secret#s1"],
  "unchosen_options": [],
  "unreached_labels": ["main.secret"],
  "golden": { "mismatched": [], "stale": [], "new": ["wake"], "unexplored": [], "written": [], "removed": [] }
}
```

### 終了コード

| 終了コード | 場合 |
| --- | --- |
| 0 | 下の 1 に当たらない |
| 1 | コンパイルエラー。ファイルを読めない・書けない。エラーの経路・答えられない停止点がある。golden の不一致・古い golden がある。`--require-coverage` で、着かなかった停止点・選ばれなかった選択肢・入らなかったラベルがある、または打ち切った |
| 2 | 引数の誤り（6.9） |

- `--update` でも、エラーの経路・答えられない停止点があれば、golden を書いたうえで、終了コード 1。

## 6.18 `yomi debug`

```
yomi debug <台本> [--root <ディレクトリ>] [--start <ラベル>] [--seed <数>] [--texts <表>]
```

台本を、ソースの行の単位で止めながら実行する、対話の道具である（コアの約束は host/09-debug.md）。登録表は、組み込みの登録表（6.1）。

| 引数・オプション | 内容 |
| --- | --- |
| `<台本>` | 起動ファイル。必須 |
| `--root <ディレクトリ>` | モジュールを探すディレクトリ（6.1） |
| `--start <ラベル>` | 開始するラベル（6.3 と同じ） |
| `--seed <数>` | 乱数の種（6.3 と同じ） |
| `--texts <表>` | 本文の差し替え表のファイル（6.3 と同じ） |

### 起動

1. 台本を集めてコンパイルする。警告は標準エラーに出す。エラーがあるときは、診断を標準エラーに出し、実行せずに終了コード 1。
2. `--texts` を読む。読めない・設定できないときは、標準エラーに書いて、終了コード 1。
3. 開始ラベルの**最初の行で止まる**（まだ何も実行していない）。

### 止まり方と入力

実行は、次の 2 つの形で止まる。どちらも、止まったあとの表示は標準出力へ、案内・誤りは標準エラーへ出す。

| 形 | 場合 | 読む入力 |
| --- | --- | --- |
| 一時停止 | ブレークポイント・ステップで、行の手前で止まった | デバッガのコマンド（下。`:` をつけない） |
| 停止点 | 台本の停止点（6.3.1）に着いた | 停止点の答え（6.3.2 と同じ）。`:` で始まる行は、デバッガのコマンド（下。`:` をつけて書く） |

- 標準入力が端末のときは、入力の前に、プロンプト `(yomi) ` を標準出力に出す。端末でないときは、出さない。
- 一時停止のときの空行は、**直前の動かすコマンド**（`step`・`next`・`finish`・`continue`）をもう一度行う。まだなければ、`step`。
- 標準入力の終わり（EOF）：一時停止では、`quit` と同じ。停止点では、6.3.2 と同じ（答えは既定値、本文は進む）。
- 呼び出しから戻ったあとの、呼び出した行の行イベント（host/09-debug.md の 9.2）で、直前に表示した止まった位置と、モジュール・行・名前・呼び出しの深さが同じときは、ブレークポイントがなければ、表示せずに、同じコマンドで続ける（`next` で、呼び出しのある行を、2 度表示しない）。
- 停止点では、答えのあと、**直前に選んだ動かすコマンドの続き**として、実行を続ける。`step` なら、停止点のあとの次の行で止まる。`continue` なら、次のブレークポイントか停止点まで進む。動かすコマンドを、停止点で `:next` のように書くと、答えのあとの続け方を変える（その場では動かず、同じ停止点で答えを待つ）。
- 停止点の表示は、`yomi run` と同じ（6.3.1）。

### 止まったときの表示

一時停止で止まるたびに、標準出力へ次の 2 行を出す。

```
-> main:12 (start)
12 | 　　@game.attack(power)
```

1 行目は、モジュール名・行番号・ラベルまたは `fn` の名前。2 行目は、その行の原文（行番号と `|` で区切る）。差し替え表を設定していても、原文を出す。

### コマンド

コマンドと引数は、空白で区切る。略称を使える。

| コマンド | 略称 | 動作 |
| --- | --- | --- |
| `step` | `s` | 次の行へ進む。`fn`・ラムダ式の中へも入る（`StepMode::In`） |
| `next` | `n` | 次の行へ進む。呼び出しの中は飛ばす（`Over`） |
| `finish` | `fin` | いまの呼び出しから戻るまで進む（`Out`）。いちばん外側のフレームでは、`continue` と同じ |
| `continue` | `c` | 次のブレークポイント・停止点・終わりまで進む |
| `break <行>`<br>`break <モジュール>:<行>` | `b` | ブレークポイントを置く。モジュールを省くと、いま選んでいるフレームのモジュール。番号（1 から、使い回さない）と、置いた位置を、1 行で出す。その行に実行できる命令がなければ、次の、実行できる行に寄せて、寄せたことを知らせる（host/09-debug.md の 9.7）。寄せる先がなければ、標準エラーに知らせて、置かない |
| `delete [<番号>]` | `d` | その番号のブレークポイントを消す。番号を省くと、すべて消す |
| `breaks` | | ブレークポイントを、`番号 モジュール:行` で 1 行ずつ出す。なければ、その旨を 1 行 |
| `bt` | `where` | 呼び出しの並びを、いちばん内側から、`#0 モジュール:行 (名前)` の形で 1 行ずつ出す。選んでいるフレームには、行の先頭に `*` を付ける |
| `frame <番号>` | `f` | フレームを選ぶ。選んだフレームの、止まったときの表示（上の 2 行）を出す。範囲の外は、標準エラーに知らせる |
| `up` | | 1 つ外側のフレームを選ぶ（`frame` と同じ表示）。いちばん外側なら、標準エラーに知らせる |
| `down` | | 1 つ内側のフレームを選ぶ。いちばん内側なら、標準エラーに知らせる |
| `vars` | `v` | 選んでいるフレームのローカル変数を、続けて、モジュール変数・ホストの変数を、`名前 = 値` で 1 行ずつ出す（値の形は、`:vars` と同じ。6.3.5 の「`:vars` の値の形」） |
| `print <名前>` | `p` | 変数 1 つを、`名前 = 値` で出す。選んでいるフレームのローカル変数を先に探し、なければ、モジュール変数・ホストの変数。なければ、標準エラーに知らせる。式は書けない（名前だけ） |
| `list [<行数>]` | `l` | 選んでいるフレームの行の前後（既定は前後 5 行）の原文を、`行番号 | 原文` で出す。いまの行には `=>`、ブレークポイントのある行には `*` を、行番号の前に付ける |
| `quit` | `q` | 実行をやめる。終了コード 0 |

- 動かすコマンドを受けたら、実行を続ける。次に止まるか、停止点か、終わりに着くまで、戻らない。
- 知らないコマンド・引数の誤りは、標準エラーに知らせて、同じ場所で待つ（使えるコマンドの一覧を添える）。
- `frame`・`up`・`down` で選んだフレームは、動かすコマンドの実行で、いちばん内側に戻る。
- 停止点で選べるフレームは、一時停止のときと同じ。停止点に着いたあとの `bt` の 0 番目の行は、その停止点の行（host/09-debug.md の 9.5）。
- 非対応：式の評価・条件つきブレーク・変数の書き換え・セーブ・読み込み・ロールバック・`reload`・`--watch`・`--persistent`。

### 終わり

台本が最後まで進んだら、終わりを示す 1 行（`(end)`）を標準出力に出して、終了コード 0。

### 終了コード

| 終了コード | 場合 |
| --- | --- |
| 0 | 台本が最後まで進んだ。`quit`・一時停止での EOF でやめた |
| 1 | コンパイルエラー。ファイルを読めない。`--texts` の誤り。実行時エラー。`input.integer`・`input.confirm` の入力の誤り。標準出力が閉じた |
| 2 | 引数の誤り（6.9） |

## 6.19 `yomi dap`

```
yomi dap
```

Debug Adapter Protocol（DAP）のサーバーを、標準入出力で動かす。エディタ（VS Code など）のデバッグの画面から、台本をステップ実行できる。メッセージの枠は DAP の基本の形（`Content-Length` ヘッダーと JSON）。標準出力には DAP のメッセージだけを出し、ログ・診断は標準エラーに出す。台本のデバッグの働きは `yomi debug`（6.18）と同じで、コアは host/09-debug.md。登録表は、組み込みの登録表（6.1）。

引数はない。台本・モジュールの場所・開始ラベルなどは、`launch` の引数で受ける。クライアントが `disconnect` を送るか、標準入力が閉じたら終了する。終了コードは、正常に終わったら 0、メッセージの枠・JSON の誤りや標準入出力の失敗で続けられないときは 1。引数を渡したときは、引数の誤り（6.9）。

### 対応するリクエスト

| リクエスト | 動作 |
| --- | --- |
| `initialize` | 次の機能を返す：`supportsConfigurationDoneRequest`。ほかは持たない（条件つきブレークポイント・式の評価の `supportsEvaluateForHovers` など）。`initialized` イベントは、応答のあとに送る |
| `launch` | 引数は下の表。台本を集めてコンパイルし、VM を作る。失敗は、診断を標準エラーに書き、応答を失敗にして、`terminated` を送る |
| `setBreakpoints` | `source.path` のファイルのブレークポイントを、渡された行で置き換える。行に実行できる命令がなければ、次の実行できる行へ寄せ、応答の `line` を寄せた行にする（host/09-debug.md の 9.7）。寄せる先がなければ `verified: false` と `message`。`condition`・`hitCondition`・`logMessage` のあるものは、`verified: false` と `message` で、置かない。台本のファイルでない `source.path` は、すべて `verified: false` |
| `setExceptionBreakpoints` | 空の応答（実行時エラーでは止まらない） |
| `configurationDone` | 実行を始める。`stopOnEntry`（既定は真）なら、最初の行で止まる |
| `threads` | スレッドは 1 つ（`id` 1、名前 `main`） |
| `stackTrace` | `call_stack`（host/09-debug.md の 9.5）。フレームの `id` は 0 から（内側が 0）。`source` は、モジュールのファイルの `path` と `name`。`name` はラベルまたは `fn` の名前。`line` は 1 始まり（`linesStartAt1` が偽でも、1 始まりに揃える） |
| `scopes` | フレームごとに 2 つ：`Locals`（ローカル変数）と `Globals`（モジュール変数・ホストの変数） |
| `variables` | `scopes` の `variablesReference` に対し、`frame_variables`・`Vm::variables`（host/09-debug.md）の値を、`name`・`value`（`:vars` と同じ形。6.3.5）で返す。子の変数は持たない（`variablesReference` は 0） |
| `continue`・`next`・`stepIn`・`stepOut` | 実行を続ける。それぞれ `StepMode` の `Continue`・`Over`・`In`・`Out`。応答は先に返し、止まったとき `stopped` を送る |
| `pause` | 次の行で止める。1 行の中で続く処理（1 行に書いた繰り返し）では、行をまたぐまで効かない |
| `evaluate` | 下の「評価と停止点の答え」 |
| `disconnect`・`terminate` | 終了する（応答を返してから） |

知らないリクエストは、`success: false` で、`message` に、知らないことを書いて返す。実行中（`continue` などのあと、止まるまで）に受けられるのは `pause`・`disconnect`・`terminate` だけで、ほかは `success: false`（`message` は、実行中であること）。

### `launch` の引数

| 引数 | 内容 |
| --- | --- |
| `program` | 起動ファイルのパス。必須 |
| `root` | モジュールを探すディレクトリ（6.1） |
| `start` | 開始するラベル（6.3 と同じ） |
| `seed` | 乱数の種（6.3 と同じ） |
| `texts` | 本文の差し替え表のファイル（6.3 と同じ） |
| `stopOnEntry` | 最初の行で止まる。既定は真 |

### 止まる・終わる

- 行で止まったら、`stopped` イベント（`threadId` 1、`allThreadsStopped` 真）を送る。`reason` は、ブレークポイントなら `breakpoint`、ステップなら `step`、`pause` リクエストなら `pause`、最初の行なら `entry`。
- 台本の停止点（6.3.1）に着いたら、その表示（6.3.1 と同じ。合図の行も含む）を `output` イベント（`category` は `stdout`）で送り、`stopped`（`reason` は `step`、`description` は、答えを待っていること）を送る。停止点でも、`stackTrace`・`scopes`・`variables` は使える。
- 台本が最後まで進んだら、`output`（終わりを示す 1 行）、`terminated`、`exited`（`exitCode` 0）を送る。実行時エラーは、`output`（`category` は `stderr`。6.3 と同じ文）、`terminated`、`exited`（`exitCode` 1）。
- `terminated` のあとも、クライアントの `disconnect` を待つ。

### 評価と停止点の答え

`evaluate` の `expression` は、`context` によって、次のとおりに扱う。式は書けない。

| `context` | 動作 |
| --- | --- |
| `repl`、停止点で止まっているとき | `expression` を、停止点の答えの 1 行（6.3.2 と同じ規則）として扱う。答えとして解釈できたら、実行を再開し、応答の `result` は空の文字列。再開のあとは、直前に選んだ動かすコマンドの続きとして実行する（初めは `step`）。答えにならない入力は、`success: false`（`message` は、6.3.2 の案内の文）で、同じ停止点で待つ。`:step` のように `:` で始めると、`yomi debug` の動かすコマンド（6.18）として、続け方だけを変える |
| `repl`、一時停止のとき | `expression` を、`yomi debug` のコマンド（6.18。`step`・`next`・`finish`・`continue`・`bt`・`vars`・`print`・`list`）として扱う。出力は `result` に書く（動かすコマンドは、そのとおり動かし、応答の `result` は空） |
| `watch`・`hover`・ほか | `expression` を変数の名前として、選んだフレーム（`frameId`）のローカル変数、なければモジュール変数・ホストの変数から探し、`result` に値（`:vars` と同じ形）を返す。なければ `success: false` |

- 停止点の答えを受けられるのは、`context` が `repl` のときだけ。
- 非対応：式の評価・条件つきブレークポイント・変数の書き換え（`setVariable`）・セーブ・読み込み・ロールバック・`reload`・`--persistent`・複数スレッド・`attach`。
